# 高校教师 AI 提效技能包

## 安装

### 让 Agent 自己装

本包可以自举。把下面任一句丢给 Agent 即可：

> 从 https://github.com/EtherealMingo/university-teacher-skills 安装这个技能包

Agent 应执行：

```bash
# 方式一：一键脚本（自动探测各 agent 技能目录、建依赖、自检）
curl -fsSL https://raw.githubusercontent.com/EtherealMingo/university-teacher-skills/main/install.sh | bash

# 方式二：克隆后安装
git clone --depth 1 https://github.com/EtherealMingo/university-teacher-skills.git
cd university-teacher-skills && bash install.sh
```

安装脚本做的事：

| 步骤 | 动作 |
|---|---|
| 1 | 取源：本地仓库直接用；否则 `git clone`，失败回退 tarball |
| 2 | 落到 `~/.local/share/university-teacher-skills`（可用 `--prefix` 改） |
| 3 | 建 `vendor/office-layer/.venv` 并装文档依赖 |
| 4 | **软链**到各 agent 技能目录（软链指向同一份，venv 不重复占空间） |
| 5 | 跑 `verify.py` 完整性自检 |

自动探测的技能目录：`~/.claude/skills`、`~/.codex/skills`、`~/.agents/skills`、
`~/.cc-switch/skills`、`~/.cursor/skills`、`~/.trae-cn/skills`、`~/.kimi-code/skills`、
`~/.junie/skills`、`~/.lingma/skills`、`~/.lmstudio/skills`、`~/Doubao/skills`、`~/skills`

脚本是**幂等**的：重复运行只同步代码、保留已装依赖，不会重新下载 105 MB。

```bash
bash install.sh --prefix ~/opt/ut-skills   # 自定义安装位置
bash install.sh --target ~/.claude/skills  # 只装到指定目录
bash install.sh --no-deps                  # 不装依赖（稍后手动 bootstrap）
bash install.sh --force                    # 全量重装（含依赖）
bash install.sh --uninstall                # 卸载（只删软链与安装目录）
```

### 手动安装

```bash
git clone --depth 1 https://github.com/EtherealMingo/university-teacher-skills.git
cd university-teacher-skills
bash vendor/office-layer/bootstrap.sh   # 建 venv、装依赖
python3 verify.py                       # 自检，应 24 项全过
```

在支持 Agent Skills 的客户端里，把本目录加入技能搜索路径即可。入口是根目录的 `SKILL.md`。

### 关于体积

仓库本身约 **3.7 MB**（不含 `vendor/office-layer/.venv/`，已在 `.gitignore` 排除）。
装完依赖后本地约 **111 MB**，其中 venv 占 105 MB。

依赖里 `matplotlib` + `numpy` 占约 39 MB，确有用途（`paper-to-slides` 重绘论文图表、
`research-assistant` 出统计图），故保留。

## 场景全景

### 一条学期时间轴

真实的使用不是「逐个功能试用」，而是跟着校历走。下面是一条完整的学年动线，
括号里是对应的子技能。

**开学前**

- 接了一门新课，要从零写整学期教学大纲、排章节学时、定考核方式（`lesson-plan`）
- 手上有往届课件，但内容要更新，想批量翻新（`lecture-slides`）
- 要建本学期题库，按知识点覆盖铺开（`quiz-generator`）

**开学后每周**

- 备下一次课：教案 + 课件 + 演讲者备注（`lesson-plan` → `lecture-slides`）
- 课前想要 3–5 个随堂投票题和一条递进式提问链（`classroom-live`）
- 课后把考勤与互动记录录进去，攒到期末算平时分（`classroom-live`）
- 研究生组会：排轮值、派文献、记纪要、跟进度（`lab-meeting` → `paper-to-slides`）

**期中**

- 出一套期中卷，要 A/B 卷、要双向细目表（`quiz-generator`）
- 卷子出完先自审一遍：A/B 等价性、知识点覆盖、表述歧义（`exam-pipeline`）
- 指导学生开题：审研究问题是否成立、方法与问题是否匹配（`thesis-supervisor`）

**期末（最忙的两周）**

- 补全参考答案与评分细则（`exam-pipeline`）
- 考完读成绩表，算得分率与区分度，写试卷分析报告（`exam-pipeline`）
- 归档：试卷审批表、分析报告、平时分依据表（`exam-pipeline` + `classroom-live`）
- 留学生论文初稿，逐章批注（`thesis-supervisor`）
- 学生答辩，要预判 10–15 个会被问的问题（`thesis-supervisor`）

**申报季**

- 判断选题有没有人做过（`grant-proposal` 查重）
- 对指南找最合适的条目，列匹配矩阵（`grant-proposal`）
- 写申报书，引文与证据逐条对应（`grant-proposal`）
- 交之前先模拟评审一遍（`grant-proposal`）

**全年零散**

- 期刊邀你审稿，要出结构化意见（`peer-review`）
- 组会或学术会议要讲别人或自己的论文（`paper-to-slides`）
- 自己的实证研究：设计、综述、数据审计（`research-assistant`）
- 科技周、开放日、给中学生或政府讲自己的研究（`science-outreach`）
- 准备教学竞赛、示范课（`teaching-contest`）

**年底**

- 把散在简历、成果登记表、系统导出里的成果归成一张表（`annual-review`）
- 写年度述职，过字数门与 AI 套话门（`annual-review`）
- 整理职称评审材料，对照检查「缺什么」（`annual-review`）

### 按角色看

| 角色 | 最常用的子技能 | 典型诉求 |
|---|---|---|
| 青年教师 | `lesson-plan`、`lecture-slides`、`teaching-contest`、`grant-proposal` | 站稳讲台、拿第一个项目、教学竞赛 |
| 骨干教师 | `quiz-generator`、`exam-pipeline`、`annual-review` | 出题审卷、应付考核、评职称 |
| 研究生导师 | `thesis-supervisor`、`lab-meeting`、`paper-to-slides` | 指导论文、管课题组、组会 |
| 科研为主 | `grant-proposal`、`research-assistant`、`peer-review` | 写本子、做实证、审稿 |
| 教学为主 | `lesson-plan`、`classroom-live`、`teaching-contest` | 备课、课堂互动、示范课 |
| 教研室主任 | `annual-review`、`exam-pipeline`、`lesson-plan` | 汇总材料、统一试卷、课程建设 |

## 14 个子技能详解

每个技能都遵循同一套纪律：**不虚构**（未知信息留 `【待补：…】`）、
**留人工确认位**（评价性内容 AI 只出草稿）、**文件产出走 office-layer**。

### 教学

#### `lesson-plan` — 教案与教学设计

**什么时候用**：接新课要写大纲；每周要写教案；学生基础参差要分层设计；想试翻转课堂不知从何下手。

**典型场景**

- 新学期接一门 48 学时专业课，要从零搭教学大纲：章节学时分配、考核方式占比、目标覆盖矩阵
- 每周备课时写教案：三维目标（知识/能力/素养，且必须可观测）、重难点破解策略、环节时间分配、板书设计
- 班上学生基础两极分化，要设计拓展/达标/基础三档任务（引 `differentiated-instruction`）
- 想用项目式学习但不确定课时够不够（引 `project-based-learning` 的时程档位）

**输入**：学科、课程名、学生层次、学时、教材、是否有课程思政要求、班级规模

**产出**：教案 `docx`、教学大纲 `docx`、配套课件 `pptx`

**特色**：内置「不可测动词」扫描门（如「理解」「掌握」会被拦下，要求改为可观测表述）；
底座是繁體中文 108 课纲口径，文档里附了**强制转译表**，映射到内地三维目标与 45 分钟学时，避免直接照抄课纲术语。

---

#### `lecture-slides` — 日常课件

**什么时候用**：教案有了要做成 PPT；课件太满字太小；要补演讲者备注；明天上课今晚赶工。

**典型场景**

- 把教案知识点直接转成 16:9 课件，自动配好中文字体与配色
- 一页塞了 250 字，学生根本看不清 —— 用信息密度自检揪出过密页并拆页
- 给每页写演讲者备注：不是把正文念一遍，而是过渡语、举例、时间提示、易错点提醒
- 五类课型各有页面骨架：新授课 / 复习课 / 习题课 / 实验课 / 导论课

**输入**：教案或知识点清单、课时、课型、配色偏好

**产出**：课件 `pptx`（含备注）

**特色**：遵循 assertion-evidence 原则（标题写结论，正文给证据）；
自带 `overdense` 告警（单页正文 >220 字符触发）；产出物命名与 `lesson-plan` 对齐，两技能可直接衔接。

---

#### `quiz-generator` — 出题与测评

**什么时候用**：要出一套题；编练习题；随堂小测；要 A/B 卷。

**典型场景**

- 按大纲知识点规划题量与双向细目表，而不是拍脑袋凑题
- 八种题型分别命制，每种都有「好题标准」与「常见命题缺陷」清单
- 干扰项必须来自学生**真实常见错误概念**，不能拿「以上都不对」凑数
- 生成等价 A/B 卷（同知识点、同难度、同分值、不同题面）并校验等价性
- 把题目转成 FSRS 间隔重复闪卡，供学生复习

**输入**：知识点范围、题量、题型、难度要求、学生层次、是否要 A/B 卷

**产出**：试卷 `docx`、双向细目表/覆盖矩阵 `xlsx`

**特色**：内置 `quiz_audit.py` 质检（能抓出正确项长度泄露、「以上都不对」凑数项、题干雷同、
认知层次偏差、知识点覆盖缺口）；产出按冻结字段契约交接给 `exam-pipeline`。

---

#### `exam-pipeline` — 期末试卷后半程

**什么时候用**：审核这套试卷；出评分细则；考后成绩分析；整理试卷归档。

**典型场景**

- 卷子出完先自审：A/B 卷等价性、知识点覆盖面、难度与分值匹配、题目表述歧义、
  答案唯一性、以及「一道题的答案泄露了另一道题的线索」
- 按得分点拆评分细则（客观题/主观题/计算题/论述题细则写法不同）
- 考完读成绩表，自动算**得分率、区分度、分数段分布、偏度峰度**
- 把统计结果翻译成改进建议：哪道题该淘汰、哪道该改编
- 归档：试卷审批表、试卷分析报告、平时分依据表

**输入**：试卷或成绩表、课程名、各题满分、学生名单（或已脱敏的）

**产出**：审核意见、评分细则 `docx`、试卷分析报告 `docx`、分析表 `xlsx`（含原生图表）

**特色**：区分度按教育测量学通行口径（高低分组各取 27%），
D≥0.4 优良 / 0.3–0.39 良好 / 0.2–0.29 尚可需修改 / <0.2 应淘汰；
**全程本机脱敏处理**，产物必标「含学生个人信息」。

#### `classroom-live` — 课堂互动与平时分

**什么时候用**：生成随堂投票题；这节课的提问链；把互动记录算平时分。

**典型场景**

- 课前生成 3–5 个可投屏的投票题，选项设计成能暴露常见误解（答案只放在备注页）
- 设计一条布鲁姆六层递进式提问链（识记→理解→应用→分析→评价→创造），配追问技巧
- 课中记录五类互动：点名回答、小组讨论、投票结果、随堂小测、课堂提问
- 期末算平时分：权重可配置、封顶与扣分可追溯，**每一分都能对应到原始记录行**
- 从互动记录看参与度分布，识别沉默学生与进步学生，给干预建议

**输入**：课程名、班级人数、本次课知识点、平时分权重规则、考勤方式

**产出**：投票题 `pptx`、提问链 `docx`、平时分依据表 `xlsx`

**特色**：核心是**可举证** —— 学生质疑平时分时，能逐行指出扣分依据；
权重和 ≠ 100% 时脚本拒绝计算并报错，不闷头算出一个错数。

#### `teaching-contest` — 教学竞赛与示范课

**什么时候用**：准备教学竞赛；设计示范课；教学创新大赛；说课稿；模拟评委提问。

**典型场景**

- 判断参赛类型（教学创新大赛 / 青教赛 / 课程思政 / 教学能力比赛 / 校内示范课）与材料要求差异
- 设计 20 分钟节段：严格 2/14/4 时间骨架，并安排一个「让评委记住」的高潮点
- 把日常做法提炼成可命名的教学创新点（问题→做法→理论依据→成效证据）
- 写说课脚本（说教材/学情/目标/教法学法/过程/反思）——说课与讲课是两回事
- 评委视角自评：按评分维度打分、列常见失分点、给 A/B/C 档判断与追问预案

**输入**：参赛类型、学科、课程名、节段范围、时长、评分标准文件

**产出**：竞赛教案 `docx`、节段设计、说课稿 `docx`、课件 `pptx`、自评报告

**特色**：明确是 `lesson-plan` 的**竞赛增强版**，并强制「先补底盘再做节段」；
创新点必须有证据支撑，无证据一律标 `【待补：成效证据】`，不替你编数据。

### 科研

#### `research-assistant` — 实证研究辅助

**什么时候用**：帮我设计研究方案；实证研究怎么做；数据分析；文献综述怎么写；稳健性检验。

**典型场景**

- 从研究问题出发选设计类型（实验/准实验/相关/质性/混合），并列出四类效度威胁
- 组织文献综述（按时间/主题/方法/争论），识别研究缺口
- 建数据字典（变量名/含义/类型/取值/缺失编码/来源）
- 实证审计清单：样本筛选可复现性、变量构造文档、回归设定与稳健性、标准误聚类、
  多重检验校正、p-hacking 风险点
- 描述统计与交叉表，规范结果表（系数、标准误、显著性标记、样本量、R²）
- 因果推断警示：遗漏变量、反向因果、选择偏误、辛普森悖论

**输入**：研究问题、数据类型、变量清单、已有的文献材料

**产出**：研究设计 `docx`、数据字典 `xlsx`、描述统计报告 `md` + `xlsx`、审计清单

**特色**：**绝不生成文献引用、绝不编造数据、绝不替用户填统计结果** —— 这条是最高红线，
单独成节；所有数字必须来自用户数据。另注明 `xlsx_kit` 的难度/区分度是教育测量口径，**不得当作干预效应量**。

#### `grant-proposal` — 项目申报全流程

**什么时候用**：写本子；申报书；选题查重；模拟评审；课题论证活页；国自然/社科基金/教改项目。

**典型场景**

- **选题查重**：把你手上的已立项/已发表清单丢进去，算「用词重叠 / 方法重叠 / 场景重叠」三维度，
  给出撞车风险分级
- **指南匹配**：把指南条目与你的前期基础逐条对照，输出匹配矩阵，标出缺口
- **撰写**：走底座 `awesome-benzi` 的七阶段工作流，正文只在 Markdown 生成，引用必须用 `[n]` 标识并与证据卡对应
- **模拟评审**：以评委视角出预审意见，给 A/B/C 档判断 + 3 条最可能被追问的问题
- 出匿名版论证活页（去单位/姓名/成果署名）

**输入**：申报项目族、指南、模板、前期成果、团队构成、字数与限项要求

**产出**：申报书初稿 `docx`、匿名版 `docx`、查重报告 `md`、匹配矩阵 `xlsx`、模拟评审意见 `docx`

**特色**：查重脚本实测——近乎同题 0.668 判「疑似撞车」，同领域异方法 0.42 判「需切割」，
无关题目归零。**查重结论不构成查新报告**，这句会写进交付说明。

#### `paper-to-slides` — 论文转汇报

**什么时候用**：把这篇论文做成汇报 PPT；组会要讲这篇；论文转 PPT；学术汇报怎么讲。

**典型场景**

- 拿到一篇 PDF 论文，要拆出元信息、章节结构、图表
- 先判论文类型（综述/方法创新/实证/理论/案例），不同类型的「该讲什么、可略过什么」不同
- 按学术汇报六段结构出稿：背景与问题 → 相关工作与缺口 → 方法 → 实验 → 讨论与局限 → 结论
- 处理图表：论文原图不能直接贴（版权/清晰度/配色），需重绘或裁切，图注写结论而非「如图所示」
- 批量写演讲者备注：时间分配、过渡语、可能被追问的点
- **反剽窃**：汇报他人论文必须标注出处，不得表述为自己的成果

**输入**：论文 PDF、汇报场合（组会/会议/答辩）、时长、听众背景

**产出**：汇报 `pptx`（含备注）

**特色**：明说能力边界 —— 扫描版无文字层需 OCR，无 OCR 时**停止拆解而非猜测补全**；
双栏 PDF 文本乱序会复现并提示；`extract_pdf_figures.py` 缺 pymupdf 时给已验证的替代链路。

#### `peer-review` — 期刊审稿意见

**什么时候用**：帮我写这篇论文的审稿意见；这篇论文评审一下；审稿意见怎么写；这稿子能不能收。

**典型场景**

- 读稿拆解，重点区分**作者声称的贡献**与**实际实现的贡献**（这是审稿的核心判断）
- 按六维评审：创新性、方法严谨性、数据可靠性、论证充分性、写作规范、文献覆盖，每维给出具体检查问题
- 写结构化意见：总体评价（复述证明你读懂了）+ 编号的主要问题（问题+为什么是问题+建议如何改）+
  编号的次要问题 + **给编辑的保密意见**
- 意见分级 must-fix / should-fix / nice-to-have，附「可接受的措辞」与「应避免的措辞」对照
- 学术不端疑点筛查：图像复用（条带重复、拼接缝）、数据异常（Benford 定律、SD 异常、样本量骤增）、文本重复

**输入**：稿件 PDF 或 docx、目标期刊、审稿表模板、截稿时间

**产出**：审稿意见 `docx`；可直接在稿件上留原生批注

**特色**：**学术不端疑点只上报编辑，不写入给作者的意见**（连暗示都不许）；
明确「我不同意」与「论证不充分」的区别；利益冲突须回避并声明。

### 指导

#### `thesis-supervisor` — 毕业论文全流程

**什么时候用**：看开题报告；写论文评语；预判答辩问题；批改论文；整理批改意见。

**典型场景**

- **开题审查**：10 个维度逐项查（选题依据、文献综述、研究问题、技术路线、创新点、可行性、进度、参考文献质量等），
  意见分三级：必须修改 / 建议修改 / 通过
- **过程稿批改**：把批注**直接写进学生的 Word 文档**（Word 原生批注，学生打开就是批注气球），
  不是另出一份意见表
- **评语生成**：按五栏模板出草稿，分数与是否通过留人工确认位
- **答辩预案**：按六类生成 10–15 个大概率被问的问题（概念澄清/方法质疑/创新性质疑/数据可靠性/边界条件/应用价值），
  每条给「提问角度 + 应答要点 + 需准备的材料」

**输入**：论文或开题报告（docx）、学生层次（本科/硕士）、学校评语模板、字数要求

**产出**：审查意见表 `docx`、**带批注的论文 docx**、评语草稿 `docx`、答辩问题清单 `docx`

**特色**：批注锚点支持表格单元格（审查意见表本身也是表格）；
批注分级策略（必须改/建议改/提问式）；常见问题库涵盖综述只罗列不评述、
方法缺参数设置、图表无编号、结论与摘要重复等。

> ⚠️ 红线：评语与分数必须留人工确认位；不代写论文正文；学生论文属未公开材料需保密。

#### `lab-meeting` — 研究生组会管理

**什么时候用**：安排组会轮值；这篇文献让学生讲；生成组会纪要；实验进度跟踪。

**典型场景**

- **排轮值表**：考虑人数、组会频率、学期周次、节假日、导师时间冲突，
  汇报类型轮换（文献/进展/预答辩），保证公平（禁止连续两次同一人、点评人不自评）
- **文献派工**：指定文献后走 `paper-to-slides` 出学生汇报稿骨架，并给出派工单
  （为什么选这篇、重点看什么、汇报时长、需回答的问题）
- **组会纪要**：七栏模板，含「上次遗留 / 本次进展 / 下次计划」三栏进度跟踪
- **进度跟踪表**：状态色标（正常/滞后/阻塞），一眼看出谁需要关注
- **追问问题生成**：按苏格拉底提问法生成五类追问，训练学生批判性思维

**输入**：课题组人数与学生名单、组会频率与时长、学期周次、汇报类型

**产出**：轮值表 `xlsx`（含公平性统计）、派工单 `docx`、纪要 `docx`、进度表 `xlsx`、追问清单

**特色**：轮值算法实测有效 —— 18 周含节假日跳过、汇报次数极差 1、无人连续两场；
约束无法满足时**打印告警说明放宽原因**，绝不静默糊过去。

### 考核与对外

#### `annual-review` — 年度考核与职称材料

**什么时候用**：写年度述职；整理职称评审材料；教学成果奖申报；把成果整理成表；年度考核材料。

**典型场景**

- **成果归表**：散在简历、成果登记表、系统导出、证书里的成果，按评审栏目自动归类
  （论文→科研成果栏、教改项目→教学研究栏、指导学生获奖→人才培养栏、社会服务→社会服务栏）
- **去重**：同一条成果在不同材料里写法不同（一条带收录号一条没带、一条写「期刊论文」一条写「论文」）
  也能识别为同一条，并提示字段冲突（如「第一作者」vs「1/3」）
- **待核实标记**：缺收录号、缺获奖等级的一律标出而非猜测
- **述职报告**：按考核栏目成文，过字数门与 AI 套话门，自我评价留教师本人定稿位
- **职称材料清单**：对照评审要求双向检查，明确列出「缺什么」
- **倒排时间表**：基于真实通知日期排期

**输入**：考核年度、学校考核表模板、职称层级、成果材料清单与位置

**产出**：成果归表 `xlsx`、述职报告 `docx`、职称材料清单 `docx`、倒排时间表

**特色**：单独一节红线强调**绝不虚构成果** —— 禁补条目、禁编收录号/项目编号/专利号、
禁抬高等级排名、禁把「在投/申请中」写成已取得、禁凭记忆写课时与评教分、禁搬用往年数据。

#### `science-outreach` — 科普与对外讲座

**什么时候用**：做个科普 PPT；给中学生讲我的研究；科普讲座怎么准备；把研究讲给外行听。

**典型场景**

- **受众分层**：六类受众（中小学生/高中生/非本专业大学生/社会公众/企业人士/政府人员）
  各自的知识起点、关注点、注意力时长、语言习惯、禁忌话题 —— 同一个课题讲法完全不同
- **公众版叙事重构**：术语替换表（「多模态融合」→「同时看多种信息」）、
  类比五原则 + **类比边界表**（说明类比在哪里会失效，否则传递错误认知）、
  叙事弧（钩子→冲突→探索→揭示→回响）、大数字可视化类比
- **科普 PPT 风格**：与学术汇报严格区分 —— 大字、少字、多图，单页 ≤30 字
- **讲稿与互动**：每 5–8 分钟一个互动点，避免「大家都听懂了吗」这类无效提问

**输入**：受众类型与年龄、讲座时长、场地设备、研究主题、保密限制

**产出**：科普 `pptx`（含分段讲稿备注）

**特色**：红线是**科学准确性不能让位于趣味性** —— 简化可以，产生错误认知不行；
不夸大应用前景（避免「有望治疗癌症」式表述）；面向未成年人需适龄。

## 文件产出层

所有 docx / pptx / xlsx 产出走 `vendor/office-layer/`，针对中文场景做了处理：

```bash
PY="vendor/office-layer/.venv/bin/python"

# Markdown → Word（中文字体、页码、首行缩进两字）
$PY vendor/office-layer/scripts/docx_kit.py md --in draft.md --out 交付.docx

# 在学生的 Word 文档上写「真批注」（Word 原生，学生看得见批注气球）
$PY vendor/office-layer/scripts/docx_kit.py comment \
    --in 学生论文.docx --out 学生论文_批注.docx --comments 批注.json --author "指导教师"

# 成绩分析（得分率 / 区分度 / 分数段分布）
$PY vendor/office-layer/scripts/xlsx_kit.py analyze \
    --in 成绩.xlsx --out 试卷分析.xlsx --first-q-col 3

# 课件（16:9，可写演讲者备注，自带信息密度检查）
$PY vendor/office-layer/scripts/pptx_kit.py build --spec 课件.json --out 课件.pptx
```

`docx_kit.py comment` 的批注是**真正的 Word 原生批注** —— 写入 `word/comments.xml`
与 `commentRangeStart/End`，Word 打开显示批注气球，学生能逐条回复。
这是论文批改、开题意见、试卷审核的基础能力。

受限环境需要可写的 matplotlib 缓存目录（不影响 docx/pptx/xlsx 命令）：

```bash
export MPLCONFIGDIR=/tmp/mplcache && mkdir -p /tmp/mplcache
```

## 三条铁律

1. **不虚构**。学生数据绝不生成；文献、政策条文、个人成果一律用 `【待补：…】` 占位。
   高校材料一旦编造，后果是学术不端。
2. **产出是初稿**。涉及评价、打分、结论的内容必须留人工确认位，AI 不给终稿。
3. **文件产出走 office-layer**。不用文本框拼表格，不把 Markdown 当交付物。

## 敏感数据

成绩、学号、姓名、联系方式属个人信息：

- 只在本机处理，不上传、不外发
- 任务结束后删除中间文件
- 交付说明注明「本文件含学生个人信息，请注意保管」
