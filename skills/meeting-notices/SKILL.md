# 会议纪要与通知公文

> **Goal**：把会开成事、把通知写成能执行的动作。
> 本技能的核心纪律只有一句：**纪要记的是「决定了什么、谁去做、什么时候完成」，
> 不是「谁说了什么」**；通知记的是「谁、何时、何地、做什么、带什么、找谁」，
> 不是「请相关老师参加」。
> **AI 出的是草稿。会议决议、人事表态、成效结论一律由主持人和参会人确认后才算数。**

## 何时使用

- 「写个教研会纪要 / 系务会纪要 / 党政联席会纪要 / 课程组会纪要 / 学生座谈记录」
- 「整理一下今天的会 / 会议记录转纪要 / 把录音整理成纪要」
- 「起草个调课通知 / 写个会议通知 / 发个紧急通知 / 评审会通知」
- 「写学期工作总结 / 写年度工作总结 / 写专项工作总结」
- 「写个工作计划 / 排个教研室工作计划 / 三件事排一下谁做什么」
- 「帮我写个发言稿 / 三分钟发言 / 述职讲话 / 汇报稿（配合 PPT）」
- 「整理会议任务分工 / 做张任务清单 / 排个值班表 / 做个工作安排表」

**本技能覆盖的 6 类文书**：

| # | 文书 | 主产出格式 |
|---|---|---|
| 1 | 会议纪要（含决议与任务分工） | docx（+ xlsx 任务表） |
| 2 | 会议通知（例行 / 紧急 / 评审三类） | docx |
| 3 | 工作总结（学期 / 年度 / 专项） | docx |
| 4 | 工作计划（目标—任务—责任人—时间节点—衡量标准） | docx / xlsx |
| 5 | 发言稿 / 汇报稿（3 / 5 / 10 分钟） | docx（+ pptx） |
| 6 | 工作安排表 / 值班表 / 任务清单 | xlsx |

**不适用（走别的子技能，不要串味）**：

- **研究生组会**（文献派工、学生三栏进度、实验进度色标）→ `lab-meeting`。组会也要纪要时走它的三栏结构，本技能不重复实现。
- **年度述职、职称材料、教学成果奖** → `annual-review`。工作总结若明确是**考核用述职**，走那边；本技能只做业务口径的学期/专项总结。
- 教学竞赛说课稿、示范课 → `teaching-contest`；课程教案 → `lesson-plan`；审稿意见 → `peer-review`。

## 边界提醒：本技能最容易出事的两个地方

1. **把「讨论」写成「决议」**。会上有人说「建议下学期改培养方案」，写进纪要的「决议」栏，
   下次检查时就成了「教研室已决定改培养方案」。这是真实会发生的责任事故，
   所以阶段一把「决议 / 讨论 / 待定」分成三栏强制归位，`scripts/task_gate.py` 会对
   「决议」小节里的模糊表态词直接判 `blocked`。
2. **编造参会人和决议**。纪要是要签字归档的正式文件。
   名单、人数、缺席、议题、决议**只能来自**录音、转写、教师笔记或教师口述；
   缺什么就写 `【待补：…】`，**绝不按「一般教研会都这么开」补全**。

### 从 LANGUAGE_MODEL.md 直接引用的公文口径（照抄，不要另立一套）

| 条号 | 内容 | 在本技能的用法 |
|---|---|---|
| `WR-STYLE-010` | 无信息套话不得进入正文：值得注意的是、需要指出的是、综上所述、众所周知、不难发现、由此可见…… | 总结/通知/发言稿一律扫除 |
| `WR-STYLE-011` | 营销简报腔不得进入正文：赋能、抓手、闭环管理、底层逻辑、颗粒度、倒逼、深耕、助力、形成合力、全面提升 | 公文重灾区，必删 |
| `WR-STYLE-012` | 聊天机器人残留不得进入正文：下面我将、以下是为你、如需我继续、好的、当然 | 交付前最后一遍扫 |
| `WR-STYLE-013` | 「首次/首创/填补空白/开创性」只有能引已核实证据时才克制使用 | 工作总结的成效表述 |
| `WR-STYLE-015/016/017` | 不用感叹号、反问句、网络语、夸张副词；不用「我们觉得、说白了、搞定、很厉害」 | 纪要正文；口语只允许出现在**直接引语**里 |
| `WR-STYLE-021` | 先写判断句，再写支撑材料 | 决议与成效的写法 |
| `WR-STYLE-023` | 转承词只用于真实逻辑关系；没有关系就直接另起一句 | 删掉「首先……其次……最后……」式铺排 |
| `WR-STYLE-024` | 删除空泛判断「具有重要价值、提供有力支撑、奠定坚实基础」，改写为对象、机制、使用场景或检验标准 | 工作总结最需要的一条 |
| `QG-ISSUE-002/003` | 问题分 `blocked`/`needs-review`/`advisory`；存在 `blocked` 不得进入下一状态 | 本技能所有阶段沿用这套分级与退出条件 |

### 公文里最该删的套话清单（本技能的自用速查表）

删掉后不影响任何信息的句子，一律删；不能删的，改写成「谁做什么、什么时候、做到什么程度」。

| 该删的句子 | 为什么 | 改成 |
|---|---|---|
| 学院高度重视本次会议 | 没有动作、没有主体行为 | 删（或写「会议决定：…」） |
| 狠抓落实 / 扎实推进 / 切实把 X 抓好 | 只有态度，没有动作 | 「由 X 在 11月20日 前完成 Y，交 Z 审核」 |
| 进一步提高认识 / 统一思想 / 凝聚共识 | 无法核查 | 删；若确有学习安排，写「11月28日 组织学习《…》，全体教师参加」 |
| 在校领导关怀下 / 在学院领导的正确领导下 | 领导关怀式开头 | 「本学期课程组完成 32 学时理论课、8 次实验」 |
| 取得了显著成效 / 效果显著 / 反响热烈 | 成效无据（`WR-STYLE-013`） | 给数字或可核对事件：「学生评教 4.6 分（上学期 4.3）」「3 个班平均分提高 6 分」 |
| 具有重要价值 / 奠定坚实基础 / 提供有力支撑 | 空泛判断（`WR-STYLE-024`） | 「该方案可直接用于下学期的实验排课」 |
| 形成合力 / 赋能 / 抓手 / 全面提升 | 营销腔（`WR-STYLE-011`） | 删，或写具体协同关系 |
| 值得注意的是 / 综上所述 | 无信息转承（`WR-STYLE-010`） | 删 |

> 用法：写作时先按这张表自查一遍，再用 `task_gate.py` 机器扫一遍。
> **`task_gate.py` 只报位置，删不删、改成什么，由教师决定** —— 有些套话在学校公文格式里是固定用语，
> 例如抬头、落款、期号，那些不算套话。

## 前置信息收集（intake，一次性问完）

按 `INPUT_MODEL.md` 的 `question-batch`（`IN-QUESTION-002`），**合并成一次提问**，不要边做边问：

| # | 要问的 | 为什么必须问 |
|---|---|---|
| 1 | **会议类型**：教研会 / 系务会 / 党政联席会 / 课程组会 / 学生座谈 / 评审会 / 专项工作会 | 决定纪要栏目与通知措辞（党政联席会与教研会的记录口径不同） |
| 2 | **本次议题清单**：共几项、每项要解决什么 | 决定「议题与讨论情况」的分节，也决定哪些议题涉敏感 |
| 3 | **参会范围与名单**：姓名、单位/职务；缺席人及原因；有无列席 | **唯一不能默认的一项**。本技能绝不虚构参会人 |
| 4 | **时间、地点、主持人、记录人** | 纪要抬头与通知正文的硬要素 |
| 5 | **有没有录音 / 转写 / 手写笔记**（给文件路径）；有没有现成的纪要/通知模板 | 决定素材来源与缺口清单；有模板就照套 |
| 6 | **学校/学院的公文格式要求**：字体字号、期号、是否红头、是否要落款盖章、电子版还是纸质版 | 决定排版；没给就用通用结构并标注 |
| 7 | **这次要产出哪几件文书**（纪要 / 通知 / 总结 / 计划 / 发言稿 / 表格），各自交付格式与时间 | 一对多产出很常见（会后三件套），一次问清避免返工 |
| 8 | **是否涉及人事、处分、绩效、学生个案等敏感议题** | 决定保密级别、传阅范围、是否单独出附件 |

附加但强烈建议一次问掉：**下次会议拟时间**、**本次会议是否需上报学院**、
**发言稿的场合与时长**、**总结的统计口径**（学年还是自然年、含不含某类课程）。

### 缺信息时的安全默认值（不停下干等）

| 缺什么 | 默认值 | 交付物里怎么标 |
|---|---|---|
| 参会人名单 | **不默认，必须索要**；先给占位「应到 __ 人，实到 __ 人」 | 直接说明「不给名单无法写实到/缺席，本工具不编造姓名」 |
| 会议类型 | 按「教研会」通用纪要结构 | 「结构为通用教研会模板，请按贵院要求调整」 |
| 公文格式 | 通用公文结构（标题 + 正文 + 落款），走 office-layer 默认中文排版 | 「未提供格式要求，已用通用结构」 |
| 录音/笔记 | 只用教师提供的内容；缺项一律占位 | 「录音中未听清处已标 `【待补：请核对原话】`」 |
| 时间地点未定 | 写 `【待补：时间】`，**不写「另行通知」**（通知里出现「另行通知」等于没通知） | 提示教师定后补发第二版 |
| 敏感议题不明 | 按「内部资料」处理，正文加「内部资料，限定传阅」 | 提示教师确认传阅范围 |
| 目标值/数字 | 占位 `【待补：本学期__次数】` | 交付说明单列「所有数字占位处请补」 |

## 工作流

### 阶段零 · 文书类型判定与素材清点

**输入**：intake 全部答案；录音、转写、教师笔记、既有模板。

**动作**：

1. 判定本次要产出哪几件（常是一对多），列成「素材 → 文书 → 格式」对照表：

   | 文书 | 素材来源 | 交付格式 | 谁确认 |
   |---|---|---|---|
   | 会议纪要 | 录音 + 主持人口述 | docx | 主持人 + 参会人 |
   | 任务分工表 | 纪要「决议 + 任务」两节 | xlsx | 各责任人 |
   | 会议通知 | 下次会议安排 | docx | 分管领导 / 办公室 |
   | 工作总结 | 学期记录 + 教务数据 | docx | 教研室 / 院办 |

2. 清点素材缺口，**能一次性问掉的合并问一次**（`IN-QUESTION-004`：答不了的转 `【待补：…】`，不连环追问）。
3. 涉敏感议题的，先标出哪些内容只能进「内部版」。

**输出**：`文书清单.md`（或在对话中确认清单，不落盘也行）。

**退出条件**：产出物清单、格式、确认人三项明确；素材缺口已列清；未答项已转占位。

### 阶段一 · 决议提取（本技能的核心，必须先做这一步再动笔）

**输入**：会中记录 / 录音转写 / 教师口述。

**动作**：把每一段发言逐条归位到**三类**，一条都不许含糊：

| 类别 | 判断标志 | 归到哪一节 | 怎么写 |
|---|---|---|---|
| **决议** | 主持人归纳、明确表态、表决通过、会议明确采纳 | 「三、形成的决议」 | 陈述句：会议决定/同意/要求 + 动作 + 责任人 + 时间 |
| **讨论意见** | 某人提出、建议、认为；讨论到但没定；有不同意见 | 「二、议题与讨论情况」 | 记「谁提出什么方向」，并显式标 `（未形成决议）` |
| **待定事项** | 明确要下次再议、需上级审批、需先拿数据 | 「五、待定事项」 | 待定原因 + 推进人 + 何时再议 |

**模糊表态 → 明确任务：转写对照表**（左列是会上真实会听到的话，右列是能写进纪要的写法）：

| 会上原话 | 不能这么写进决议 | 转写成 |
|---|---|---|
| 「这个事要高度重视」 | 会议决定高度重视此事 | 由 X 于 11月20日 前提交 Y 方案，会议下次审议 |
| 「尽快落实」 | 会议要求尽快落实 | X 于 11月18日 前完成，交 Y 审核 |
| 「大家配合一下」 | 会议要求全体配合 | A 于 11/18 前提供数据；B 于 11/20 前汇总成表交 X |
| 「原则上同意」 | 会议同意该方案 | 会议同意 X 方案，但须满足 Y 条件后执行；条件未满足时按原方案执行 |
| 「再研究研究」 | 会议研究后决定 | 待定：需先取得 Z 数据，由 X 在下次会前给出结论 |
| 「下次再说」 | — | 列入下次会议议题（第 __ 项），由 X 准备材料 |
| 「经费回头解决」 | 会议同意追加经费 | 由 X 于 __ 前向学院提交经费申请，额度 __；未获批则该项目暂缓 |
| 「可以让某某试试」 | 会议决定由某某负责 | 由 X 试点，__ 周后提交效果说明交会议审议 |
| 「有老师反映……」 | 会议认为…… | 列入议题：由 X 核实情况，__ 前向会议反馈 |
| 「按学校规定办」 | 会议决定按学校规定 | 按学校/学院相关规定执行（**具体文号由 X 核对后补充**，不引条款号） |
| 「这个我同意」 | 会议同意 | 会议同意（据记录：主持人表示同意）… |
| 记录不清 / 没听清 | — | `【待补：请核对主持人原话】` |

**四条硬规则**：

1. **不得把讨论写成决议**。有人在会上提建议 ≠ 会议决定了。
2. **不得替领导表态**。只有记录里主持人/领导**原话**出现过「同意 / 批准 / 原则同意 / 不同意」，
   才能写成决议；且建议写成「（据记录：主持人表示…）」，供核对。
3. **不同意见要如实记录**。只记一致意见的纪要，在检查或争议时最站不住脚。
   写法：「X 提出不同意见：…；会议未采纳/决定按原方案执行」。
4. **每条决议必须有出处**（记录位置、时间点或发言人），方便回听核对。

**输出**：`决议提取表.md`（三栏：决议 / 讨论 / 待定 + 出处列）。

**退出条件**：三类无遗漏；每条决议有出处；所有模糊表态已转写或标 `【待补】`；
**主持人/教师已逐条确认**（这一步是判断，不是 AI 能定的 —— 留人工确认位）。

### 阶段二 · 任务可执行化

**输入**：阶段一的决议与待定事项。

**动作**：把每条决议展开成任务行，公式固定：

```
任务 = 动词 + 对象 + 责任人 + 截止时间  （+ 配合人 + 验收方式）
```

四要素缺任何一项，都要**标出来问**，不许糊过去：

| 缺什么 | 后果 | 处理 |
|---|---|---|
| 缺动词/对象 | 看不出要做什么 | 打回，写「提交修订版培养方案」而不是「培养方案问题」 |
| 缺责任人 | 没人做 | 打回，**必须填到姓名或明确岗位**；「相关老师 / 大家 / 有关部门」一律不算 |
| 缺截止时间 | 永远不做 | 打回；截止要可核对：`2025-11-20` / `11月20日` / `第12周`；「尽快 / 近期 / 学期末」不算 |
| 缺验收方式 | 做没做说不清 | 补一行：交付物名称或通过标志（`needs-review`，不阻断） |

**正反例**：

| 反例 | 问题 | 正例 |
|---|---|---|
| 落实课程思政建设 | 无动词对象、无人、无期 | 张老师于 11/20 前提交 5 个课程思政案例，课程组会审议 |
| 相关老师负责整理 | 责任人不是人 | 李老师于 11/18 前汇总上学期成绩分析表 |

### 阶段四 · 会议通知

**输入**：会议安排（时间、地点、参会范围、议程）、需准备的材料、联系人。

**动作**：先核**七要素**，缺一项就别发（通知缺要素 = 事后挨个打电话）：

| 要素 | 要求 | 反例 |
|---|---|---|
| 事由 | 一句话说清为什么开 | 「开会」 |
| 时间 | 到分钟，含星期 | 「本周内」 |
| 地点 | 具体到楼栋房间号；线上会写链接与会议号 | 「另行通知」 |
| 参会人 | **名单或明确范围**（全体 XX 教研室教师 / 各课程组组长） | 「相关老师」 |
| 议程 | 逐项列出，标每项时长 | 「研究有关工作」 |
| 需准备材料 | 交什么、什么时候交、交给谁 | 「请做好准备」 |
| 联系人 | 姓名 + 电话（办公电话优先） | 「有问题群里问」 |

**三种场景的措辞差异**（同一件事，写法完全不同）：

| 维度 | 例行会议 | 紧急会议 | 评审会 |
|---|---|---|---|
| 提前量 | 提前 3–5 个工作日 | 当天下发，明确到分钟 | 提前 5–7 个工作日（留材料阅读时间） |
| 标题 | 「关于召开 __ 会议的通知」 | 「**紧急**通知：关于 __ 的会议（时间变更/临时召开）」 | 「关于召开 __ 评审会的通知」 |
| 必须写清 | 议程与常规准备材料 | **变更原因 + 变更后安排 + 线上备用方案 + 回执时限（几小时内）** | 评审对象、材料份数、**回避要求**、评审纪律与保密、答辩时长、评分表 |
| 语气 | 「请准时参加」 | 「请务必于 __ 前回复能否参加，不能参加请指定 __ 代为参加」 | 「请于会前完成材料审阅；评审期间不得对外透露评审情况」 |
| 落款 | 单位 + 日期 | 单位 + 日期 + 时间（时分） | 单位 + 日期 + 联系人电话 |

**通知骨架**：

```markdown
# 关于召开 ____ 会议的通知

各位老师：

为 ____，经研究，决定召开 ____ 会议。现将有关事项通知如下：

一、会议时间：2025年11月20日（星期四）14:30
二、会议地点：文科楼 302（线上备用：腾讯会议 __，会议号 __）
三、参会人员：____（写明名单或范围）
四、会议议程：
  1. 14:30-14:50 __（汇报人：__）
  2. 14:50-15:30 讨论 __
五、需准备的材料：请于 11月19日 17:00 前将 __ 发至 __（联系人邮箱）
六、联系人：__，电话 __

请各位准时参加。

××学院 __ 教研室
2025年11月17日
```

**三条纪律**：

1. 通知正文里**不出现「另行通知」**。时间地点未定就先别发，或写明「定于 __ 前以 __ 方式通知」。
2. 参会范围必须明确到人/到岗。写「全体 XX 教研室教师」可以，写「相关老师」不行。
3. 涉学生姓名的材料清单不要写进群发通知（个人信息最小化，见红线 5）。

### 阶段六 · 工作计划

**输入**：上级要求 / 学院目标 / 上学期总结的问题项。

**动作**：每条任务补齐**五要件**，缺一不可检查：

| 要件 | 要求 | 反例 → 正例 |
|---|---|---|
| 目标 | 可检验（含指标与基线） | 「提高教学质量」→「课程目标达成度 ≥0.75（上一轮 0.71）」 |
| 任务 | 动词 + 对象 | 「加强课程建设」→「完成 3 门课程的教学大纲修订」 |
| 责任人 | 到人/到岗 | 「教研室」→「张老师（牵头）、李老师」 |
| 时间节点 | 可核对日期或周次 | 「本学期」→「2025-12-15 前完成初稿，2026-01-10 前定稿」 |
| 衡量标准 | 交付物或通过标志 | 「取得良好效果」→「提交 3 份大纲修订稿，课程组会审议通过」 |

**目标值必须有依据**：写清目标值来自学院要求、上一轮基数还是经验估计；

### 阶段七 · 发言稿 / 汇报稿

**输入**：场合（教研会发言 / 学期汇报 / 专项工作汇报）、时长、教师想讲的要点、可用的数据。

**动作**：先按时长定结构。中文口语语速按 **200–240 字/分钟**（正式会议念稿偏慢，取 200–220），
**含停顿与翻页，宁短勿长**：

| 时长 | 字数区间 | 结构骨架 |
|---|---|---|
| **3 分钟** | 600–720 字 | ① 一句话结论（15 秒）② 一件最关键的事 + 数据（90 秒）③ 一个请求或下一步（45 秒） |
| **5 分钟** | 1000–1200 字 | ① 结论先行（20 秒）② 三块工作，每块带数字（3 分钟）③ 一个真实问题（40 秒）④ 下一步与请求（60 秒） |
| **10 分钟** | 2000–2400 字 | ① 结论（30 秒）② 背景一句带过（30 秒）③ 三块工作 + 数据（5 分钟）④ 问题与原因（1.5 分钟）⑤ 三条举措（含责任人与时间，2 分钟）⑥ 结尾请求（30 秒） |

**口语化与书面语转换表**（发言稿是**讲出来的**，不是念公文）：

| 书面语（不能直接念） | 口语版 |
|---|---|
| 高度重视，狠抓落实 | 我们打算这么做：…… |
| 形成闭环管理机制 | 每次检查的结果都反馈到具体人，下次会议先看上次的整改 |
| 全面提升课程建设水平 | 这学期重点抓三件事：大纲、实验、考核方式 |
| 取得显著成效 | 学生评教从 4.3 升到 4.6 |
| 赋能青年教师成长 | 给每位新老师配一位带教老师，每月听一次课 |
| 由于……因此……（长复句） | 拆成两句短句 |
| 具有重要价值与深远意义 | 删 |
| 下面我将从三个方面汇报 | 直接说「先讲三件事」 |

**口语化的边界**：可以「短句、换行、停顿」，不可以「我们觉得、搞定、说白了」
（`WR-STYLE-016`）—— 正式场合的发言稿仍是书面底稿。

凡是「我承诺 / 我保证 / 我代表教研室表态」这类句子，一律标注

**退出条件**：字数落在时长区间内（超出必须删，不是念快一点）；
套话已扫除；所有表态句为占位或已确认；输出 pptx 时已 `inspect` 且 `overdense` 为空。

### 阶段八 · 工作安排表 / 值班表 / 任务清单（xlsx）

**输入**：任务表（阶段二）、排班需求（人员、时间范围、节假日）、既有表模板。

**动作**：三张表的列结构固定如下，**不要随意增删列**（增删会让筛选和统计失效）：

| 表 | 列结构 |
|---|---|
| **任务清单 / 任务分工表** | 序号 / 任务 / 责任人 / 配合人 / 截止时间 / 验收方式 / 状态 |
| **值班表** | 日期 / 星期 / 周次 / 值班人 / 值班地点 / 办公电话 / 替班人 / 备注 |
| **工作安排表** | 周次 / 日期范围 / 工作事项 / 责任人 / 截止时间 / 状态 / 备注 |

**值班表的三条规矩**：

1. **节假日与调休不删行**，标 `【节假日】`/`【调休上班】` 且不排人 —— 表要是一张完整日历。
2. **必须留「替班人」列**：值班表最常见的失效方式就是「那天我有课，没人替」。
3. 联系方式用**办公电话**；确需手机号时提醒教师这是个人信息、不要外发。

**命令**：

```bash

cat > 值班spec.json <<'EOF'
{"sheets": [
  {"name": "值班表",

   "rows": [

     ["2025-11-24", "一", "第13周", "李老师", "文科楼 302", "____", "张老师", ""],
     ["2025-12-01", "一", "第14周", "—", "—", "—", "—", "【节假日】"]
```

需要「每人值班次数」统计图时，在同一 spec 里加第二个 sheet + `chart` 字段

**退出条件**：列结构齐全；无空责任人；日期连续无断层（节假日已标注而非删除）；
xlsx 已 `inspect`；教师确认排班（**排班是人的安排，必须教师定**）。

### 阶段九 · 交付与归档（留痕与保密）

**动作**：

1. **纪要走版本管理，三版留痕**（这是「留痕」要求的具体做法）：

   | 版本 | 文件名 | 状态 | 用途 |
   |---|---|---|---|
   | v1 | `纪要_20251112_v1会中记录.md` | 草稿 | 会中记录，不外发 |
   | v2 | `纪要_20251112_v2待确认.docx` | 待确认 | 发参会人核对，文末带确认位 |
   | v3 | `纪要_20251112_v3定稿.docx` | 定稿 | 参会人/主持人确认后归档，附签字页 |

   **未确认前不得作为正式文件使用、不得外发** —— 这句话要写进交付说明。

2. **交付说明写三句**（`CONVENTIONS.md` §6、§9）：
   - 「这是初稿，请重点核对：决议是否属实、任务责任人定得对不对、时间是否可行、所有 `【待补】` 处」；
   - 「本文件含个人信息（如涉及），请注意保管」；
   - 「中间文件请及时删除」（列出清单：录音转写 `*.txt`、`任务分工spec.json`、`决议提取表.md`、`批注.json`）。

3. **敏感纪要单独归档**：涉人事、处分、绩效的，放单独目录、标注传阅范围，
   **不进大群、不发邮件列表**；必要时正文拆成「公开版 + 内部附件」。

4. **归档清单**（一份会议一个目录）：纪要 v3 定稿 / 任务分工表 / 通知 / 参会签到 / 相关附件。

**退出条件**：交付说明三句齐全；中间文件清单已列并提醒删除；
敏感内容已标注传阅范围；确认位未被 AI 填上结论。

## 红线

1. **不虚构会议内容、决议、参会人。** 纪要要签字归档，编造后果严重。
   名单、人数、缺席、议题、发言、表决结果**只能来自**录音、转写、教师笔记或教师口述。
   缺的一律 `【待补：具体说明】`，**绝不按「一般教研会通常这样」补全**。
2. **不得把「讨论过」写成「已决定」，不得替领导表态。**
   「同意 / 批准 / 原则同意」必须能在记录里找到原话依据，并写「（据记录：…）」；
   记录不清就留 `【待补：请核对主持人原话】`。讨论意见一律标 `（未形成决议）`。
3. **涉人事、处分、绩效、学生个案的议题必须提示保密与范围。**
   正文标注「内部资料，限定传阅」；单独归档、不群发、不上传外网；
   必要时拆成内部附件。**这一条不确定时按更严的一档处理，并明确提示教师复核。**
4. **纪要必须经主持人/参会人确认后才能定稿，必须留人工确认位。**
   文末保留「记录人签字 / 主持人审核 / 【待主持人确认：…】/ 【待参会人确认：…】」，
   AI 绝不自己填「确认无误」。交付说明写明「未确认前不得作为正式文件使用或外发」。
5. **学生姓名等个人信息本地处理**（`CONVENTIONS.md` §6）。学生座谈记录、
   学生个案不上传、不外发、不写进群发通知；中间转写文件任务结束提醒删除；
   交付说明写明「本文件含学生个人信息，请注意保管」。
6. **所有数字必须有来源。** 课时数、次数、人数、比例、评教分、达成度 ——
   没有依据就占位，不许用「大约」「左右」蒙过去。总结里的数字会进考核材料。
7. **不生成 Markdown 当交付物**（`CONVENTIONS.md` §2）。
   `.md` 只是中间稿，交付一律走 office-layer 出 docx / xlsx / pptx。
8. **不覆盖教师提供的原始材料**：录音、转写、笔记、模板、历史纪要一律只读；
   新文件另起文件名（带版本与日期）。
9. **不引政策条款号**。写「按学校/学院相关规定」，具体文号由教师核对后补充。
