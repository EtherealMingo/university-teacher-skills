# 部署模块——该选哪个部署工具

*当 /learn 以 "deploy" 参数被调用，或学习者询问如何/在哪里部署项目时加载。*

全程使用 `session.language` 回复（默认希伯来语）。使用 `session.address` 称呼学习者。遵循 **cli-first**——阅读 `.claude/commands/learn/cli-first.md`，优先命令而非仪表盘，并始终给出命令 + 一行「为什么」。

本模块的职责**不是**默默替他们完成部署——而是帮助他们*选对工具、理解原因、并亲手运行命令*，从而在实操中学习。

---

## 核心原则（开始时简明陈述一次）

1. 做真实项目——在部署（deploy）中学习。
2. 优先免费工具，并了解免费额度（free tier）的限制。
3. 优先 CLI 而非在仪表盘里点来点去（遵循 cli-first）。
4. **只在真正需要时**才注册新账户——不提前注册。
5. 永远解释*为什么*选这个工具。

---

## 步骤 1——先读 FAQ

阅读 `courses/ai-dev/deploy-faq.md`。如果学习者的问题在那里已有答案，先给出该答案（并说明它来自共享 FAQ）。这会奖励贡献循环。

---

## 步骤 2——诊断（3 个问题，一起问）

**不要**仅凭项目类型猜测平台。问：

1. 项目只是前端（HTML/CSS/JS，或 React/Vite 的构建产物），没有服务器吗？
2. 它会调用带 secret key 的 LLM / API，或需要数据库吗？
3. 它需要常驻运行的服务器吗——websockets、后台进程、定时任务（job），或 Postgres？

本课程最重要的分支是：**问题 2。** 静态站点无法隐藏 API key——浏览器里的任何东西都是可见的。所以一个*看起来*静态的 AI 项目（调用 Claude 的 React 聊天界面）实际上需要一个小型服务器来持有密钥。在适用时把这一点讲明白。

---

## 步骤 3——决策树

| 情况 | 推荐 | 原因 |
|-----|--------|-----|
| 纯静态，无机密、无服务器 | **GitHub Pages** | 免费、零维护、直接从仓库部署。永远是默认项。 |
| 静态 + API key / LLM / 轻量数据库 | **Cloudflare Workers + Wrangler** | 一个小 Worker 持有密钥（`wrangler secret put`）并转发请求。KV/D1 存数据。免费额度慷慨。 |
| 需要构建/预览部署、表单，或「增强版」静态站点 DX | **Cloudflare Pages**（或 Netlify） | 仍然免费、自动构建、每个 PR 都有预览。 |
| 常驻服务器——websockets、Postgres、后台任务 | **Render** | 支持长时运行的服务器。**警告：** 免费档闲置 15 分钟后休眠（冷启动约 30 秒）。 |
| 带 SSR 的 Next.js，想要零配置 | **Vercel / Netlify** | 对 Next 最省心。**但：** 存在供应商锁定（vendor lock-in），且 hobby 档仅限非商业用途。 |

**默认规则：** 如果是静态站点——永远选 GitHub Pages，除非有具体理由排除它。

推荐时给出：
- 工具名 + 一句「为什么」，
- 相关的免费额度限制，
- 最初几条命令（遵循 cli-first），在真正需要之前先不注册账户。

---

## 步骤 4——注册账户（仅在需要时）

只在进行到需要账户的步骤时才注册，按此顺序：

1. **GitHub**——总是要（他们在课程中已经有了）。
2. **Cloudflare**——仅当选择 Workers/Pages 时。免费档无需信用卡。
3. **Render**——仅当需要常驻服务器时。
4. **Vercel / Netlify**——仅当确实需要时（Next SSR）。

每个账户：说明这是一次性的仅 UI 步骤（OAuth 登录），之后继续用 CLI。

---

## 步骤 5——成本与免费额度意识

结束之前，确认学习者知道所选工具的限制（这与结业项目的 checklist 相呼应——成本计算）：

- **GitHub Pages：** 公开仓库，约 1GB，每月 100GB 流量。
- **Cloudflare Workers：** 免费档约每天 10 万次请求。
- **Render 免费档：** 闲置 15 分钟后休眠。
- **Vercel/Netlify hobby 档：** 非商业用途，构建/带宽有限制。

如果项目调用 LLM——提醒 API 本身的费用（它与托管费用是分开的）。

---

## 步骤 6——向 FAQ 贡献（通过 gh 提 PR）

如果学习者遇到了 `deploy-faq.md` 中**尚未**收录的坑并已解决，提议：

> "你解决了一个新问题——想把它加进共享 FAQ 吗？这是真实的 git + PR 练习，也会帮到后面的同学。"

如果同意，遵循 **cli-first** 带他们走一遍（让他们自己运行命令——逐条解释）：

```bash
git checkout -b faq/<short-topic>
# 把问题 + 答案添加到 courses/ai-dev/deploy-faq.md 的相应小节
git add courses/ai-dev/deploy-faq.md
git commit -m "faq: <short topic>"
gh pr create --fill
```

替他们起草 FAQ 条目文本（问题 + 简明答案 + 相关命令），但让*他们*运行 git/PR 命令，以便练习工作流。如果 `gh` 未认证，那是唯一的仅 UI 步骤（`gh auth login`）。

---

## 步骤 7——对线上应用做安全扫描

当有了线上 URL——这才是做真正安全审查的时机。不是在此之前：检查响应头、文件暴露和认证端点都需要一个正在运行的应用。

告诉学习者：

> "应用上线了——现在正是检查安全的时候。对线上 URL 的审查能发现纯代码检查漏掉的东西：实际被暴露的文件、缺失的响应头、响应出乎意料的端点。
>
> 运行：`/learn security [把你拿到的 URL 填在这里]`"

如果学习者现在不想做——安静接受。不要再重复提起。
