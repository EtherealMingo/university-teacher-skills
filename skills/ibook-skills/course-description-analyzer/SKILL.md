# 课程描述分析器

**版本：** 0.04

## 概述

本技能（Anthropic Claude Skill）是生成智能教材流程的第一步。
下一个技能是 `learning-graph-generator`。

分析或创建高质量的课程描述，使其包含生成 200+ 概念的全面学习图谱所需的全部要素。检查 `/docs/course-description.md` 文件的完备性、质量，以及与 2001 版布鲁姆分类法（Bloom's Taxonomy）学习成果的对齐情况。

## 工作流程决策树

首先检查 `/docs/course-description.md` 是否存在：

- **文件不存在** → 走**创建流程**（第 1 步）
- **文件存在** → 走**分析流程**（第 2 步）

告知用户当前运行的是课程描述分析器技能的 0.04 版本。

## 第 1 步：课程描述创建

当 `/docs/course-description.md` 不存在时使用本流程。

### 1.1 收集课程信息

按顺序向用户提问以下问题（不要一次性全部抛出）：

1. **课程的名称是什么？**

2. **课程的目标受众是谁？**
   - 选项：小学、初中、高中、大学本科、研究生、成人继续教育、职业培训，或其他

3. **这门课的先修要求是什么？**
   - 如果没有，明确写「无」

4. **这门课涵盖的主要学科/主题有哪些？**
   - 请用户提供主要主题清单

5. **按 2001 版布鲁姆分类法组织的学习成果是什么？**
   - 向用户解释：学完本课程后，学生将能够在以下各层级展现出相应能力：
     - **记忆（Remember）**：提取、识别并回忆相关知识
     - **理解（Understand）**：从教学信息中建构意义
     - **应用（Apply）**：在给定情境中执行或使用程序
     - **分析（Analyze）**：把材料分解为部分并确定其间关系
     - **评价（Evaluate）**：依据标准和准则做出判断
     - **创造（Create）**：把各要素组合成连贯的整体；包括结课项目（capstone project）

### 1.2 生成课程描述

使用 `assets/course-description-template.md` 中的模板，填入用户的回答。在 `/docs/course-description.md` 创建文件。

确保生成的文件包含：
- 清晰的课程标题
- 目标受众说明
- 先修要求（或「无」）
- 全面的主要主题清单
- 「不涵盖的主题」一节（用于划定边界）
- 按全部六个布鲁姆分类法层级组织的详细学习成果
- 解释课程重要性的描述性文字

### 1.3 创建之后

创建文件后，自动进入**第 2 步（分析流程）**，对新建的课程描述进行校验并给出质量分。

## 第 2 步：课程描述分析

当 `/docs/course-description.md` 已存在时使用本流程。

### 2.1 读取课程描述

读取 `/docs/course-description.md`，按质量标准分析其内容。

### 2.2 课程描述质量评分体系

使用以下 100 分制评分体系评估课程描述：

| 要素 | 分值 | 评分标准 |
|---------|--------|----------|
| **标题** | 5 | 有清晰、描述性的课程标题 |
| **目标受众** | 5 | 指明了具体受众（如「大学本科」） |
| **先修要求** | 5 | 列出了先修要求，或明确说明「无」 |
| **涵盖的主要主题** | 10 | 全面的主题清单（理想为 5–10 个主题） |
| **不涵盖的主题** | 5 | 为不涵盖的内容划定了清晰边界 |
| **学习成果引导语** | 5 | 有明确表述：「学完本课程后，学生将能够……」 |
| **记忆层级** | 10 | 有多条具体的记忆/回忆类成果 |
| **理解层级** | 10 | 有多条具体的理解/解释类成果 |
| **应用层级** | 10 | 有多条具体的应用/使用类成果 |
| **分析层级** | 10 | 有多条具体的分析/分解类成果 |
| **评价层级** | 10 | 有多条具体的评价/判断类成果 |
| **创造层级** | 10 | 有多条具体的创造/综合类成果；含结课项目构想 |
| **描述性背景** | 5 | 有关于课程重要性、相关性或价值的补充背景 |

**评分细则：**
- 要素完整且质量高：给满分
- 要素存在但不完整或含糊：给部分分
- 要素缺失：给 0 分
- 对布鲁姆分类法各层级：至少 3 条具体、可行动的成果才给满分

### 2.3 差距分析

识别缺失或薄弱的要素：
- 列出每个未得满分的要素
- 说明缺了什么或哪里不够
- 指出该缺失对生成学习图谱的影响

### 2.4 改进建议

提供具体、可行动的建议：
- 对缺失要素：建议应补充什么
- 对薄弱要素：举例说明如何加强
- 对布鲁姆分类法成果：推荐具体的动词和主题
- 优先排列对达成「生成 200 个概念」目标影响最大的建议

### 2.5 课程描述评估报告

用 `mkdir -p docs/learning-graph` 在 docs 目录下创建 `learning-graph` 目录。

生成一份全面的课程描述质量报告，写入 `docs/learning-graph/course-description-assessment.md`：

1. **总分**：X/100
2. **质量等级**：
   - 90–100：优秀——可以开始生成学习图谱
   - 75–89：良好——建议做小改进
   - 60–74：合格——需要若干改进
   - 40–59：一般——有明显差距要弥补
   - 0–39：较差——需要大改

3. **详细得分明细**：展示每个要素的得分
4. **差距分析**：缺失或薄弱要素清单
5. **改进建议**：按优先级排列的建议
6. **下一步**：
   - 得分 ≥ 85：可以继续生成学习图谱
   - 得分 < 85：建议在生成学习图谱前先弥补指定差距

### 2.6 更新课程描述元数据

本节中 NAME 是取自课程描述的课程名称，QUALITY_SCORE 是你为课程描述计算出的分数。

如果 `docs/course-description.md` 文件顶部还没有以下 yml 元数据，则添加：

```yml
---
title: Course Description for Course NAME
description: A detailed course description for NAME including overview, topics covered and learning objectives in the format of the 2001 Bloom Taxonomy
quality_score: QUALITY_SCORE
---
```

### 2.7 概念生成就绪度

评估课程描述是否包含足够的细节来生成 200 个概念：
- 评估主题的广度与深度
- 检查布鲁姆分类法成果是否指向多样的概念类型
- 基于当前内容估算潜在的概念数量
- 如果概念生成可能达不到数量，建议补充内容

### 把 course-description.md 和 course-description-assessment.md 加入 mkdocs.yml 导航

在 course-description.md 加入 /docs 目录之后，询问用户是否要把新文件加入 mkdocs.yml。
如果答案是肯定的，把新文件放在 about.md 之后。

```yml
nav:
   ...
   About: about.md
   Course Description: course-description.md
   ...
   Learning Graph:
      Course Description Assessment: learning-graph/course-description-assessment.md
```

## 下一步

对所有得分超过 85 的用户，询问是否接着运行 `learning-graph-generator` 技能。

## 最佳实践

使用本技能时：

1. **要完整**：不要跳过布鲁姆分类法的任何层级——六个层级对全面学习都必不可少
2. **要具体**：「理解课程内容」这类含糊的成果无法支撑高质量的学习图谱
3. **用行为动词**：每条成果都应以可测量的动词开头（列举、解释、应用、分析、评价、设计等）
4. **想着概念**：每个主题和成果都应能引出多个可学习的概念
5. **划定边界**：「不涵盖的主题」与「涵盖的主题」对范围管理同等重要
