# 定义的 ISO 11179 元数据注册标准

本参考为创建符合 ISO/IEC 11179 元数据注册标准的定义提供详细指导。

## 四项核心标准

### 1. 精确性（Precision）

当一条定义准确而具体地捕捉概念的含义、没有歧义时，它就是精确的。

**准则：**

- 说明这个概念*是什么*，而不是它*做什么*或*怎么用*
- 包含使其区别于其他概念的本质特征
- 使用适合目标受众的术语
- 避免空泛或含糊的语言

**示例：**

❌ **不精确：** 「Learning Graph——一种有用的教育工具」

✓ **精确：** 「Learning Graph——一种概念的有向图，反映为掌握新概念而应遵循的学习顺序」

❌ **不精确：** 「API——一种连接程序的方式」

✓ **精确：** 「API——一组定义软件组件应如何交互的协议与工具」

### 2. 简洁性（Conciseness）

当一条定义高效传达含义、没有冗余字词时，它就是简洁的。

**准则：**

- 多数定义以 20–50 字为目标
- 删掉填充词和冗余短语
- 尽量使用主动语态
- 快速直达核心含义
- 定义本身不要夹带例子（例子单独另加）

**示例：**

❌ **不简洁：** 「学习图谱是一种专门化的图结构，常用于教育语境和学习管理系统中，表示学生需要学习的不同概念之间存在的各种关系与依赖」

✓ **简洁：** 「一种概念的有向图，反映为掌握新概念而应遵循的学习顺序」

❌ **不简洁：** 「脚手架式教学是一种教学方法，教育者和教师在学习过程的初始阶段为学习者与学生提供支持与帮助，然后随着学习者信心的增强逐渐撤除这些支持」

✓ **简洁：** 「一种教学策略：在学习初期为学习者提供支持，并随着其信心与能力的增长逐步撤除」

### 3. 可区分性（Distinctiveness）

当一条定义独一无二、能把概念与相关概念清晰区分开时，它就是可区分的。

**准则：**

- 突出该概念与相似概念的差异
- 避免逐字照搬其他来源的定义
- 确保你的术语表中没有两条定义过于相似
- 包含区分性特征

**示例：**

两个相关但不同的概念：

✓ **Learning Graph（学习图谱）：** 「一种概念的有向图，反映为掌握新概念而应遵循的学习顺序」

✓ **Concept Dependency（概念依赖）：** 「两个概念之间的先修关系：必须先理解其中一个，才能有效学习另一个」

（注：二者是可区分的——一个是整体结构，另一个是该结构内部的一种关系）

❌ **不可区分：** 「Learning Graph」和「Knowledge Graph」两条定义几乎一模一样

### 4. 非循环性（Non-Circularity）

当一条定义不引用被定义术语本身、也不形成循环依赖链时，它就是非循环的。

**准则：**

- 定义中不要使用术语本身
- 不要引用那些反过来引用本术语的术语
- 在定义中使用更简单、更基础的术语
- 确保所有被引用的术语要么在他处有定义，要么是通行易懂的

**示例：**

❌ **循环：** 「Learning Graph——表示学习的图」

✓ **非循环：** 「Learning Graph——一种概念的有向图，反映概念应遵循的学习顺序」

❌ **循环链：**
- 「先修概念——必须先于依赖概念学习的概念」
- 「依赖概念——需要先修概念的概念」

✓ **非循环：**
- 「先修概念——必须先理解它，才能有效学习另一个概念的概念」
- 「依赖概念——需要先掌握其他概念的知识的概念」

## 另一条 ISO 11179 原则

### 5. 不夹带业务规则（Unencumbered with Business Rules）

定义应当描述某物*是什么*，而不是*应该如何使用*或*适用什么规则*。

**准则：**

- 避免规定性语言（必须、应当、要求）
- 描述概念本身，而非政策或流程
- 把定义与使用规则分开
- 聚焦概念的本质，而非其治理方式

**示例：**

❌ **夹带业务规则：** 「先修概念——学生必须先完成才能进入下一级的概念」

✓ **不夹带：** 「先修概念——必须先理解它，才能有效学习另一个概念的概念」

❌ **夹带业务规则：** 「MicroSim——必须包含用户控件和可视化反馈的交互式仿真」

✓ **不夹带：** 「MicroSim——一种小规模的嵌入式交互仿真，用于在教育内容中演示某个概念」

## 定义模板

可以以此模板作为起点：

```
一种 [基本类别/类型]，[本质特征] [区分性特征]。
```

**示例：**

- 「一种**有向图**，**反映概念的先修关系**，**用于学习**」
- 「一种**教学策略**，其中**支持随着能力增长逐步减少**」
- 「一种**小规模仿真**，**在教育内容中演示某个概念**」

## 质量检查清单

定稿一条定义前，请核对：

- [ ] **精确：** 准确捕捉了概念的特定含义？
- [ ] **简洁：** 用了 20–50 字（或合适时更短）？
- [ ] **可区分：** 与相关概念明显不同？
- [ ] **非循环：** 没有引用自身，也没有形成循环链？
- [ ] **不夹带：** 不含业务规则和规定性要求？
- [ ] **清晰：** 目标受众能看懂？
- [ ] **语法正确：** 句子结构规范？
- [ ] **术语：** 只使用他处已定义或通行易懂的术语？

## 按概念类型的常见句式

### 物体/实体

句式：「一种 [类型]，[本质特征]」

示例：「一种表示概念依赖的有向图」

### 过程/动作

句式：「为 [目的] 而 [动作] 的过程」

示例：「随着学习者能力增长而逐步减少教学支持的过程」

### 属性/特性

句式：「[实体] 在 [维度] 上的 [性质/特征]」

示例：「教学内容在多大程度上建立在已有知识之上」

### 关系

句式：「[实体 A] 与 [实体 B] 之间的一种关系，[特征]」

示例：「两个概念之间的一种关系：必须先理解其中一个，才能理解另一个」

## 字数指南

- **下限：** 10 字（多数概念至少需要这么多）
- **目标：** 20–50 字（多数定义的甜点区）
- **上限：** 75 字（超过则应考虑拆成多句，或把细节放到例子里）
- **简单概念：** 10–25 字即可
- **复杂概念：** 可能需要 30–50 字
- **非常复杂：** 50–75 字，但应考虑是否用例子表达更好

## 可读性目标

- **年级水平：** 匹配目标受众
  - 高中：9–10 年级（Flesch-Kincaid）
  - 本科：12–14 年级
  - 研究生：14–16 年级
  - 专业读者：14–18 年级
- **句子结构：** 优先简单、直接的句子
- **行话：** 仅在精确性必需、且术语在他处有定义时使用
- **主动语态：** 自然时优先使用

## 示例工作流程

1. **起草：** 先写出初始定义，暂时不管标准
2. **审查精确性：** 是否准确捕捉了含义？
3. **审查简洁性：** 还能删掉哪些字？
4. **审查可区分性：** 与相关概念有何不同？
5. **审查非循环性：** 有没有循环引用？
6. **审查业务规则：** 有没有规定性语言？
7. **修订：** 做必要的修改
8. **验证：** 对照完整检查清单核对
9. **补例子：** 如果概念抽象或举例有帮助，则补上例子

## 评分细则

每项标准 25 分：

**20–25 分：** 完全满足标准，无问题
**15–19 分：** 基本满足标准，有小问题
**10–14 分：** 部分满足标准，有明显问题
**5–9 分：** 勉强满足标准，有严重问题
**0–4 分：** 不满足标准

**总体质量分：**

- **85–100：** 优秀，可发布
- **70–84：** 良好，稍加打磨更佳
- **55–69：** 合格，需要明显改进
- **40–54：** 较差，需要大幅修订
- **40 以下：** 不合格，需要完全重写
