# 输出契约 — k12-lesson-plan-creation

由 `k12-lesson-plan-creation` 在第 5 步、写 `lesson.json` 之前加载。这里的每一条规则
都是对文档的硬性要求。

## 密度规则 — 对每份文档的硬性要求

每份文档都要清晰、简短、
易扫读。纳入教师上课需要的东西；略去仅仅用来
显得严谨的东西。标题用句首大写格式 (sentence case)。结构优于文段：

- 一个 `paragraph` 或 `labeled` 块最多 3 句。更长 → 拆开、列要点或
  做成表格。
- 像同事之间的便条一样写：平实、直接的句子，用逗号和句号构成。
- 要点是短语——每条一个意思，≤ 约 15 个词；绝不用分号串联多个分句。
- 平行变体（分组支持、分阶段的差异化、分层观察要点）放进
  同一个 `table` 块——行 = 阶段或特征，列 = 变体，每格 ≤ 约 25 个词——
  绝不写成接连多段的多句文段。
- 标注块 (callout) 用来标记教师绝不能错过的少数时刻——一个警告
  （"先不要终结这场辩论"）、一个"收齐再继续"的提示、一个阶段的
  关键成败动作。一页上全是框等于什么也没突出：一个阶段
  读起来应是平实的话术，最多一两个标注块。教师旁白
  （观察提示、个别指导话术）用 `labeled` 或 `instructions` 块。
- 每条指令只存在于一个地方。一个阶段的开场文段和它的内容块
  分工合作——文段负责铺垫，内容块承载内容；互不重复。
- 标准逐字引用恰好一次（目标标准标注块，来自 `shared`）。
  其他所有地方——预备知识锚定、后续衔接——都用代码加
  十个词以内的要点引用；绝不重新粘贴标准全文。
- 任何连续文段超过约半页的章节，必须在渲染前重构
  （表格、要点，或拆成两个章节）。

## 一切互相对得上 — 对每份文档的硬性要求

教师信任这份材料包，
是因为每一部分都与其他部分一致：

- 材料清单与各阶段完全吻合：清单中每一项都被某个具名
  阶段使用，且每个计数的集合都与其枚举相符（"图片卡，18 张"
  就列出 18 个词）。
- **拿来就能上课：** 这节课用教师手上已有的东西就能进行。材料清单中的
  每一项要么是本材料包附带的一页，要么是教室里就有的设备，
  要么是有明确获取途径的外部资源——准确的标题和来源，
  能确认时附链接。比这更难获取的东西不进这节课，
  除非教师主动要求。这节课依赖的可打印材料随材料包附带——
  当文档集能表达时作为课程页面，或以呈现效果最好的格式
  单独成文件（5e）。
- 同一任务在两处出现时（教案的"Students see（学生看到）"和学生页），
  两处措辞完全一致。
- 学生任务与标准所点名的技能在两个方向上都匹配。解码、拼写
  和写作技能在纸上进行——学生在学生页面上读写真实的词。
  听说技能以口头、指认、分类、画图或圈选的方式作答。
  课程的范围声明约束其后的每一个任务。
- 话术和例题是最终定稿的口播文本：每一步都在落到纸面
  之前定好，教师照念即可。
- 出门票的分拣桶把答案划分干净：每个示例回答恰好落入一个
  桶，且同一答案的等价形式（17 + 24 = ? 和 24 + 17 = ?）放在同一
  个桶里。
- 答题空间与要求相称：行数与所要求的数量一致，每个框都位于
  说明该填什么的题目之下。
- 句子内部的数值对用纯文本（"2 → 10，5 → 25"）；表格永远是
  独立的块。

## 阅读水平与负担

面向学生的文本按学生的阅读水平写——
教师可能会把阅读水平与年级分开说明（"我的六年级学生阅读水平
在二到四年级"意味着用二到四年级读者能读懂的句子承载
六年级的内容：短句、日常用词、一次一条指令）。把学生任务的量
按课时来定：一个典型学生能在该阶段允许的分钟数内完成练习页。
要说"家庭语言 (home language)"，不要指定某种具体语言；只有教师
点名的语言才打印译文。

**句子支架 (Sentence supports)** 是学生书写处的纯文本：一个开头的
起始句（"一个中心思想是……"）或一个按学生书写量留好空白的
填空框。支架帮助学生开始，而不是替学生回答——它绝不预填
任务所要求的内容。每个支架放在写作动作最难的那个具体
任务上——包括数学算式旁的"解释为什么"——绝不把一个支架库
复制到所有题目上。K–2 学生和多语言学习者 (multilingual learners) 在每一个
要求写完整句子的任务上都有支架。只要一个数字、一个词或
一幅图就能回答的任务不需要支架。

**在所有面向教师的文档中把框架名称写全称**——写*科学
与工程实践*，而不是光秃秃的 *SEP*——教师绝不应该需要去查
缩写。

## 文档完整性

每份文档都是教师可以直接印发或照用的成稿：

- 文档内的每个引用都指向材料包中真实存在的东西："记在
  下面的表格里"意味着那张表就在页面上；单独收取的出门票
  印成独立的一页；参考表中的数字与它支持的题目一致。
- 材料与课程在两个方向上都吻合：清单中每一项都在课程的
  某处被使用；任何章节——包括各阶段和拓展——让学生去看的
  每一项都出现在材料清单中；学生要读的任何东西要么印在
  材料包里，要么给出准确标题。对对话的提议和指引
  完全不进入文档。
- 课程在材料上保持轻量：默认配置是每个教室都有的东西（黑板、
  投影仪、纸）加上本课附带的页面。单独的可打印材料或教具
  只有在活动真正需要时才有其位置——而练习页上同样的
  思考任务通常就能胜任。当可打印材料确有必要时（卡片、
  垫子、模板），随材料包附带（5e 选择格式）；教室已有的设备
  列出即可。
- 阶段分钟数包含其引起的过渡环节（分发、重新分组、收取），
  节奏按该年级真实学生能跟上的速度，且各阶段之和恰好等于
  所述课时——过渡时间包含在各阶段之内，绝不做隐形的缓冲。
- 教师注释读起来是完整的句子。预设错误要指名一个
  真实学生会产生的具体错误答案。
- 通过实际演算验证每一处计算——答案、例题，以及课程
  依赖的任何定量链条（能量金字塔的层级、比值表的各
  项、硬币总额）都要产出材料所述的数字。

## 无障碍（含黑白打印）

意义承载在文字中，绝不只靠颜色、位置或格式：指引学生
时说"证据栏"，绝不说"右边的框"。每个填写处都标注
该填什么；任何要画而不是写的东西——比如 `number_line`——
都用文字说明其任务。章节标题是标题块（`h2`/`h3`），
不是加粗的段落。

### 5a. 编写完整的 `lesson.json`（同一轮次）

写一份 `lesson.json`，含两个顶级键：`shared` 和 `documents`。

**`shared` 是内容登记处。** 它总是承载课程标识——`grade`、
`subject`、`duration`、`standard_code`、`standard_text`（以及适用时的
`curriculum`、`prerequisite_standard`、`smps[]`）。除此之外，把任何
出现在多个页面上的内容用你自选的键登记：一道题记为 `p1`，
一份史料记为 `stamp_act_petition`，一个数据集记为 `prices_table`。
一个键的值可以是字符串、单个块、块列表，或带面向的对象
`{teacher: …, student: …, stimulus: [blocks]}`。在**学生**页面上，只有
`student` 面向（跟在 `stimulus` 块之后）会被渲染——`student` 为
`null` 意味着那里什么都不打印，口头或教师主导的任务就是这样
被挡在练习页之外的。在**教师**页面上，两个面向都渲染：
先是教师面向，作为平实话术，然后是学生面向，作为一行
"Students see（学生看到）"，让教师既读到自己的话术，又读到
学生将要看到的确切题目。写成字符串列表的教师面向
每个动作渲染一行——这是任何超过两个动作的话术都适合
的快速浏览形式——而且由于学生文本就印在旁边，话术
指向它（"朗读框中的故事"）而不是再引用一遍。除了
`standard`（它把 `standard_code` + `standard_text` 组装成目标标准
标注块）之外，键名不携带任何特殊渲染——词汇表、
迷思概念表、出门票分拣都是你自己组织的块（模式见
`references/example_lesson.json`）。

**`documents[]` 是你组织每一页的地方。** 每个条目是完整的一页：
`{id, audience: teacher|student, eyebrow, title, meta?, theme?, sections[{heading, blocks[]}]}`。
至少包含：

- `id: "lesson_plan"`（`audience: "teacher"`）——学科文件的章节结构。
- `id: "observation_template"`（`audience: "teacher"`）——使用说明、观察要点、
  迷思概念、一个供记录学生情况的 `fill_table`，以及出门票分拣。
- `id: "student_materials"`（`audience: "student"`）——**仅当学生手持打印
  页面时。** K–2 拼读课或口头课可能没有；史料量大的课可能
  既有这个又有单独的 `id: "source_packet"`。学科文件的*学生页
  布局*给出了默认骨架；按这节课的需要调整。如果教师要求
  分级/分层的学生材料，标注为 A 组 / B 组 / C 组（A = 低于、
  B = 达到、C = 超出年级水平）——分层措辞只留在面向教师的
  文档中。

在任何文档内部，用 `{"type": "from_shared", "key": "…"}` 拉取已登记的
内容——同一个键在两个页面上渲染相同的内容（按读者分面向）。
给 `from_shared` 块加 `"label": "1"` 会把拉取的文本渲染为
一行中的编号条目。在同一份文档内，每个键只拉取一次（参考表、
出门票流程、单词表只出现在一个章节中）。只出现在一个
页面上的内容可以内联撰写。

**模式 (Schema)** —— 本说明自足完备；不要为查模式去读任何其他文件：

```
shared:
  grade, subject, duration, standard_code, standard_text          (required identity)
  curriculum?, prerequisite_standard?, smps[]?
  <any key you choose>: string
                      | block | block[]
                      | {teacher: …, student: … or null, stimulus?: block[]}
  (only `standard` is special — it assembles standard_code+standard_text)
documents[]: {id, audience: teacher|student, eyebrow, title, meta?, theme?,
              sections[]: {heading, color?, blocks[]}}
block types:
  {type: from_shared, key}
  {type: paragraph, text} | {type: labeled, label, text}
  {type: callout, kind: special|student-task|teacher-note|student-note, label, text}
  {type: h2|h3, text} | {type: list, label?, ordered?, items[]}
  {type: phase_header, name, minutes} | {type: cards, items[{title, text}]}
  {type: table|data_table, headers[]?, rows[[]]}
  {type: fill_table, headers[], blank_rows: int, row_height_pt?}
  {type: number_line, min, max, ticks?, marks[]?}
  {type: source_card, title, author?, date?, origin?, excerpt}
  {type: answer_box, height_pt?, ruled?} | {type: page_break}
  {type: group, blocks[]} | {type: columns, left[], right[]}
```

`references/example_lesson.json` 是一份填写完整的示例。行文保持紧凑；
JSON 内容中不用 emoji。上述密度规则是对每个文本字段的硬性要求。
打印安全：绝不用 markdown 管道表格（用 `table`/`data_table`）；数轴用
`number_line` 块，不要用数字字符串。渲染器不能绘制图片——教师
要展示的东西（视频、照片、投影图片、图表）写进教案：在材料清单
和使用它的阶段话术中点名。学生页面只承载印在
它上面的东西。

**何时用哪个块** —— 按内容*是什么*来选，而不是按它该*长什么样*：

| 块 | 用途 |
|---|---|
| `callout` `kind: special` | 每份成品唯一的锚定性事实——目标标准。通常只用一次。 |
| `callout` `kind: student-task` | 学生做的任何任务：锚任务、出门票题目、教案中展示的一道练习题。 |
| `callout` `kind: teacher-note` | 教师读但不说出口的旁白："先不要下结论"、个别指导动作、观察提示。 |
| `list` `ordered: true` | 编号序列——题组、操作步骤。其他情况用无序。 |
| 带 `label` 的 `list` | 带标题的枚举——一个标签下的若干离散条目。 |
| `h2` | 章节内的子章节——课程流程的各阶段用 `phase_header`，它渲染为带分钟数的 h2；所有阶段标题上的 `minutes` 之和应等于 `shared.duration`。 |
| `h3` | 一个块上方的小标题（一张表、一组列表、观察要点）。 |
| `cards` | 2–4 个长度大致相当的平行条目——出门票分拣桶、层级摘要。绝不用于过长或长短悬殊的条目；那些用 `list`。 |
| `table`（无 `headers`） | 术语/定义对、标签/数值参考行。 |
| 带 `headers` 的 `table` / `data_table` | 带列标签的真实表格数据（迷思概念、支架、学生要分析的数据集）。`display: "large"` 把单元格渲染为大号居中字体——年幼学生指着读的单词网格。 |
| `fill_table` | 学生填写的组织图——观察记录表、比较表、证据收集表。`rows` 为数字时给出空白行；`rows` 为列表时可混合已填和空白——`[["cap","cape"], [], []]` 展示一行填好的示例后跟填写空间，`[["Shell", "", ""]]` 给出一行带标签、学生填空白单元格的行（在其上方的说明行里写明空白处填什么——打 ✓、是/否、一个词）。 |
| `number_line` | 绘制的数轴（`min`、`max`、`ticks`、可选 `marks`）。省略 `ticks` 默认为 10 个等分段；`ticks: 0` 画一条只有 `min`/`max` 端点标签、没有刻度的裸线，让学生自己划分。 |
| `source_card` | 学生阅读的一手或二手史料节选：标题/作者/日期 + 节选文本。 |
| `answer_box` | 任务后的书写空间。不给 `height_pt` 时按年级段自动定尺寸（K-2 约 200pt，3-5 约 150pt，6-8 约 130pt，9-12 约 115pt）。K-5 的框默认画书写横线，数学除外（数学默认留白）；`ruled: true` 在任何年级都画横线——适合写完整句子的回答——`ruled: false` 给出供画图或画模型的空白。在 `fill_table` 或 `number_line` 上作答的任务已有其作答面。 |
| `group` | 把任务的题干、素材、支架和答题框保持在一起，分页绝不会把它们拆散。 |

### 5e. 补充性成品使用其最佳格式

`lesson.json` 流水线用于课程的文档集：学生或教师阅读
或书写的页面。价值依赖于其形态的成品——卡片需要精确
尺寸以便裁剪、海报需要大字号——不属于它，应作为单独
文件以能产出最佳版本的格式生成（例如可直接打印的 PDF）。
格式由你判断；共享内容从 `shared` 取，使各页面不会漂移，
并像其他页面一样在材料清单中点名该文件。
