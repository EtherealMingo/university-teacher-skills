# 输出契约 — k12-lesson-differentiation

由 `k12-lesson-differentiation` 在第 5 步、写 `differentiation.json` 之前加载。
这里的每一条规则都是对四份文档的硬性要求。

## 密度规则 — 对每份文档的硬性要求

教师们一直在反馈成片的密集文字让人难以消化。结构优于文段：

- 一个 `paragraph` 或 `labeled` 块最多 3 句。更长 → 拆开、列要点或
  做成表格。
- 要点是短语——每条一个意思，≤ 约 15 个词；绝不用分号串联多个分句。
- 平行的层级内容（Below / At / Above 以不同方式做同一个阶段）放进
  同一个 `table` 块——行 = 阶段或特征，列 = 层级，每格 ≤ 约 25 个词——
  绝不写成接连三段的多句文段。
- 超过一句话的旁白（迷思概念观察提示、个别指导话术、使用
  建议）要独立成一个 `callout` 块，而不是埋在段落里的一句话。
- 标准逐字引用恰好一次（目标标准标注块，来自 `shared`）。
  其他所有地方——预备知识锚定、后续衔接——都用代码加
  十个词以内的要点引用；绝不重新粘贴标准全文。
- 任何连续文段超过约半页的章节，必须在渲染前重构
  （表格、要点，或拆成两个章节）。

## 写前交叉检查

在调用渲染脚本之前完成所有检查。每一项都通过之前不要渲染。

**O6 — 成品对齐（两个方向）：**
1. **教案 → 层级文档。** 列出教案中说学生要做的每一个任务——各层级的
   题目/任务、出门票、锚活动，以及任何指派给"先完成的学生"
   的内容。每一项都必须有印在至少一份层级文档上的
   面向学生的内容块（锚活动通过 `from_shared: anchor_activity`
   印在所有三份上）。只作为教案描述存在的任务不通过。
2. **层级文档 → 教案。** 对每份层级文档，列出每一个已打印的任务——每道
   题/每个任务、拓展及其每个已打印的子部分、任何只印在
   某一个层级上的内容、出门票、"先完成的话"、"反思"。每一项
   都必须出现在教案中该层级的**练习页任务 (Worksheet tasks)** 一行里，
   并点名其支架（例如"P1（带状图 + 句子支架）"，而不只是"P1"）。
   教案从未点名的已打印任务不通过——练习页没印出来的
   已点名支架不通过——教案行点名了任何层级文档都没印的
   任务或组织图同样不通过。

共享内容由 `from_shared` 块保证一致；此检查针对的是文档专属的
块和教案的文字。还要确认 `shared.standard_code` 的精确字符串
出现在三份层级文档各自的 `eyebrow`（`"[年级] [学科] · [standard_code]"`）中——
标准必须在每个层级上都被点名，而不只是出现在教师教案里。
渲染之前修正所有不一致。

## 拿来就能上课（每份文档）

各层级用教师手上已有的东西就能运行。
练习页或教案点名的每一项资源，要么是本材料包中已打印的
块，要么是教室里就有的设备，要么是有明确获取途径的
外部资源——准确的标题和来源，能确认时附链接。任务依赖的
视觉材料印在使用它的练习页上，否则就把任务改写为
基于实际印出的内容。比这更难获取的东西不进课程，
除非教师主动要求。

## P8 — 弹性分组（在教师教案 JSON 中确认）
- `Flexible Grouping`（弹性分组）一节说明了把学生分到各层级所用的
  证据或依据（例如某次具体的出门票、诊断分数，或"应用了
  默认画像——无诊断数据"）。留空或泛泛而谈不通过。
- 该节包含明确声明：层级归属可根据本课的形成性证据
  修订（不是长期不变的能力轨道）。

## O4 — 设计依据注释（在教师教案 JSON 中确认）
- `Why this works (1)` 和 `Why this works (2)`（设计依据）两节存在，且各自
  点名一个具体的层级设计选择并给出所述理由。泛泛而谈
  （"支架对学习者有帮助"）不通过。这两节是必需的，不能为了
  满足页数上限而删掉——应收紧其他内容。

### 面向学生的用语 — 所有层级文档

学生页面绝不使用教学设计术语。那是教师用语；印在
练习页上，读起来像是给学生贴的标签，而不是写给学生的。

- ❌ "CER"——把组织图标签写全：*主张 / 证据 / 推理*。
  （"写一个 CER"要写成"用证据和推理解释你的主张"。）
- ❌ "意义建构检查 (sensemaking check)"、"形成性检查"、"迷思概念"、"支架"、
  "层级"、"分层"、"锚任务"——用学生的语言：*"检查你的想法"*、
  *"一起试试这个"*、*"先完成的话"*。
- 在学生文档上，层级命名为 **A 组 (Group A)**（低于）、**B 组 (Group B)**
  （达到）或 **C 组 (Group C)**（超出）：`title` 按学科模板携带小组
  字母；`eyebrow` 保持 `"[年级] [学科] · [standard_code]"`，不含任何
  水平措辞。年级水平标签是教师用语——教师教案中的层级标签
  （"Below (Group A)"等）承载对应关系。
- 支架提示配一个简短的、学生友好的 `h3`，单独成行（例如
  *"先观察数据"*、*"检查你的想法"*），然后提示本身作为普通
  段落放在下面——绝不用很长的加粗行内标签，如
  "**任务 2 之前——意义建构检查：** 完成这个句子……"。小标题
  说的是学生要做什么，而不是背后的教学法。

### 低层级文档的措辞基调

面向学生的语言绝不能暗示期望被降低。支架要呈现为
任务设计的自然组成部分，而不是被宣布出来的支持。

- ❌ "任务 1（有支架）/ 任务 2（有引导）/ 任务 3（独立完成）"——看到
  这些标签的学生知道自己拿到的是更容易的版本。
- ❌ "需要的话再用这个" / "这是一个句子起始句"——把支持
  说成了拐杖。
- ❌ 任何把有支架任务和无支架任务区分开来的标题、标签或旁白。
- ✓ 组织图、批注框架或句子支架只是作为任务版面的一部分
  出现。
- ✓ 任务编号不带支架水平标签。
- ✓ 文档顶部的句子支架用面向所有人的说法引入："你可以使用
  这些句子支架："——而不是"卡住了再用这些"。

## 无障碍（含黑白打印）

意义承载在文字中，绝不只靠颜色、位置或格式：指引学生
时说"证据栏"，绝不说"右边的框"。每个填写处都标注
该填什么；任何要画而不是写的东西——比如 `number_line`——
都用文字说明其任务。章节标题是标题块（`h2`/`h3`），
不是加粗的段落。

### 5a. 编写完整的 `differentiation.json`（同一轮次）

1. 写 `differentiation.json`：顶级 `theme`、**`shared` 块**（最先写它——
   标识字段、逐字标准、每个层级任务各占一个键（`t1`、`t2`、…），
   出门票，以及组织好的词汇、句子支架和迷思概念块；
   还有 `anchor_activity`（面向学生第二人称的先完成任务——
   只写指令，不写理由）和 `reflect_prompt`（收尾的反思问题）），
   以及一个含 4 个条目的 `documents` 数组：
   `{"id": "teacher_plan", "audience": "teacher", …}` 和
   `{"id": "worksheet_group_a" / "worksheet_group_b" / "worksheet_group_c", "audience": "student", …}`。
   每份文档的 `sections` 遵循学科文件的文档内容模板。

   **模式 (Schema)** —— 完整的字段骨架（`blocks` 展示了每种类型
   各一个）。本说明自足完备——**不要打开、cat、head 或 grep
   渲染脚本**：

   ```
   theme: {primary: "#…"}
   shared:
     subject, grade, standard_code, standard_text        (required identity)
     duration?
     <any key you choose>: string
                         | block | block[]
                         | {teacher: …, student: … or null, stimulus?: block[]}
     (only `standard` is special — it assembles standard_code+standard_text)
   documents[]: {id: teacher_plan|worksheet_group_a|worksheet_group_b|worksheet_group_c,
                 audience: teacher|student, eyebrow, title, meta,
                 sections[]: {heading, blocks[]}}
     block types:
       {type: from_shared, key, label?}
       {type: labeled, label, text} | {type: paragraph, text}
       {type: callout, kind: special|student-task|teacher-note|student-note, label, text}
       {type: h2, text} | {type: h3, text} | {type: list, label?, ordered?, items[]}
       {type: checklist, label?, items[]} | {type: fill_in, label?, size: short|med|long}
       {type: phase_header, name, minutes}   (science teacher plan; supported by all renderers)
       {type: table, headers[]?, rows[[]], empty_row_height_pt?}
       {type: fill_table, headers[], blank_rows: int, row_height_pt?}
       {type: number_line, min, max, ticks?, marks[]?}
       {type: source_card, title, author?, date?, origin?, excerpt}
       {type: cards, items[{title, text}]} | {type: workspace, size: small|med|large, height_pt?}
       {type: group, blocks[]} | {type: columns, left[], right[]} | {type: page_break}
   ```

   **`shared` 是内容登记处。** 把每个层级任务登记在各自的键下
   （`t1`、`t2`、…），出门票登记为 `exit_ticket`，其他出现在多于一份
   文档上的内容登记在你自选的键下。一个键的值可以是字符串、
   一个组织好的块（词汇 `table`、迷思概念 `table`、带书写空间的
   句子支架文本），或带面向的对象 `{teacher: …, student: …}`——
   在**学生**页面上只有 `student` 面向渲染；在**教师**页面上
   两者都渲染（教师面向渲染为教师注释，然后学生面向渲染为
   "What students see（学生看到）"标注）。键名不携带任何特殊
   渲染——词汇、迷思概念和分拣桶都由你自己组织成块
   （各种模式见 `references/example_differentiation.json`）。

   行文保持紧凑；JSON 内容中不用 emoji。
   上述密度规则是对每个文本字段的硬性要求。
   **何时用哪个块** —— 按内容*是什么*来选，而不是按它该*长什么样*：

   | 块 | 用途 |
   |---|---|
   | `callout` `kind: special` | 每份成品唯一的锚定性事实——目标标准。通常只用一次。 |
   | `callout` `kind: student-task` | 学生做的任何任务：锚任务、出门票题目、教案中展示的一个层级任务。 |
   | `callout` `kind: teacher-note` | 教师读但不说出口的旁白：个别指导动作、观察提示。 |
   | `callout` `kind: student-note` | 学生在练习页上读到的提醒：提示卡、关键事实。（学生据此书写的句子支架是其任务旁的纯文本，不是标注块。） |
   | `list` `ordered: true` | 编号序列——题组、操作步骤。其他情况用无序。 |
   | 带 `label` 的 `list` | 带标题的枚举——一个标签下的若干离散条目。 |
   | `cards` | 2–4 个长度大致相当的平行条目——层级摘要、分拣桶。绝不用于过长或长短悬殊的条目。 |
   | `table`（无 `headers`） | 术语/定义对、标签/数值参考行。 |
   | 带 `headers` 的 `table` | 带列标签的真实表格数据（分层级的支架、迷思概念）。 |
   | `number_line` | 绘制的数轴（`min`、`max`、`ticks`、可选 `marks`）。省略 `ticks` 默认为 10 个等分段；`ticks: 0` 画一条只有 `min`/`max` 端点标签、没有刻度的裸线，让学生自己划分。 |
   | `workspace` | 学生书写空间；`size: small|med|large` 或按年级段默认。 |
   
   表格类内容——数据表、"完成表格"任务、行列组织图——必须
   是 `{"type": "table", "headers": [...], "rows": [[...]]}` 块（空字符串
   组成的行渲染为带横线的书写空间）。绝不在 `text` 字段里画
   表格：markdown 管道行、制表符方框字符、ASCII 画和符号字形
   （■、□）会原样印在页面上，无法通过打印安全检查。绝不在
   `text` 字符串里写项目符号（•、-）——用 `list` 块；段落会
   合并换行，项目符号会挤成一行。书写空间用 `workspace`
   块——它们自动按年级渲染为大小合适的留白（低年级给
   更大空间，K–5 的文段回答带书写横线；数学作答空间保持
   空白供画图）。只有当任务需要超出默认值时才设 `height_pt`：
   完整书面解释和出门票用 130–150，简短拓展问题用 90–110。
   空的表格单元格是书写空间，会自动获得按年级段定的
   最小高度——文段行不要把 `empty_row_height_pt` 设到约 70pt
   以下。以上适用于全部四份文档中的每个文段字段。
2. 三份层级文档（在同一个 `documents` 数组中）只在支架
   和拓展块上不同 (R6)。
   **每份层级文档都用 `from_shared` 块拉取任务文本——绝不重打、
   改写或把任务文本拆进文档自己的块**（这样教案和全部三个
   层级保持逐字一致——改写过的任务会在修改中漂移）。每个任务
   有自己的 `shared` 键，一次拉一个，让支架挨着各自的任务：
   `{"type": "from_shared", "key": "t1", "label": "1"}` 把任务 1 渲染为
   编号条目；每个任务——以及学生要回答的其他每一个提示
   （出门票、反思、先完成的话、某层级专属的拓展）——后面
   都跟一个 `workspace` 块。
   章节内的顺序是严格的：对每个任务 N——先放至多一个
   任务 N 的支架块（把多个支持合并为一个带标签的块；绝不放
   两个"任务 N 之前"的块），然后通过键放任务。支架绝不
   出现在其目标任务之后，支架与其任务之间也不放任何东西。
   R7 的撤除模式就是这样表达的——任务 1 有一个支架块，
   任务 2 的更轻，之后的任务没有。某层级专属的任务（Above
   拓展、Above 专属的子问题）是独立的带标题块——绝不去
   改共享任务文本。Below 层级支架遵循 R4；Above 层级拓展
   通过 R7 的质量检验。措辞基调规则（见上）适用于每个
   面向学生的块。

### 5d. 修改——一处编辑，所有成品保持同步

对 `differentiation.json` 做**有针对性的修改**，然后重新渲染全部四份
文档（瞬时）。保持各成品一致的规则：

- 如果改动涉及共享内容（情境、数字、任务、出门票、词汇、
  句子支架、迷思概念），就**在 `shared` 中**修改——它会传播到
  教师教案和每份层级文档。
- **任何情境/数字/任务变更之后做一次一致性清扫：** 编辑 `shared` 后，
  重读全部四份文档 `sections` 中的每个文段块，更新每一句
  仍提及旧情境、旧名称或旧数字的句子。任何成品都不得
  在任何地方引用被替换的内容——过时的文段是最常见的
  一致性失误。
- 只针对某一个层级的修改（例如"给低水平组更多支架"、
  "拓展再难一点"）写进该层级文档的块——绝不通过分裂共享
  内容来实现。支架修改必须遵守学科文件的 R4 规则和
  R7 撤除模式。
- 样式：顶级 `theme` 作用于全部四份文档；按文档的 `theme`
  覆盖仍然可用。

### 5e. 备用方案——定制生成代码（仅限例外路径）

仅当用户明确要求一个内置渲染器无法表达的成品或版面时
（不同的文档类型、横版海报、幻灯片等）：为该成品从零编写
生成代码。其内容从同一份 `differentiation.json`（尤其是
`shared`）中取，使其与其他成品保持一致。告诉用户这条
路径更慢。
