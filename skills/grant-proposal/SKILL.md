# 项目申报全流程

> **Goal**：把教师手上零散的前期成果与指南要求，变成一份通过质量门的申报书初稿，
> 并给出模拟评审意见。**产出是初稿，不是终稿** —— 所有个人事实由教师补全。

## 何时使用

- 「帮我写本子 / 写申报书 / 写申请书」
- 「这个选题是不是有人做过了」（查重）
- 「指南里哪一条最适合我」（匹配）
- 「帮我模拟评审一下」（预审）
- 教改项目、大创、挑战杯、创青春、国自然、社科基金

**不适用**：普通论文、课程作业、简历、市场文案。

## 前置信息收集（intake，一次性问完）

按 `INPUT_MODEL.md` 的 `question-batch` 机制，把下面这些**合并成一次提问**，不要边做边问：

**第 1 组 · 项目与两个截止时间（必需）**

1. 申报项目族与具体指南名称（社科基金 / 国自然 / 教改 / 大创 / 挑战杯…）、指南条目编号。
2. **两个截止时间**：官方截止 + **学校科研院 / 学院内部截止**（通常早 1–2 周，很多教师栽在后者）；
   提交渠道是在线系统还是纸质，在线系统是否要单位管理员审核后才能提交。

**第 2 组 · 模板与硬约束（决定能不能写）**

3. 申报书模板文件（有则给，无则按通用结构）；是否需要**匿名活页**（去掉单位/姓名/成果署名）。
4. 字数 / 页数上限（全文与各部分是否分别限）；**限项规定**：在研同类项目几项、
   主持与参与是否分开算、本次申报是否会撞限项。
5. 是否需要科技查新报告、伦理审查批件、实验安全承诺等**前置合规件**（涉及人体/动物实验、
   问卷调研、涉密数据时必须问清）。

**第 3 组 · 教师基础（决定能不能过评审）**

6. 选题方向一句话 + 前期基础清单在哪（论文 / 专利 / 预实验 / 已结题项目），**只登记真实存在的**。
7. 团队构成（职称、专业、分工）与依托单位条件（实验室、设备、数据可得性）；
   有无合作单位，合作内容是否已谈过。

**第 4 组 · 经费（写预算表前必须问）**

8. 总预算额度与科目口径（设备费上限比例、劳务费比例、是否有间接费用），以哪份经费管理办法为准。

**缺什么也不能缺模板和指南** —— 这两样没有就先用通用结构，并在交付物标注
「结构为通用模板，请对照贵校指南调整」。教师答不上来的条目按 `IN-QUESTION-004`
转成 `【待补：…】` 占位写进待核实清单，**不停下干等**；内部截止、限项、匿名要求
这三项答不上来时，默认按「存在内部截止、存在限项、活页需匿名」的最严口径写，
并在交付说明里逐条列出本次用了哪些默认值。

## 工作流

### 阶段一 · 选题查重

用自建脚本对选题做**已立项/已发表**的重叠度检查：

```bash
PY="skills/office-layer/.venv/bin/python"
$PY skills/grant-proposal/scripts/topic_overlap.py \
    --topic "基于多模态学习的城市轨道交通客流预测" \
    --corpus 已立项清单.xlsx --out 查重报告.md
```

脚本输出三维度：**用词重叠**、**方法重叠**、**应用场景重叠**，并给出「撞车风险」分级。
无语料时退化为纯文本相似度，并在报告里注明「未提供已立项语料，结论仅供参考」。

> 查重结论**不构成查新报告**。正式申报需以科技查新机构的报告为准，这一点必须写进交付说明。

- **退出条件**：报告含用词 / 方法 / 应用场景三个维度的重叠度与「撞车风险」分级；
  每条高重叠条目给出已立项 / 已发表的出处；无语料时报告首页注明
  「未提供已立项语料，结论仅供参考」；全文无「查新」字样。

### 阶段二 · 指南匹配

把指南条目与教师前期基础逐条对照，输出匹配矩阵（xlsx）：

| 指南条目 | 匹配度 | 依据（教师已有成果） | 缺口 |
|---|---|---|---|

匹配度只依据教师**实际提供**的成果，不得替教师臆造前期基础。

- **退出条件**：指南每条可申报条目都有匹配度判定与依据列；依据列只填教师材料里的成果，
  填不出的写「缺口」并汇总进待核实清单；最终推荐条目不超过 2 条，且每条推荐理由
  能指回矩阵里的具体行。

### 阶段三 · 撰写

严格走 `WORKFLOW.md` 的七阶段，正文只在 `draft.md` 中生成：

- 十模块按依赖图顺序执行（M1–M10）
- 引用必须用 `[n]` 数字标识并与证据卡对应，**没有证据卡的引用直接留空**，让教师补
- 字数门按「每个汉字 1 字、连续西文/数字串 1 字」统计，不达下限或超上限 10% 均阻断
- 生成前先读 `style_brief`，按 `LANGUAGE_MODEL.md` 压掉 AI 套话与机械转承

- **退出条件**：`QUALITY_GATES.md` 的 `blocked` 项清零（`QG-ISSUE-003`）；
  字数在门限内；正文每个 `[n]` 都能指到证据卡，指不到的引用已删或留空。

### 阶段四 · 模拟评审（MOCK_REVIEW）

以评审专家视角按 `QUALITY_GATES.md` 出一份预审意见：

- 选题依据是否充分、创新点是否可证伪
- 技术路线是否有断点、方法可行性
- 经费预算与研究内容是否匹配
- 预期成果是否与工作量相称
- 给出 **A/B/C 档建议资助判断 + 3 条最可能被评委追问的问题**

> 资助档位判断属评价性内容，AI 只出草稿意见。`模拟评审意见.docx` 中每处结论
> 必须带显式人工确认位：`【待教师确认：是否同意该资助档位判断】`，
> 追问问题清单末尾附 `【待教师确认：是否需要针对某条追问补充答辩要点】`。

- **退出条件**：意见覆盖选题依据 / 创新点 / 技术路线 / 经费匹配 / 成果相称五项；
  追问问题 ≥3 条且每条具体到本子里的某个说法（不是「创新性够吗」这种空话）；
  档位结论与每条追问均带 `【待教师确认：…】`。

### 阶段五 · 交付

内容门通过后冻结 Markdown，用 office-layer 出 DOCX：

```bash
$PY skills/office-layer/scripts/docx_kit.py md --in draft.md --out 申报书初稿.docx
$PY skills/office-layer/scripts/docx_kit.py inspect --in 申报书初稿.docx   # 自检
```

同时交付：`查重报告.md`、`指南匹配矩阵.xlsx`、`模拟评审意见.docx`。

- **退出条件**：全部 docx 由 office-layer 生成且 `inspect` 通过；匿名版（如有）逐页核对
  无单位名、姓名、成果署名残留；交付说明列出全部 `【待补】` / `【待教师确认】` 位置、
  本次用到的安全默认值、以及「查重结论非查新报告」声明。

## 占位符规范

两种占位分工明确，不许混用：

| 写法 | 用在哪 | 本 skill 的典型场景 |
|---|---|---|
| `【待补：具体事实】` | **事实缺口**：客观存在但暂时拿不到的信息 | 项目编号、论文收录号、获奖等级、经费额度、内部截止日期、限项条文 |
| `【待教师确认：判断项】` | **判断与签字**：评价、结论、是否通过 | 资助档位、是否建议申报、选题最终拍板、指导教师意见 |

细则：

1. 占位里必须写清**缺什么**（`【待补：论文收录号】` 而不是 `【待补】`），交付说明按占位全文检索列出清单。
2. **匿名活页不是占位能解决的**：单位、姓名、成果署名一律**删除**，不留 `【待补：单位】`
   这种自我暴露的占位；删完逐页核对残留（身份证号、基金号、导师姓名都是漏网高发区）。
3. 教师答不上来的限项 / 内部截止，按最严口径默认值推进，默认值本身也要标注
   （如「按存在限项处理（默认），请科研院核对」）。
4. 申报书里的事实主体是教师本人，任何「拟开展」「计划做」不得写成「已完成」（`EVIDENCE_MODEL.md`）。

## 红线

1. **不虚构**申请人事实、文献、数据、成果、合作、财务、专利、奖项。未知一律 `【待补：…】`。
2. **不替教师编造前期基础** —— 这是学术不端。
3. 引用的文献必须来自教师材料；`[n]` 标识与证据卡必须一一对应。
4. 查重结论不得表述为「查新报告」。
5. 不修改、覆盖教师提供的原始材料；过程文件放临时目录。
6. **评价性内容必须留人工确认位** —— 资助档位（A/B/C）、是否建议申报等
   判断性结论，AI 只出草稿，交付时带 `【待教师确认：…】` 标注，不给终稿口吻。
