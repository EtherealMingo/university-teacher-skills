# 学术通信与对外联络

> **Goal**：把教师一句话的意图，变成一封**简短、得体、目的明确、对方愿意回**的邮件或函件草稿。
> 这类通信量大、单封不长，但写不好要么失礼（称呼头衔错、过度客套、诉求含糊），
> 要么低效（一封问五件事、让对方自己找重点、没有截止时间）。
>
> **产出是草稿，不是终稿**。AI 不代发任何邮件，教师本人必须通读定稿。

## 何时使用

- 「期刊邀我审稿，回一封」「这稿子我不想审，怎么婉拒才不失礼」
- 「邀请 X 教授来做报告，写封邀请函」「下个月的会议要发征稿通知」
- 「想找 X 老师合作，第一封邮件怎么写」「发了没回，怎么再问一次」
- 「要一份数据/样品」「请人当答辩委员」「推荐同行评奖」「写封感谢信/贺信」
- 中英双语场景：「给国外学者写封英文邮件，别太中式」「这封中文怎么翻成英文才不像翻译」

**不适用**：

| 诉求 | 该走的技能 |
|---|---|
| 写审稿意见本身（不是回复邀约） | `peer-review` |
| 学生推荐信、留学推荐信 | `student-recommendation` |
| 教研会纪要、调课通知、工作总结 | `meeting-notices` |
| 项目申报书、选题查重 | `grant-proposal` |
| 会议要用的大会 PPT / 演讲幻灯片 | `lecture-slides`、`paper-to-slides` |

**与 `student-recommendation` 的分工**：给学生本人写的推荐信走那个技能；
本技能负责**向同行/机构发起的对外联络**（邀请、推荐他人评奖、索取材料、合作洽谈）。

## 前置信息收集（intake，一次性问完）

按 `INPUT_MODEL.md` 的 `question-batch`：**一次提问，把下面 7 项合并列成清单**，不要边写边问。

| # | 要问的 | 为什么必须要 |
|---|---|---|
| 1 | **通信对象**：姓名、职称/职务、单位全称、**与你的关系**（导师/同门/陌生资深学者/期刊编辑/行政领导/海外学者） | 关系决定称谓与客套层级；职称写错是本技能第一号事故 |
| 2 | **事由**：什么事、来龙去脉、对方之前说过什么（有原邮件就贴原文） | 避免 AI 自行推断背景 |
| 3 | **期望结果**：你希望对方做什么（答应/回复一个时间/提供材料/签协议） | 一封邮件只服务一个诉求 |
| 4 | **截止时间**：你要对方在什么时候前回复或交付 | 「尽快」等于没有截止 |
| 5 | **语言**：中文 / 英文 / 中英各一份；若英文，对方是否母语、地区（美/英/欧/日韩） | 中英不是互译，写法不同 |
| 6 | **是否需要抄送他人**、抄送谁、是否需要密送 | 抄送用于知情不用于施压；群发必须 BCC |
| 7 | **学校/机构格式要求**：是否有抬头纸、函件模板、必须盖章、必须走公文流程、报酬与报销标准出处 | 有模板时模板优先级最高（`WR-STYLE-007`） |

**缺信息时不停下干等**：用安全默认值继续，并在交付物顶部写明用了哪些默认值。
但第 1 项的**姓名/职称/单位**缺了不许猜 —— 一律留 `【待补：…】`。

**额外按场景补问**（只问相关的，别全问）：

- 审稿类：期刊名、稿件编号、邀请邮件原文、你与作者/单位有无合作关系、要求的审稿周期
- 会议类：会议中英文全称、主办承办单位、日期地点、投稿系统链接、重要日期、注册费、是否出版论文集
- 合作类：你的研究关联点（具体到对方哪篇论文/哪个方法）、你已有的真实进展、你想请对方承担什么
- 事务函件类：所需材料的精确范围（变量/批次/年份）、用途、是否需签署协议、报酬标准出处在哪

## 工作流

### 阶段〇 · 分诊（类型 + 风险级别）

- **输入**：教师的一句诉求 + intake 结果
- **动作**：
  1. 判定类型：`审稿` / `会议` / `合作` / `事务函件`
  2. 判定风险级别：

     | 级别 | 判据 | 例子 | 附加要求 |
     |---|---|---|---|
     | **R1 日常** | 不涉钱、不涉权、不涉未公开信息 | 会议通知、感谢信、贺信 | 常规产出 |
     | **R2 需核对** | 称谓/头衔/日期/事由名称写错就有代价 | 专家邀请函、婉拒审稿、推荐评奖、答辩委员邀请 | 强制走阶段一的核对门 |
     | **R3 高风险** | 涉经费、署名、知识产权、保密、利益冲突 | 合作意向书、分工署名讨论、审稿利益冲突声明 | **必须**标注「需正式协商 / 需主管部门确认」，并在交付物里单列待协商点 |

  3. 判定产出形态：只是邮件正文（Markdown 即可）/ 需盖章正式函件（DOCX）/ 需会议材料包（PPTX）
- **输出**：类型 + 风险级别 + 产出形态 + 选定的模板编号
- **退出条件**：三者在交付说明里都写明；R3 已标注须走正式协议

### 阶段一 · 称呼与头衔核对门（**不许跳过**）

**称呼与头衔写错是学术圈大忌**，一封邀请函把「副教授」写成「教授」、
把「研究员」写成「教授」、姓名同音字写错、单位写简称，对方会记很久，且无法挽回。

- **输入**：intake 里的对象信息 + 教师能提供的一切依据（对方主页、邮件签名、会议手册、论文署名页）
- **动作**：对**每一个收件人**核对三处，并写出来源：

  | 核对项 | 常见事故 | 处理 |
  |---|---|---|
  | **姓名用字** | 同音字、生僻字、英文拼写不一致（Wang/Xu/Lü） | 以对方自己署名为准；不确定留 `【待补：姓名用字】` |
  | **职称/职务** | 副教授↔教授、研究员↔教授、高工↔讲师；把「院士」降成「教授」（降级也是错） | 不同系列不可混用；无确证不猜 |
  | **单位全称** | 写简称、写错学院名、附属医院与大学混淆 | 用官方全称；对方自我介绍用过简称才可沿用 |

- **称谓安全降级原则**（这是本技能最实用的一条）：

  | 情况 | 中文写法 | 英文写法 |
  |---|---|---|
  | 已确证职称 | 「尊敬的 X 教授」「尊敬的 X 研究员」 | Dear Prof. X |
  | **未确证职称** | 「X 老师」（高校教师通用，最安全） | Dear Dr. X（已知有博士学位时安全） |
  | 只知是编辑 | 「尊敬的 X 编辑」或「《X》编辑部」 | Dear Dr. X / Dear Editor |
  | 行政职务已确证 | 「尊敬的 X 院长/处长」 | — |
  | 完全未知 | 【待补：对象信息】 | 【待补：recipient】 |

  **绝不**写「Dear Teacher Zhang」「尊敬的张教授（实际是副教授）」。
  **绝不**为了显得客气而升格对方职称 —— 升格同样失礼，还可能被认为不专业。

- **关系 → 客套层级**：

  | 关系 | 中文称谓 | 客套程度 | 英文 |
  |---|---|---|---|
  | 自己的导师/长辈 | 尊敬的 X 老师 | 高：可带一句问候 | Dear Prof. X |
  | 同门/平辈合作者 | X 老师，或按习惯称「X 兄/姐」 | 低：直接说事 | Dear X / Hi X |
  | 未谋面的资深学者 | 尊敬的 X 教授（须先核实） | 高：自我介绍要交代清楚 | Dear Prof. X |
  | 期刊编辑/编辑部 | 尊敬的 X 编辑 | 中：公事化，不寒暄 | Dear Dr. X |
  | 海外学者 | — | — | 首次一律 Prof./Dr. + 姓；**对方先用了名字才可改** |
  | 行政/职能部门 | 尊敬的 X 处长/院长 | 公文体 | — |

- **输出**：`称谓核对表.md`（每个收件人一行：姓名 / 职称 / 单位 / 采用称谓 / **依据来源** / 是否待核）+ `需补信息清单.md`
- **退出条件**：每个收件人都有完整一行；**依据列写不出来的，一律降级为 `【待补：…】`**，
  并在交付说明里把「请务必核对姓名与职称」列在第一条

### 阶段二 · 拟稿

- **输入**：称谓核对表 + 事由 + 期望结果 + 截止时间 + 语言
- **动作**：
  1. 按阶段〇选定的模板填内容（模板见下文「模板库」）
  2. **只填教师提供的事实**：对方论文题名、年份、会议名称、金额、日期 —— 未提供的留 `【待补：…】`，
     不允许模型用「合理的」内容补全
  3. 收敛诉求：把教师想说的多件事，压成**一件需要对方回复的事**，其余降为「供您知悉，无需回复」
  4. 加降低行动成本的设计：给对方 **A/B 选项**（「周三或周五哪个方便？」），
     或明确「回复一个词即可」（「回复『可』或『不可』即可」）
  5. 主题行按「邮件写作方法论」第 1 条写
- **输出**：`draft.md`（含 Subject line 与正文）
- **退出条件**：正文 ≤ 25 行（正式函件除外）；诉求唯一且带**具体日期（含星期）**；
  所有未知事实已占位；无一字自造信息

### 阶段三 · 语言治理

按 `LANGUAGE_MODEL.md` 逐条过，中英分别处理（**不是互译**）：

- **中文侧**：
  - 删无信息套话（`WR-STYLE-010`）：「值得注意的是」「综上所述」「不难发现」等一律删
  - 删营销/简报腔（`WR-STYLE-011`）：「赋能」「抓手」「闭环」「助力」「形成合力」
  - 删聊天机器人残留（`WR-STYLE-012`）：「下面我将」「希望这对你有帮助」「如需我继续」
  - 客套**只保留两处**：开头一句致谢/致意 + 结尾一句敬语。中段不再重复「非常感谢」「麻烦您了」
  - 不用感叹号、不堆形容词、不写「非常非常」「特别特别」（`WR-STYLE-015`/`WR-STYLE-017`）
- **英文侧**：
  - 第一句就说清来意，不铺垫
  - 删中式谦卑：`I am very sorry to bother you` / `I am sorry to waste your time` /
    `Please forgive my poor English` / `My English is not good` —— 全部删掉，写事即可
  - 删中式祈使句：`Please reply me as soon as possible` → `I would appreciate a reply by [date]`
  - 删自评与空祝：`My paper is very good`、`Best wishes to your work` 等
  - 结尾用 `Best regards` / `Sincerely`；不用 `Respectfully yours`（除非正式公文）
- **共同**：短句优先，一句一个意思；**读一遍，凡是删掉不损失信息的话，就删掉**

- **输出**：草稿终版 + `语言治理记录.md`（列出删掉了什么、为什么）
- **退出条件**：套话/AI 残留为零；中英各自读起来像本语言母语者写的，而不是翻译腔

### 阶段四 · 风险检查（三道，逐条写结论）

1. **保密检查（审稿类必做）**
   邮件或草稿里是否出现：稿件内容、作者姓名与单位、审稿意见、审稿人身份、稿件编号？
   - 回复编辑部时可以引用**编辑部已经告诉你的**稿件编号与题名；
   - **不得**向任何第三方（包括同事、合作者、学生、其他期刊）透露稿件的任何内容或作者信息；
   - 审稿意见**只通过期刊系统提交**，不用邮件正文发；
   - 命中即删，并在风险结论里写明删了什么。
2. **利益冲突检查**
   与作者/单位是否存在：同单位、师生关系、近期合作、竞争关系、共同经费、亲属关系？
   - 有 → 主动声明并建议回避，**把处理决定权交给编辑部**，不自行判断；
   - 接受邀请时也应主动问一句「是否需要我声明利益冲突」。
3. **承诺性条款检查（R3 必做）**
   草稿里是否出现确定表述的：报酬金额、经费分担、署名顺序、通讯作者、知识产权归属、
   检索收录（EI/CPCI/Scopus）、出版承诺？
   - **一律不代拟**，改为 `【待补：由主办方/期刊/学校确认】`，并加一句
     「以上为初步设想，最终以双方正式协商结果与正式协议为准」。

- **输出**：`风险检查结论.md`（三行：保密 / 利益冲突 / 承诺性条款，各写「通过」或「已处理：…」）
- **退出条件**：三项都有明确结论；含 R3 内容的函件已标注「需正式协议 / 需主管部门确认」

### 阶段五 · 定稿产出

- **输入**：定稿 Markdown
- **动作**：

  邮件正文**不必**转 DOCX —— 直接给 Markdown，教师复制粘贴即可。
  需要**盖章、留档、走公文流程**的正式函件才走 `office-layer`：

  ```bash
  cd /Users/mingo/Documents/kimi/Workspaces/skills   # 必须在包根执行，vendor 路径是相对包根写的
  PY="vendor/office-layer/.venv/bin/python"

  # 方式一：Markdown → DOCX（中文字体、标题层级、页码、首行缩进两字）
  $PY vendor/office-layer/scripts/docx_kit.py md \
      --in 专家邀请函.md --out 专家邀请函.docx --title "专家邀请函"

  # 方式二：JSON 规格 → DOCX（正式函件的抬头、表格回执、人工确认位）
  # spec 结构：{title, subtitle, sections:[{heading, paras, no_indent, table:{header,rows}, placeholder}]}
  $PY vendor/office-layer/scripts/docx_kit.py spec \
      --spec 邀请函_spec.json --out 专家邀请函.docx

  # 写完必须 self-check，读回段落/表格/字数
  $PY vendor/office-layer/scripts/docx_kit.py inspect --in 专家邀请函.docx
  ```

  `spec` 里留人工确认位（会在文档里以楷体斜体显式出现，提醒教师必须手改）：

  ```json
  {"title": "专家邀请函",
   "subtitle": "【待补：会议中英文全称】",
   "sections": [
     {"heading": "一、邀请事由",
      "paras": ["尊敬的【待补：专家姓名】教授：", "您好！"]},
     {"heading": "二、回执",
      "no_indent": true,
      "table": {"header": ["项目", "内容"],
                "rows": [["能否出席", "【待补】"], ["报告题目", "【待补】"]]},
      "placeholder": "【待教师确认：专家费标准依据与发放方式】"}]}
  ```

  会议议程大屏或主持人提词卡走 `pptx_kit.py`（中文字体必须经本层，不要手写 pptx）。

- **输出**：`*.docx` / `*.md`
- **退出条件**：`inspect` 通过（段落数、表格数、字数符合预期，退出码 0）；文件命名规范
  （`对象_事由_版本.docx`，如 `张伟教授_专家邀请函_v1.docx`）

### 阶段六 · 交付与归档

- **动作**：
  1. 交付说明写清四件事：**这是什么** / **哪些是 `【待补：…】`** / **哪些必须教师核对** / **是否需要盖章或走公文流程**
  2. 明确告知：**「这是草稿。AI 只出草稿，本技能不代发任何邮件，请通读定稿后自行发送。」**
  3. 提示教师把定稿模板存进自己的常用模板库，下次直接复用
- **输出**：交付说明 + 需核对清单
- **退出条件**：教师确认收到；**未发送前不得视为完成**

## 中英文学术邮件差异（重点）

### 中文的规矩

- **称谓**：尊敬 + 职称 + 姓（「尊敬的张教授」）。不确定职称用「张老师」。
  同一封信内职务前后一致，不要开头「张教授」结尾「张老师」。
- **客套层级**：一句开场致意 + 一句结尾敬语，够了。中式通信忌**过**也忌**无**：
  完全不致意显得生硬，每段都「非常感谢」显得不专业。
- **结尾敬语**：正式函件用「此致 / 敬礼」；学术邮件用「顺颂 / 时祺」「顺祝 / 研安」；
  熟悉的同门可直接「祝好」。
- **落款**：姓名 + 职称 + 单位院系 + 电话 + 邮箱（中文正式函件要留可联系信息）。
- **委婉**：请求用「不知您是否方便」「若您时间允许」；但**委婉不等于含糊** ——
  委婉之后必须跟一个具体日期。

### 英文的规矩

- **称谓**：`Dear Prof. [Last name]` / `Dear Dr. [Last name]`。
  **不要** `Dear Teacher Zhang`、`Dear Mr. Zhang`（职称优先于 Mr./Ms.）。
  首次一律用姓，对方先署名用了 first name 才可改用 first name。
- **Subject line**：短、具体、含动作与期限。占位符 `[Action] [topic] — [deadline]`。
  例：`Invitation to review — MS#12345 — reply by Jun 3`。
  **不要**写 `Hello`、`Question`、`Urgent!!!`、`Important`。
- **直接**：第一句就是 `I am writing to ...`。绕圈子在英文语境里等于不专业。
- **忌过度谦卑**：不要 `I am very sorry to bother you`、`I am sorry to waste your time`、
  `I hope you can forgive my poor English`。删除后信息量不减，反而更受尊重。
- **催稿不冒犯**：三段式 —— ① 指回原邮件与日期 ② 给一个新截止日期或新信息 ③ 给台阶
  （`If your schedule does not allow it, just let me know and I will approach someone else.`）
- **落款**：`Best regards,` 换行写姓名、职称、单位、邮箱。不用 `Respectfully yours`。

### 常见中式英文对照（写英文邮件前扫一遍）

| 中式写法 | 得体英文 |
|---|---|
| Dear Teacher Zhang | Dear Prof. Zhang |
| I am very sorry to waste your time | Thank you for your time |
| I want to consult you some questions | I would like your advice on [one specific question] |
| Please reply me as soon as possible | I would appreciate a reply by [date] |
| Could you please help me to do... | Would you be able to ...? |
| Thanks for your attention | Thank you for your consideration |
| My paper is very good / very innovative | （删除自评，交给内容说话） |
| I hope you can give me some advice | I would welcome your comments on ... |
| Please forgive my poor English | （删除） |
| Best wishes to your work | Best regards |
| Looking forward to your reply | I look forward to hearing from you |
| I am writing to you to ask... | I am writing to ask... |

**中文版**

主题：【邀请】邀请您在【待补：会议名称】做学术报告（请于【待补：日期】前回复）

尊敬的【待补：姓名】教授：

**英文版（按英文习惯重写，不是直译）**

```
Subject: Invitation to speak at [Conference Name], [Date] — reply by [Date]

Dear Prof. [Last name],

I am writing to invite you to give a [30]-minute talk at [Conference Name],
which will be held at [Venue] on [Date].

Your work on [specific topic] is closely related to this year's theme,
[theme]. We would be glad to have you speak to [audience].

We will cover [travel and accommodation] and provide an honorarium in
accordance with [institution] policy; details are in the attachment. If you
need a signed letter of invitation for your leave application, we can send
one in advance.

Would [Date] work for you? [Alternative date] is also possible — please let
me know which you prefer. At this stage a one-line reply is all we need.

[Full name], [Title]
[Department, Institution]
[email] | [phone]
```

**差异说明（为什么不是直译）**

| 维度 | 中文 | 英文 | 原因 |
|---|---|---|---|
| 主题行 | 可写全称、可较长 | `[Action] + topic + deadline`，短 | 邮箱列表只显示前几十个字符 |
| 开场 | 「冒昧来信」先致意 | 第一句直接 `I am writing to invite you` | 英文绕 = 不专业 |
| 谦辞 | 「才疏学浅」「冒昧」可保留 | `sorry to bother` 一律删 | 英文过度谦卑显得没底气 |
| 诉求 | 「不知您是否方便」（委婉） | `Would [Date] work for you?`（直问） | 都要给具体日期 + 备选 |
| 减负 | 「只需回复本邮件即可」 | `a one-line reply is all we need` | 明确降低对方行动成本 |
| 时间 | 「X月X日（星期X）」 | `[Date]` + 时区（如 `14:00 CST (UTC+8)`） | 国际通信必须写时区 |
| 落款 | 「顺颂时祺」+ 职称单位电话 | `Best regards` + 姓名职称单位邮箱 | 中文讲敬语，英文讲可联系性 |

## 邮件写作方法论

1. **主题行要写得能被回复**
   - 中文：`【动作】+ 事项关键词 + 期限`。例：`【审稿回复】同意承担 MS-12345，预计 X月X日交稿`
   - 英文：`[Action] + topic + deadline`。例：`Review invitation MS#12345 — reply by Jun 3`
   - 禁：`你好`、`请教`、`紧急`、`重要`、空白主题、`Re: Re: Re: 关于之前说的那件事`
2. **一封邮件只问一件事**。真要问多件，编号列出，并标出「只需回复第 2 项，其余供您知悉」。
   一次问五件事的邮件，通常只会得到零个回答。
3. **明确诉求 + 具体截止时间**。写日期、星期，国际通信写时区。
   并说明**为什么**是这个时间（「因为要在 X 日前提交议程」）—— 有理由的截止更容易被尊重。
4. **把对方的行动成本降到最低**。这是本技能最有效的一条：
   - 能给选项就别让对方思考：`周三 15:00 或周五 10:00，哪个方便？`
   - 能一句话答的，不要写成一段；能回一个词的，就写明「回『可』即可」
   - 需要对方做的事**不超过一件**；多做一件事，回复率就掉一截
5. **25 行原则**。正文控制在 25 行内。确实要交代细节的，放附件，
   正文里写一句「详见附件第 X 节」。
6. **三段结构**：① 我是谁 + 为什么写这封（1–2 句）② 必要事实（时间/地点/金额/依据）③ 一个明确的 action + 截止日期。
7. **抄送与保密的礼节**：
   - 抄送用于**知情**，不用于施压；不要用抄送领导来催人
   - 群发必须用**密送（BCC）**，避免把所有收件人邮箱暴露给彼此
   - 涉及他人论文、稿件、评审、学生信息的邮件，**不抄送任何无关第三方**
   - 回复时想清楚 Reply（只回发件人）还是 Reply All（回全部）
8. **发送时机**：工作日发送，周二至周四上午回复率最高；
   避开周五傍晚、长假前一天、对方所在时区的深夜。
9. **发前最后一眼**（发出前教师自己过）：收件人邮箱拼写、称谓与职称、日期与星期是否对得上、
   附件是否真的附上了、附件命名是否清楚、有没有把 A 的邮件发给 B。

## 模板库

### A · 审稿邀约的回复

**A1 接受（确认交稿时间 + 说明专业匹配）**

匹配点必须说清一句，别只说「我愿意审」—— 编辑需要知道你能给实质意见。

```
尊敬的【待补：编辑姓名】编辑 / 《【待补：期刊名】》编辑部：

感谢邀请，我愿意承担稿件【待补：稿件编号】的审稿工作。

我的研究方向是【待补：你的方向】，与本文涉及的【待补：主题（须来自邀请邮件，
不得自行推断）】有直接交集，可以给出具体意见。

预计在【待补：X年X月X日】前通过系统提交审稿意见。

另外想确认两点：
1) 是否需要我声明利益冲突？
2) 贵刊对审稿意见的格式或篇幅有无特别要求？

此致
敬礼

【待补：姓名】【职称】【单位】
```

**A2 婉拒（得体拒绝三要素）**

三要素：**先谢邀请 → 给具体理由（不辩解、不冗长）→ 给出补救**。
不要只写「最近比较忙」；也不要编造理由。**一次只给一个理由**，罗列太多像借口。

- **理由一：时间冲突**

```
尊敬的【待补：编辑】：

感谢邀请与信任。我对稿件主题有了解，但【待补：时间段】我已承诺
【待补：在审稿件数 / 项目节点 / 答辩与结题安排】，无法在贵刊要求的
【待补：X 周】内给出负责任的评审意见。与其拖延，不如请您另请专家，以免耽误作者。

若贵刊后续有【待补：方向】方向的稿件，在【待补：时间】之后我很乐意承担。
也欢迎把我列为该方向的备选审稿人。

此致
敬礼

【待补：落款】
```

- **理由二：方向不符**

```
尊敬的【待补：编辑】：

感谢邀请。本文主要涉及【待补：方法/领域】，我的专长在【待补：你的方向】，
对稿件核心问题难以给出专业判断。为避免给出误导作者与编辑部的意见，
建议转请该领域更合适的专家。

若贵刊有【待补：你的方向】的稿件，我很愿意承担。

此致
敬礼

【待补：落款】
```

- **理由三：利益冲突（婉拒 + 声明一并写）**

```
尊敬的【待补：编辑】：

感谢邀请。我需要先声明一项潜在利益冲突：我与本文作者/单位存在
【待补：同单位 / 近期合作 / 师生关系 / 共同经费 / 竞争关系 / 亲属关系】。

按贵刊相关规定（具体条款请编辑部依贵刊制度判定），我认为应当回避，
故请另请专家评审。若编辑部认为该关系不影响评审，我可就
【待补：方法/统计部分】提供有限意见，最终由编辑部决定。

此致
敬礼

【待补：落款】
```

> **推荐替代审稿人时**：可以先在心里有人选，但**不要把同行的姓名+邮箱直接写给编辑部**，
> 除非你已获得对方同意。更稳妥的写法：「如需，我可以协助推荐人选，但请由编辑部直接联系，
> 我不便代为转达。」—— 擅自把同行联系方式转给第三方在学术圈同样是失礼。

**A3 请求延期**

要点：**主动给出新日期**（不是问「能不能延」）→ 说明已完成进度 → 给退路。

```
尊敬的【待补：编辑】：

感谢邀请，我已开始审阅【待补：稿件编号】。因【待补：期末考试/出差/项目节点】，
原定【待补：原日期】前提交有困难，希望将交稿时间调整至【待补：新日期】。

目前我已读完正文并整理了主要意见，只差【待补：需要核实的部分】。
若贵刊排期紧张，不便延期，请直接告知，我可退回稿件，由编辑部另作安排，
不会影响我对贵刊其他稿件的承接。

此致
敬礼

【待补：落款】
```

> 忌：「尽量」「尽快」「过几天」。延期**只能请求一次**，第二次延期应当直接退回稿件。

**A4 请求补充材料**

要点：**列出要什么 + 每一项用来做什么**。只说「请补充材料」对方不知道补什么，配合度低。

```
尊敬的【待补：编辑】：

感谢转达。审阅【待补：稿件编号】时，有几处需要补充材料才能判断，烦请协助：

1) 【待补：原始数据或统计输出】—— 用于核对【待补：表 X】的结果是否可复现；
2) 【待补：伦理审批信息】—— 用于确认【待补：涉及人的部分】的合规性；
3) 【待补：高清图/补充说明】—— 现图【待补：图 X】的【待补：坐标轴/图例】不清晰。

若作者不便提供，也请告知，我会在现有材料范围内给出意见。

此致
敬礼

【待补：落款】
```

**A5 利益冲突声明（接受审稿时主动声明）**

声明四要素：**冲突对象 + 冲突性质 + 时间范围 + 建议处理**。
最后把决定权交给编辑部，不自行判断。

```
尊敬的【待补：编辑】：

关于【待补：稿件编号】的审稿邀请，我需要声明一项利益冲突，供编辑部判断：

- 冲突对象：【待补：作者姓名 / 单位】
- 冲突性质：【待补：近三年合作发表 / 同单位同事 / 共同承担项目 / 师生关系】
- 时间范围：【待补：起止年份或「至今」】
- 我的建议：回避本次评审，或仅就【待补：方法/统计】部分提供意见

是否回避请编辑部依贵刊制度决定，我服从安排。

此致
敬礼

【待补：落款】
```

### B · 学术会议组织

**B1 征稿通知（Call for Papers）要素**

| 要素 | 必填内容 | 易错点 |
|---|---|---|
| 会议名称 | 中英文全称 + 缩写 | 缩写首次出现时须给全称，全文一致 |
| 主办/承办 | 主办、承办、协办、支持单位 | 用官方全称，不缩写；单位顺序不能错 |
| 时间地点 | 日期（含星期）、会场、线上平台与链接 | 跨时区会议**必须写时区** |
| 主题与分议题 | 会议主题 + 3–8 个 track | track 必须与征文范围对得上 |
| 征文要求 | 语言、篇幅、格式模板、是否匿名、原创未发表声明 | 用词不能超出主办方授权 |
| 投稿方式 | 系统链接 / 邮箱、命名规则、模板下载 | 邮箱投稿要写清主题行命名规则 |
| 重要日期 | 摘要截止、全文截止、录用通知、注册截止、会议日期 | **全部给具体日期**，「另行通知」最多用一次 |
| 出版与收录 | 论文集出版方、是否推荐期刊特刊 | **不得承诺 EI / CPCI / Scopus 等检索收录**，除非主办方书面确认 |
| 注册与费用 | 注册费、学生优惠、缴费方式、发票类型 | 金额与发票类型必须准确，不确定就留占位 |
| 组织与联系 | 组委会、主席、秘书处联系人邮箱与电话 | 联系人必须能实际答复，不能挂名 |
| 其他 | 最佳论文奖、学生专场、优秀报告推荐 | 奖项设置须主办方确认 |

> **本技能的高频事故**：征稿通知里写「本次会议论文集将被 EI 检索」。
> 检索收录由数据库方决定，主办方也无权承诺。除非有主办方书面确认，
> 一律写作 `【待补：出版与收录信息，须由主办方书面确认后填写】`。

**B2 专家邀请函要素**

| 要素 | 内容 |
|---|---|
| 抬头 | 专家姓名 + 已核实职称（见阶段一）；不确定用「X 老师」 |
| 事由 | 会议/讲座中英文全称、在其中的角色（主旨报告/特邀报告/分会场主持） |
| 时间 | 日期（含星期）、具体时段、报告时长、答疑时长 |
| 地点 | 会场名称、地址；线上则给平台、链接、会议号与测试时间 |
| 报告题目 | 建议题目（可写「题目可由您自定」） |
| 受众 | 本科生 / 研究生 / 教师 / 业界，人数规模 |
| 议程位置 | 第几场、前一位讲者、是否需提前到场 |
| 差旅安排 | 谁订票、舱位/席别标准、是否接送、住宿几晚与标准、随行人员 |
| 报销 | 报销范围、凭证要求、提交时限、报销联系人 |
| 报酬 | 专家费/讲课费标准与**依据出处**、个税代扣方式、发放时间与所需材料 |
| 内容授权 | 是否录像/直播、录像用途与范围、PPT 是否可分享 |
| 回执 | 回复截止日期 + 回执内容（能否出席/题目/身份证信息用于报销等） |
| 落款 | 主办单位（盖章）、联系人、电话、邮箱、日期 |

完整函件模板见前文「中英对照示例」，直接复用。

**B3 会议通知 / 议程 / 主持词 / 致辞**

- **会议通知**：名称、时间地点、报到时间与地点、议程概览、参会回执、住宿交通指引、
  注意事项（PPT 提交截止、时间控制、是否录制）、联系人。
- **议程**：时间精确到分钟、环节、报告人、题目、主持人、地点。
  **每个环节之间留 5 分钟切换机动**；上午/下午分段；茶歇与午餐写清。
  报告人姓名与单位必须核对（同 B2）。
- **主持词**四段：
  1. 开场：场合 + 欢迎 + 议程概览 + 时间规则（「每位报告 X 分钟，提问 Y 分钟」）
  2. 介绍报告人：**只介绍真实信息** —— 单位、职称、研究领域、代表作（依据真实材料，
     代表作题名与年份不得由 AI 补全）
  3. 串场与提问引导：承接上一场 + 引出下一场；提问先请现场再请线上，每人一问
  4. 收尾：致谢 + 提示下一环节 + 提示回执/合影/用餐等事务
- **开幕致辞**：致谢承办方 + 会议缘起 + 主题意义（**具体到本次议题，不空喊**）+ 议程概览 + 期望。
- **闭幕致辞**：回顾用**实际发生的数字**（收到投稿 X 篇、参会 Y 人、Z 个分会场）+
  指出已达成的共识与仍未解决的问题 + 致谢 + 后续安排（论文集/特刊/下届）。
  > 数字必须来自会议实际统计，教师提供；不得由 AI 估算。

**B4 会后：感谢信 / 纪要 / 论文集征稿**

- **感谢信**：写清**具体贡献**（做了什么、什么时候、起了什么作用）+ 实际影响 +
  后续期待。禁忌：「感谢您的大力支持」这类空句。
  给报告人、主持人、评审专家、志愿者各写不同版本 —— 不要一封群发。
- **会议纪要**：时间地点参会人、议题、每人发言要点、**决议**、待办（任务/责任人/期限）、附件。
  > **决议与待办必须经会议确认**。AI 只整理，不替会议「决定」，
  > 拿不准的写 `【待教师确认：是否为会议决议】`。
- **论文集征稿**：复用 B1 的 CFP 要素表；若为期刊特刊，
  须先有**期刊方的正式确认**，否则不得写「拟在《X》出版」。

### C · 合作洽谈

**C1 初次接触邮件（四要素）**

四要素：**我是谁 + 为什么找你（具体到某篇论文/某个方法）+ 我想做什么（一句话）+
我需要你做什么（一个低成本的诉求）**。

```
主题：【合作】关于【待补：具体合作点】的合作探讨 —— 【待补：你的单位/姓名】

尊敬的【待补：姓名】教授：

您好！我是【待补：单位】【待补：院系】的【待补：姓名】，【待补：职称】，
主要做【待补：你的研究方向】。我在【待补：会议或期刊，年份】读到您的
《【待补：论文题名】》，其中【待补：具体方法或结论】对我们正在做的
【待补：你的工作】很有启发。

我们目前在做【待补：一句话说明你的研究】，已完成【待补：教师提供的真实进展】。
我的想法是，若把【待补：你的方法或数据】与【待补：对方的方法或数据】结合，
可能可以处理【待补：具体问题】。

想请教您两点：
1) 这个方向您认为是否值得做？
2) 若您有兴趣，是否方便约【待补：20 分钟】线上聊一次？

如果方向对不上，请直接告知，我不会再打扰。若您有兴趣，
回复一个您方便的时间段即可，会议邀请我来发。

顺颂
时祺

【待补：落款】
```

> **三条纪律**：
> ① 引用的对方论文（题名/年份/期刊）必须是教师提供的真实信息，AI 不得补全；
> ② **第一封邮件不要索要数据、不要谈署名** —— 这是最常见的失礼；
> ③ 诉求只留一个（约 20 分钟），把「要不要合作」这种大问题拆成「聊不聊」这种小决定。

**C2 跟进邮件（未回复时的得体催问）**

| 时点 | 动作 |
|---|---|
| 首次发出后 5–7 个工作日 | 第一次跟进：简短，**补一条新信息**（新结果/新会议/新截止），不重复原邮件 |
| 第二次无回复后 10–14 个工作日 | 第二次也是最后一次跟进：明确「若不便请忽略」 |
| 仍无回复 | **停止**。换渠道（会议现场、共同熟人引见）或换对象。**不要发第三次** |
| 对方明确婉拒 | 一句感谢 + 保持联系，**不追问理由** |

```
主题：Re: 【合作】关于【待补：合作点】的合作探讨

尊敬的【待补：姓名】教授：

冒昧再发一封。关于【待补：事项】，我们这边有了新进展：
【待补：一句话新信息】。若您有兴趣，我随时可以同步细节；
若目前不合适，也不必回复，我完全理解。

顺颂
时祺

【待补：落款】
```

> 「不必回复」是降低对方心理负担的关键句，比「期待您的回复」更能得到回复。

**C3 合作意向书要素 + 分工与署名讨论的措辞**

意向书要素（**AI 只列要素与措辞建议，不代拟条款结论**）：

| 条款 | 必须写清 | 提示 |
|---|---|---|
| 合作主题与目标 | 一句话目标 + 可检验的产出 | 不写「深化合作」这类无法检验的目标 |
| 双方角色与分工 | 谁做什么、交付物是什么 | **分工决定署名**，先谈分工 |
| 时间节点 | 里程碑与截止日期 | 与各自考核/毕业周期对齐 |
| 数据与材料 | 提供范围、格式、时点、能否用于其他用途 | 涉及人类数据须伦理审批 |
| 成果形式与署名 | 产出形式、排序原则、通讯作者、单位署名 | `【待补：需双方正式协商】` |
| 经费与资源 | 谁出资、谁出设备、经费科目 | `【待补：须经学校科研管理部门确认】` |
| 知识产权 | 归属、共有方式、许可与转让 | `【待补：须经学校知识产权/技术转移部门确认】` |
| 保密 | 保密范围、期限、例外情形 | 与学生学位论文/毕业要求的冲突要提前处理 |
| 变更与终止 | 如何修改、如何退出、退出后成果如何处置 | **缺此条最易起纠纷** |
| 有效期与签署 | 有效期、签署主体 | 个人签署与单位盖章的法律效力不同 |

**分工与署名讨论的措辞（三条原则）**：

1. **先谈贡献，后谈顺序**。把各自承担的工作逐条列出（选题 / 设计 / 数据 / 分析 /
   写作 / 修改 / 经费 / 指导），对照学科惯例（如 CRediT 贡献分类）再定顺序。
   直接谈顺序必然对立，谈贡献才有共同依据。
2. **用规则说话，不用立场说话**。
   - 好：`按我们领域的惯例，通讯作者通常承担投稿、答复审稿与全责，因此……`
   - 差：`这个必须是我。`
3. **敏感结论放进正式文件，邮件里只谈原则与流程**。邮件结尾写一句：
   `以上为我的初步理解，供讨论；最终以双方正式协议为准。`

```
关于署名，我的想法是先把各自承担的工作列出来，再对照学科惯例讨论顺序，
这样比直接谈顺序更容易达成一致。分工与顺序的最终结论，
建议写进双方的合作协议并经双方单位确认，邮件里只作为讨论记录。
```

### D · 外联与事务函件

**D1 请求提供数据 / 样品**

要素：要什么（精确到变量/批次/年份/规格）+ 用途 + 使用范围与保密承诺 +
时间要求 + 致谢或署名方式 + 是否需签协议 + 归还或销毁约定 + 成本与运费由谁承担。

```
主题：【数据索取】【待补：数据集/样品名称】—— 【待补：你的单位/姓名】

尊敬的【待补：姓名】老师：

您好！我是【待补：单位】的【待补：姓名】。我们正在做【待补：研究课题】，
想向您申请使用【待补：数据集/样品名称】，具体范围如下：

- 所需内容：【待补：变量清单 / 样品规格与批次 / 年份区间】
- 时间要求：希望在【待补：日期】前获得
- 用途：仅用于【待补：具体研究】，不用于其他目的，不向任何第三方提供
- 若涉及发表：将在文中致谢并注明来源为【待补：提供方】；
  署名方式按学科惯例与双方贡献协商
- 若需签署数据使用协议或材料转移协议，请告知贵方模板，我们按贵方要求办理
- 使用完毕后的处理方式：【待补：归还 / 销毁并出具说明】

请问是否可行？需要我们补充什么材料，请直接告知。

顺颂
时祺

【待补：落款】
```

> 不用「能否把数据发我一份」这种写法。数据提供方最关心的是**用在哪、会不会外泄、要不要签协议**，
> 这三点写清楚，回复率会高很多。

**D2 邀请评审专家 / 答辩委员**

要素：学位层次与学科、答辩人姓名（**适度披露**）、论文题目、时间（含星期与预计时长）、
地点或线上平台、**需回避的关系**、需提交的材料（评阅书/决议书模板与截止时间）、
报酬与报销、联系人。

> **两条注意**：① 邀请函中不宜向无关第三方透露答辩人信息，**必须逐一单独发送**，
> 不得群发（群发会把答辩人姓名与论文题目泄露给所有候选人）；
> ② 须核查评阅人与学生/导师之间是否存在应回避关系，必要时在邀请函里请对方自行声明。

**D3 推荐同行参评奖项**

要素：奖项名称与主办方（**须核实，不得凭记忆写**）、推荐类别、
推荐人身份与资格依据、被推荐人**真实可核查**的成就（含时间、成果名称、编号）、
推荐理由（具体到贡献与影响）、截止时间与材料清单、被推荐人是否已知情同意。

> **红线**：不得编造被推荐人的成果、奖项、数据、职务；
> 正式推荐前应征得被推荐人同意；推荐信里不写未经证实的评价。
> 所有事实留 `【待补：请教师提供可核查材料】`，不要用「在国内外产生重要影响」这类无据评价充数。

**D4 感谢信 / 贺信**

- **感谢信**：具体贡献（做了什么、什么时候、起了什么作用）+ 实际影响 + 后续期待。
- **贺信**：具体祝贺事由（真实可核：获奖名称 / 论文发表期刊 / 当选职务 / 校庆年份）+
  一句话说明其意义 + 祝愿。忌堆形容词，忌「再创辉煌」式空祝福。
- **两者都必须核对**：受贺人/受谢人姓名用字、职务、单位、事由名称与年份。

```
尊敬的【待补：姓名】教授：

您好！【待补：会议/评审/报告名称】已于【待补：日期】顺利结束。
您在【待补：具体工作，如担任分会场主持并评议 X 篇投稿】中的投入，
使【待补：具体效果，如青年学者的报告得到了细致反馈】。

再次感谢。后续【待补：论文集/特刊/下一届会议】的安排，我们再向您同步。

顺颂
时祺

【待补：落款】
```

## 红线

1. **不虚构**。对方的姓名、职称、单位、研究领域、已发表成果、奖项、职务一律依据真实信息。
   无信息一律留 `【待补：具体说明】`，**绝不用「合理的」内容补全**。
   **称呼与头衔写错是学术圈大忌**：副教授写成教授、研究员写成教授、院士降成教授、
   姓名同音字写错、单位写简称 —— 每一处都必须走阶段一的核对门，
   核不出来就降级为「X 老师」/`Dear Dr. X`，**猜就是错**。同一封信内职务前后必须一致。
2. **不代拟承诺性条款**。经费、报酬金额、署名顺序、通讯作者、知识产权归属、
   检索收录（EI/CPCI/Scopus）、出版承诺，一律不写成确定表述，
   留 `【待补：由主办方/期刊/学校确认】` 并提示**需正式协商**。
3. **审稿保密**。不得在邮件、草稿、附件中泄露稿件内容、作者信息、审稿意见、
   审稿人身份。审稿意见只通过期刊系统提交；不得向同事、合作者、学生、
   其他期刊透露正在评审的稿件。回复编辑部时只引用编辑部已告知的稿件编号与题名。
4. **利益冲突主动声明**。存在同单位、师生、近期合作、竞争、共同经费、亲属等关系时，
   主动声明并建议回避，**把处理决定权交给编辑部**，不自行判断。
5. **署名与经费要谨慎**。涉及合作署名、分工、经费分配的邮件，
   只谈原则与流程，明确写「最终以双方正式协议为准」；
   涉及经费与知识产权时提示教师走学校科研管理部门 / 技术转移部门的正式流程。
   不替任何一方承诺署名位置。
6. **推荐与评价要有据**。推荐同行参评奖项，被推荐人的成果必须可核查，
   推荐前应征得本人同意，不写未经证实的评价。
7. **所有对外函件教师本人必须通读定稿**。AI 只出草稿，**本技能不代发任何邮件、不代盖章**。
   涉及「是否同意/是否拒绝/是否承诺」的决定，一律留
   `【待教师确认：是否同意承担本次审稿】` 这类显式人工确认位。
8. **群发必须密送**。不得暴露收件人邮箱列表；答辩委员、评审专家邀请**必须逐一单独发送**，
   防止答辩人信息泄露给其他候选人。
9. **敏感信息本地处理**。学生姓名、学号、联系方式、身份证信息（报销用）只在本机处理，
   不上传、不外发；中间文件任务结束后提醒教师删除。
10. **不承诺未被确认的检索收录与出版**。主办方也无权承诺数据库收录，
    除非有书面确认，一律留占位。
