# 文献综述

*v1.0 —— 支持多会话连续作业的结构化文献综述工作流*

管理研究项目的文献综述：搭建新综述、继续已有综述，或查看所有综述的状态。综述遵循标准化模板，支持多种输出格式（Markdown、Quarto、Beamer）。

**参数：** `$ARGUMENTS`
- `setup` = 首次运行配置
- 无参数或 `status` = 显示所有综述的状态面板
- `new [名称]` = 搭建一个新综述（如 `new remote-ed`）
- `[名称]` = 继续某个已有综述（如 `soft-skills`）
- `[名称] referee` = 对某个已有综述运行"审稿人检查"（referee pass）

---

## 操作指令

### 第 0 步：读取配置

1. 检查 `~/.config/lit-review/config.yml` 是否存在。

2. **若配置不存在且 `$ARGUMENTS` 不是 `setup`：**
   告知用户："未找到配置。请先运行 `/lit-review setup` 完成初始化。"然后停止。

3. **若配置不存在且 `$ARGUMENTS` 是 `setup`：**
   进入 **S 模式**。

4. **若配置存在：** 读取并提取：
   - `base_dir` —— 综述存放位置
   - `author` —— 幻灯片/文档页眉上的署名
   - `voice_file` —— 可选，写作风格 `.md` 文件的路径（null = 使用默认风格）
   - `output_format` —— `markdown`、`quarto` 或 `beamer`

5. 若设置了 `voice_file` 且文件存在，读取它。否则使用默认风格：清晰、直白的学术文风。

6. 若 `[base_dir]/BEST_PRACTICES.md` 存在，读取其中的约定。

7. 按 `$ARGUMENTS` 路由到相应模式。

## S 模式：初始化（`setup`）

### S1. 询问配置问题

向用户提以下 4 个问题（可以对话式，也可以逐条问）：

1. **综述存放在哪里？**（绝对路径，如 `~/research/literature-reviews`）
2. **幻灯片/文档页眉上署什么名字？**（如 `Jane Smith`）
3. **你有写作风格文件吗？**（一个描述你偏好学术写作风格的 `.md` 文件路径，也可跳过）
4. **你偏好哪种输出格式？**（`markdown`、`quarto` 或 `beamer` —— 默认：`markdown`）

### S2. 创建配置文件

```bash
mkdir -p ~/.config/lit-review
```

写入 `~/.config/lit-review/config.yml`：
```yaml
# lit-review configuration
# Created [DATE]

base_dir: [用户的回答]
author: [用户的回答]
voice_file: [路径或 null]
output_format: [markdown|quarto|beamer]
```

### S3. 创建基础目录与起始文件

```bash
mkdir -p [base_dir]
```

创建 `[base_dir]/BEST_PRACTICES.md`，内容如下：

````markdown
# 文献综述 —— 最佳实践

*构建结构化、多会话文献综述过程中沉淀的经验教训。*

## 行之有效的做法

### 1. 标准化目录结构

每篇综述使用同一套模板。这意味着任何人（或任何 agent）都能随时接手任何一篇综述，并且确切知道去哪里找什么：

```
[review-name]/
├── AGENT_INSTRUCTIONS.md    # 这篇综述是干什么的
├── RESEARCH_QUESTIONS.md    # 我们想弄清什么
├── MASTER_LIST.md           # 我们找到了什么（单一事实来源）
├── SEARCH_PROCESS.md        # 我们如何检索（数据库、检索词、筛选标准）
├── [name]_lit.bib           # 机器可读的引文
├── literature_review.*      # 交付物（.md、.qmd 或 .tex）
├── CONTINUATION_LOG.md      # 已完成什么 / 接下来做什么
└── pdfs/                    # 全文论文
```

这种一致性是最大的加速器。新综述可以在一个会话内从零搭起来，因为结构是可预期的。

### 2. "通往论文的路线图"框架

每篇综述以一张表开始，把**论文章节 -> 文献流派 -> 关键论文**对应起来。这让整篇综述始终锚定其目的：支撑一篇特定的论文。贯穿全文的 "-> Paper" 标注让人很容易看出每条文献与你正在写的东西如何关联。

### 3. 把"审稿人检查"作为最后一步

在初步构建完成后，做一轮"审稿人检查" —— 追问"[目标期刊]的审稿人会期待看到什么？" —— 总能抓到 5-15 篇首轮检索漏掉的基础文献。这些往往是经典理论论文或开创性实证工作，审稿人视之为入场券。

### 4. MASTER_LIST 作为单一事实来源

用一张 Markdown 表格追踪每篇文献，列含作者、年份、标题、关键发现、是否入 bib，很容易看出缺口、避免重复。底部的"待获取文献"一节是个实用的滚动待办清单。

### 5. 续作日志支撑多会话作业

带日期的日志条目，采用"已完成什么 / 接下来做什么 / 卡点"格式，使上下文不会在会话间丢失。当综述跨越多天、或由不同 agent 接力时，这一点至关重要。

### 6. 要点小结（Key Takeaways）小节

在每个部分（Part）末尾加一个"要点小结"，迫使自己做综合提炼而不是简单罗列。在真正写论文时这些最有用，因为它们蒸馏出文献对你的论文意味着什么。

## 有待改进之处

### 1. PDF 收集是最薄弱环节

`pdfs/` 目录往往很稀疏。许多论文在付费墙后。没有全文，深读就只能基于摘要和既有知识，而不是仔细阅读。这是最大的质量缺口。

### 2. Bib 文件需要明确约定

如果论文项目已有 `.bib` 文件，只新建一个补充 bib 收录新增引文。如果没有论文 bib，就建独立 bib。在创建综述时就定下来，并写进 AGENT_INSTRUCTIONS.md。

### 3. 深读还可以更深

综述往往能很好地概括论文，但很少深入方法细节、带置信区间的效应量，或跨研究的估计值仔细比较。全文 PDF 对此帮助极大。

---

## 对未来综述的建议

### 流程改进

1. **尽可能从源文档开始。** 有论文草稿的综述比基于口头描述构建的综述更有针对性。哪怕只是带关键引文的两页粗略提纲，也能显著提升质量。

2. **审稿人检查要早做，不只是最后做。** 基础文献应在第一轮检索中就出现。可以从这个问题开始："[目标期刊]的审稿人一定会期待看到哪 10 篇论文？"

3. **考虑两轮法。** 第一轮：广泛覆盖。第二轮：对最重要的 5-10 篇做深读，包含方法、效应量，以及与你的研究的直接对比。

4. **增加"定位"（Positioning）小节。** 明确写出："我们的论文在这片文献中处于什么位置，新意在哪里。"这与"贡献"不同 —— 它讲的是学术邻域（intellectual neighborhood）。

5. **图表标准化。** 用于实验设计或概念框架的 Mermaid 图很有用 —— 让它们成为标准组件。

6. **增加"对比表"。** 一张把你的研究与最接近的 3-5 篇论文在关键维度（样本量、情境、设计、结果、发现）上做对比的表，几乎总是有助于定位。

## 你（人类）可以怎样让这一过程更高效

### 会话前

1. **提供论文草稿和/或 PAP。** 这是杠杆最高的输入。哪怕是不完整但带参考文献的草稿，也能让 agent 获得巨大的先发优势。
2. **明确指向 `.bib` 文件。** 并说明它是只读还是可编辑。
3. **指明目标期刊。** 这会塑造审稿人检查。
4. **标出你已知道缺失的论文。** 这让检索更聚焦，而不是让 agent 猜。
5. **明确读写权限。** 这能避免误改共享文件的风险。

### 会话中

6. **把 PDF 丢进 `pdfs/` 目录。** 如果你有 Zotero 或机构访问权限，在会话间导出关键 PDF 会显著提升深读质量。
7. **对交付物提意见，而不只是对清单提意见。** 输出文件才是交付物；master list 只是簿记。"第三部分太单薄"比"再找些论文"更可执行。

### 会话后

8. **在本地渲染输出。** 检查格式 —— 表格和图的破损在源码里看不出来。在下个会话报告任何渲染问题。
9. **如果你做了手工工作，更新续作日志。** 如果你在会话间加了论文、改了综述或下载了 PDF，记到日志里，以免下个会话重复劳动。

### 结构性建议

10. **考虑共享 Zotero 导出。** 如果你在同时推进多篇综述，按综述导出 Zotero 合集（BibTeX + PDF 目录）是黄金标准。
11. **"种子论文"约定。** 开始新综述前，列出你认为最重要的 5-10 篇论文。这锚定了检索方向，确保综述反映你的学术优先级。
````

## A 模式：状态面板（无参数，或 `status`）

### A1. 扫描所有综述目录

列出 `[base_dir]` 下所有子目录。对每个综述目录，读取：
- `CONTINUATION_LOG.md` —— 最近一条记录（日期 + 接下来做什么）
- `MASTER_LIST.md` —— 统计主表中的文献数量
- `AGENT_INSTRUCTIONS.md` —— 提取主题

### A2. 展示面板

```
## 文献综述状态 —— [日期]

| 综述 | 主题 | 文献数 | 最近会话 | 状态 |
|--------|-------|---------|--------------|--------|
| [名称] | [来自 AGENT_INSTRUCTIONS 的主题] | [数量] | [日期] | [推断] |
| ... | | | | |

### 各综述接下来做什么
- **[名称]**：[续作日志中的事项]
- ...
```

### A3. 提示

```
选项：
  [名称]       —— 继续某篇综述（如 "soft-skills"）
  new [名称]   —— 搭建新综述
  done         —— 退出
```

## B 模式：继续已有综述（`[名称]`）

### B1. 读取综述上下文

并行读取 `[名称]` 的以下文件：
1. `[base_dir]/[名称]/AGENT_INSTRUCTIONS.md` —— 范围、主题、源文档
2. `[base_dir]/[名称]/CONTINUATION_LOG.md` —— 上次进行到哪里
3. `[base_dir]/[名称]/RESEARCH_QUESTIONS.md` —— 研究问题结构与论文映射
4. `[base_dir]/[名称]/MASTER_LIST.md` —— 当前文献清单

若有文件缺失，标记出来并提议按标准模板创建。

### B2. 展示续作摘要

显示：
```
## [综述名称] —— 继续

**主题**：[来自 AGENT_INSTRUCTIONS]
**上次会话**：[续作日志中的日期]
**已追踪文献**：[MASTER_LIST 计数]

### 上次进行到这里
[最近一条续作日志中的"接下来做什么"事项]

### 上次会话的卡点
[记录的卡点，如有]
```

然后问：
```
你想做什么？
  1. 检索新论文（网络检索 + 前向/后向引文追踪）
  2. 构建或扩展输出文件（幻灯片/文档）
  3. 深读特定论文（需要 PDF）
  4. 更新 MASTER_LIST 与 .bib
  5. 审稿人检查（核查基础性/经典文献）
  6. 生成 PDF 下载清单（为缺 PDF 的论文生成 DOI 链接）
  7. 其他 —— 描述你的需求
```

### B3. 执行工作

按用户指示执行。各类工作的做法：

**检索新论文：**
- 用网络检索查找符合综述研究问题的论文
- 对找到的每篇论文：提取作者、年份、标题、关键发现、RQ 映射
- 对照 MASTER_LIST 去重
- **跨综述去重**：同时扫描 `[base_dir]` 下*其他*综述目录中的 MASTER_LIST.md。若某篇论文已存在于另一篇综述中，标注："同时见于：[其他综述]（RQ X.Y）"。这能浮现共享的学术领地，避免重复检索。
- 把新条目加入 MASTER_LIST.md
- 把 BibTeX 条目加入 `[名称]_lit.bib`
- 在 `SEARCH_PROCESS.md` 中更新检索词、所用数据库与日期
- 汇报："找到 N 篇新论文。已加入 MASTER_LIST 与 .bib。[其中 M 篇同时出现在其他综述中。]"

**构建/扩展输出文件：**
- 遵循 BEST_PRACTICES.md 的标准结构：
  - 路线图（文献流派 -> 论文章节，关键论文表）
  - 第 I-VI 部分：按主题分块
  - 关键论文深读（方法、效应量、与论文的关联）
  - 每部分末尾的要点小结（Key Takeaways）
  - **对比表**（标准组件 —— 模板见下）
  - **定位小节**："我们的论文处于什么位置；新意是什么"
  - 第 VII 部分：缺口、贡献、定位
- 用 `-> Paper` 标注起草时的关联点
- 用 Mermaid 图表达概念框架
- 若配置了写作风格文件则遵循之，否则用清晰、直白的学术文风

**对比表模板**（每篇综述都包含，通常放在第 VII 部分或深读之后）：
```markdown
## 我们的研究与已有研究对比

| 维度 | [我们的研究] | [最接近的论文 1] | [最接近的论文 2] | [最接近的论文 3] |
|-----------|------------|-------------------|-------------------|-------------------|
| **情境** | | | | |
| **样本** | | | | |
| **设计** | | | | |
| **处理/信号** | | | | |
| **关键结果** | | | | |
| **主要发现** | | | | |
| **不同之处** | *我们的贡献* | | | |

> **-> Paper**：这张表直接对应"贡献"一节。"不同之处"列的每一行都是一个论述点。
```

**深读论文：**
- 检查 `pdfs/` 目录中可用的全文 PDF
- 对每篇论文：方法、样本、带效应量的关键结果、局限
- 把发现映射到研究问题
- 注明与母论文（parent paper）设计/框架的关联

**更新 MASTER_LIST 与 .bib：**
- 核对输出文件中出现但不在 MASTER_LIST 中的论文
- 确保所有 MASTER_LIST 条目都有 RQ 映射
- 检查 .bib 的完整性（DOI、期刊名、页码）

**审稿人检查：**
- 见下方 D 模式。

**生成 PDF 下载清单：**
- 扫描 MASTER_LIST.md，找出 PDF? 列为空、"No" 或缺失的所有论文
- 对每篇缺 PDF 的论文：
  - 从 .bib 文件查 DOI（如有）
  - 构造 Google Scholar 检索链接：`https://scholar.google.com/scholar?q=[作者]+[年份]+[标题关键词]`
  - 构造 DOI 链接：`https://doi.org/[DOI]`（如有 DOI）
- 在 `[base_dir]/[名称]/PDF_DOWNLOAD_LIST.md` 输出清单文件：

```markdown
# PDF 下载清单 —— [名称]
*生成于 [日期]。[M] 篇论文中 [N] 篇缺 PDF。*

下载 PDF 并按命名约定保存到 `pdfs/`：`作者-年份-短标题.pdf`

## 优先（深读所需的关键论文）
- [ ] **作者 年份** —— 标题
  - DOI: [https://doi.org/10.xxxx](https://doi.org/10.xxxx)
  - Scholar: [检索](https://scholar.google.com/scholar?q=...)
  - 保存为：`作者-年份-短标题.pdf`

## 其他论文
- [ ] **作者 年份** —— 标题
  - Scholar: [检索](...)
  - 保存为：`作者-年份-短标题.pdf`
```

- 汇报："已生成下载清单：[N] 篇论文需要 PDF。其中 [K] 篇有 DOI 链接，[J] 篇只有 Scholar 链接。文件已保存到 `PDF_DOWNLOAD_LIST.md`。"

### B4. 更新续作日志

**每个会话结束时必须执行。** 在 `CONTINUATION_LOG.md` 中追加一条带日期的记录：

```markdown
### [日期] —— [会话简述]

**已完成**
- [具体成果 —— 要精确]

**接下来**
- [ ] [可执行的事项]

**卡点**
- [任何问题，或"无。"]
```

### B5. 会话完成汇报

```
### 会话完成

**综述**：[名称]
**本次新增论文**：N
**新增/修改的输出章节**：N

下一步：[续作日志中最优先的 2-3 项]
```

若输出格式为 `quarto`，补充："运行 `quarto render literature_review.qmd` 检查格式。"
若输出格式为 `beamer`，补充："运行 `pdflatex literature_review.tex` 和 `bibtex literature_review` 检查格式。"

## C 模式：新建综述（`new [名称]`）

### C1. 收集信息

询问用户：

1. **这篇综述支撑哪个研究项目？**（论文标题、项目名）
2. **有源文档吗？**（论文草稿、PAP、现有 .bib —— 请提供路径）
3. **目标期刊是什么？**（塑造审稿人检查）
4. **关键文献流派有哪些？**（3-8 个主题）
5. **有哪些你已知的具体缺口？**（综述应聚焦的主题）

### C2. 创建目录结构

```bash
mkdir -p [base_dir]/[名称]/pdfs
```

### C3. 搭建文件骨架

按标准模板创建所有文件。前 6 个文件对所有输出格式通用：

**AGENT_INSTRUCTIONS.md** —— 填入：
- 主题、范围、读者
- 母项目与论文引用
- 源文档路径（论文草稿、PAP、.bib）
- 目标期刊
- 内容主题（来自用户输入）
- PDF 命名约定：`作者-年份-短标题.pdf`
- 会话前/后清单

**RESEARCH_QUESTIONS.md** —— 填入：
- 5-8 个主题组，每组 3-5 个问题
- 映射表：论文元素 -> 文献焦点
- 依据：论文草稿（如有）、用户指定的主题、目标期刊的期待
- 若无论文草稿：从主题出发创建占位 RQ，标注"草稿 —— 待源文档细化"

**MASTER_LIST.md** —— 填入：
- 种子论文小节（如有论文草稿/.bib 则从中提取）
- 空的"网络检索结果"与"待获取文献"小节
- 列头：作者、年份、标题、关键发现、RQ、是否入 bib、PDF?

**[名称]_lit.bib** —— 填入：
- 种子论文的 BibTeX 条目（若提供了源 .bib）
- 否则：只有头部注释的空文件

**SEARCH_PROCESS.md** —— 骨架：
```markdown
# 检索过程 —— [名称]

*检索方法的文档记录，用于可复现性。*

## 已检索数据库
- [ ] Google Scholar
- [ ] NBER Working Papers
- [ ] EconLit / JSTOR
- [ ] SSRN
- [ ] Web of Science
- [ ] 其他：___

## 检索词

| 轮次 | 日期 | 检索词 | 数据库 | 浏览结果数 | 收录论文数 |
|-------------|------|-------|----------|-----------------|--------------|
| 1 | [日期] | [检索词] | [数据库] | [N] | [M] |

## 纳入标准
- [根据 AGENT_INSTRUCTIONS.md 的范围定义]

## 排除标准
- [根据范围定义]

## 前向/后向引文检索
| 种子论文 | 方向 | 找到的论文数 |
|-----------|-----------|-------------|

## 备注
- [与检索计划的任何偏离、意外发现或方法学说明]
```

**CONTINUATION_LOG.md** —— 第一条记录：
```markdown

**已完成**
- 创建综述目录与全部模板文件（含 SEARCH_PROCESS.md）

- [若有源文档：基于论文结构起草研究问题]

**接下来**
- [ ] 审阅并批准研究问题（RESEARCH_QUESTIONS.md）

- [ ] 用首批文献构建 MASTER_LIST
```

### C4. 读取源文档（若提供）

若用户提供了论文草稿：
- 读取它（遵守文件权限 —— .tex、.md、.pdf 可以；不要打开 .dta、.csv、.sav）
- 提取：研究问题、被引论文、关键主题、方法、贡献声明
- 用提取的信息填充 RESEARCH_QUESTIONS.md，并为 MASTER_LIST 播种

若用户提供了现有 .bib：
- 读取它
- 提取条目作为 MASTER_LIST 的种子论文
- 若为只读：在 AGENT_INSTRUCTIONS.md 中注明需要一个补充 bib

## D 模式：审稿人检查（`[名称] referee`）

### D1. 读取综述上下文

同 B1 —— 读取所有综述文件。

### D2. 确定目标期刊

从 AGENT_INSTRUCTIONS.md 获取。若未指定，询问用户。

### D3. 检查基础文献

追问："[目标期刊]的审稿人一定会期待看到哪些引文？"

检索每个文献流派的经典论文。常见类别：
- **基础理论**：该领域的开创性理论模型
- **开创性实证**：领域内的里程碑研究
- **关键方法**：与设计相关的参考文献（如论文中使用的方法创新）
- **近期高曝光**：近 3 年顶级期刊上同主题论文

### D4. 对照 MASTER_LIST 交叉核对（含跨综述去重）

对识别出的每篇基础文献：
- 检查是否已在本综述的 MASTER_LIST 中
- **跨综述核对**：同时扫描 `[base_dir]` 下其他综述目录中的 MASTER_LIST.md。若该论文存在于别处，注明："同时见于：[其他综述]" —— 这有助于识别共享的基础文献、避免重复深读。
- 若本综述缺失：加入 MASTER_LIST 并附 RQ 映射
- 把 BibTeX 条目加入 .bib
- 在"审稿人检查补充"小节中标记

### D5. 汇报

```
### 审稿人检查完成：[名称]
```

## 错误处理

- **未找到配置**："未找到配置 `~/.config/lit-review/config.yml`。运行 `/lit-review setup` 创建。"
- **未找到综述目录**："未找到综述 `[base_dir]/[名称]/`。你是指以下之一吗：[列出已有综述]？或运行 `/lit-review new [名称]` 新建。"
- **已有综述缺文件**："[名称] 综述缺少 [文件]。要我按标准模板创建它吗？"
- **新综述无源文档**：用占位 RQ 和空 MASTER_LIST 继续。在 CONTINUATION_LOG 中注明需要源文档以提高针对性。
- **深读时 PDF 不可用**："pdfs/ 中无全文。将基于摘要和既有知识分析。如需更深入的分析，请把 PDF 放到 `[base_dir]/[名称]/pdfs/[作者-年份-短标题].pdf`。"

## 约定

- **文件命名**：小写连字符，无空格
- **PDF 命名**：`作者-年份-短标题.pdf`
- **写作风格**：若配置了风格文件则遵循之；否则用清晰、直白的学术文风
- **引文**：.bib 中用 BibTeX；正文中统一"作者 (年份)"格式；有 DOI 时附 DOI 链接
- **Bib 约定**：若论文项目有自己的只读 .bib，新建补充 bib 只收录新增引文
- **续作日志**：每个会话结束后**必须**更新 —— 日期、已完成、接下来、卡点
- **MASTER_LIST 作为单一事实来源（SSOT）**：每篇论文都追踪于此；无重复；所有条目都有 RQ 映射
- **检索文档化**：每次检索会话都在 SEARCH_PROCESS.md 中更新检索词、数据库与日期
- **跨综述去重**：添加论文时，检查其他综述的 MASTER_LIST，标记共享文献
