# 期刊审稿意见撰写

> **Goal**：把一篇稿件从「读不懂、说不出、写不细」变成一份**可直接提交的审稿意见初稿**：
> 读懂（结构化拆解）→ 评透（六维检查）→ 说清（三段式编号意见）→ 定级（must/should/nice）→ 定论（四档结论）。
> **产出是草稿，审稿结论由审稿人本人判断。** AI 不替作者改论文，也不替编辑做调查结论。

## 何时使用

- 收到期刊/会议外审邀请，需要按时交一份审稿意见
- 手上已有稿件，需要判断「能不能收 / 大修还是小修」
- 需要一个审稿意见的**结构骨架和措辞模板**，或要在稿件上直接留批注
- 需要区分「给作者的意见」与「给编辑的保密意见」

**不适用**（走别的 skill）：

| 场景 | 走哪个 |
|---|---|
| 指导自己学生的论文、写评语、预判答辩问题 | `thesis-supervisor` |
| 模拟评审自己的项目申报书 | `grant-proposal` |
| 自己要投稿，想先自查 | `research-assistant` + 本 skill 的阶段二当自检表 |
| 投稿被拒后写申诉信 | 本 skill 只提供红线段落，申诉不在范围内 |

## 前置信息收集（intake，一次性问完）

**不要边审边问。** 开头把下面这些合并成一次提问：

1. **目标期刊/会议**名称 + 稿件类型（研究论文 / 综述 / 短通讯 / 案例报告 / 会议扩展版）
2. **审稿表模板**：期刊给的结构化表单（有则必须按它的字段组织，无则用本 skill 默认六维结构）
3. **截稿时间**：决定投入深度（3 天内 → 只做 must-fix 维度 + 明确的专业外声明）
4. **是否需要给编辑的保密意见**（很多投稿系统是「给作者」和「给编辑」两个独立文本框）
5. **审稿人本人的专业背景**与该稿方向的接近程度（决定哪些维度能下重话，哪些只能提疑问）
6. **稿件文件**（PDF/docx）+ 是否被要求回传批注版
7. **利益冲突排查**：作者是否为熟人、合作者、同单位同事、师生、竞争者；近 3 年是否有合作/共同发表/共同申请项目；是否有个人恩怨

缺信息时的安全默认值（写明用了默认值，不要停下干等）：

| 缺什么 | 默认 |
|---|---|
| 无审稿表模板 | 用本 skill 的六维结构，交付物标注「结构为通用模板，请对照该刊审稿表字段调整」 |
| 无截稿时间 | 按「2 周内」安排；临近时优先输出 must-fix 与结论建议 |
| 未说明保密意见要求 | **默认需要**，额外产出独立文件（成本低，平台不需要就不上传） |
| 稿件为扫描版 PDF 无文字层 | 明确告知「无法可靠提取文字，需提供文字版或逐页人工核对」，**绝不靠猜补全内容** |
| 未声明利益冲突 | 视为「无」，但在交付说明中要求审稿人自行复核并补声明 |

**利益冲突问在最前面。** 若答案为「是」，本 skill 到此停止：请审稿人向编辑声明并退回邀请。
发现了冲突就立刻补声明，不要「先审完再说」。

## 工作流

### 阶段一 · 读稿与结构化拆解

**输入**：稿件文件 + 稿件类型。

**动作**：

1. **提取文本**。docx 直接读；PDF 转文本后**人工核对页数与段落完整性**。
   扫描版无文字层 → 停止拆解，告知教师需提供文字版。**任何缺口显式标注「【提取缺失：第 X 页】」，不靠上下文推测补全。**
2. **判定论文类型**：按 `paper-type-rubric.md` 判为 AI/深度学习、传统算法/理论、系统/工程、实验/实证、综述、其他 之一，写出 2–3 条判断依据（引用稿件内容）。类型决定阶段二用哪套方法学清单。
3. **填「稿件拆解卡」**（六项，缺一不可）：

| 项 | 要求 |
|---|---|
| 研究问题 | 作者明说的 + 摘要中暗含的（若二者不一致，这本身就是一条 Major） |
| 方法 | 方法名 + 核心机制 + 关键参数；注意「名实是否一致」 |
| 数据 | 来源、规模、时间跨度、采集方式、可得性声明 |
| 主要结论 | **逐条列出**，编号，便于后续与结果章节对账 |
| 作者声称的创新点 | 逐条摘录**原文**，标页码/段落 |
| 声称 vs 实际实现 | 见下表的对照判定 |

4. **区分「作者声称的贡献」与「实际实现的贡献」**——这是审稿的核心判断：

   - **声称** = 摘要/引言/结论里的原话（"本文首次…""显著优于…""提出了…"）。
   - **实现** = 方法、实验、结果章节里**能被检验**的东西。
   - 二者对不上，就是 Major 问题，且意见中必须**引用原文**，不写「作者似乎想说的是…」。

| 声称类型 | 判为「已实现」的条件 | 常见落差信号 |
|---|---|---|
| 提出了新方法 | 有新结构/新机制的具体描述 + 与基线可区分 + 消融或对照支持 | 只是把 A 模块换成 B 模块；模块拼接无协同证据 |
| 首次研究某问题 | 说明了文献检索范围，且未发现先例 | 只检索中文文献；只检索近 3 年；未检索同义术语 |
| 显著优于现有方法 | 同数据、同划分下对比 + 统计显著性 | 换数据集/换划分/更高调参预算；只报最好一次；无方差 |
| 理论证明了某性质 | 定理陈述 + 完整证明 + 假设合理性讨论 | 假设过强、证明跳步、只有证明思路（sketch） |
| 实验验证了机制 | 消融/中介分析/反事实对照等机制层证据 | 只报最终指标，用指标反推机制 |
| 方法具有普适性/可推广 | 至少 2 个不同场景或数据集验证 | 单数据集、单场景、单领域 |
| 数据/代码已公开 | 给出可访问的仓库或链接（并有访问日期） | 承诺「将公开」但无链接；链接失效 |

**输出**：`稿件拆解卡.md`（六项表 + 声称/实现对照表 + 标注「声称但证据不足」的位置清单）。

**退出条件**：六项填满；每条声称都能定位到原文位置；对照表无空缺；文本提取缺口已显式标注。
未达到 → 不要进入评审，先补齐或向教师说明缺口。

### 阶段二 · 分维度评审

按维度逐项过，**每个维度都必须给出结论**（"本维度无明显问题"也是结论）。
下面每个维度的问题清单是**检查问题**，不是意见模板；意见写法见阶段四。

#### 维度 1 · 创新性

- 与最接近的 2–3 篇已发表工作相比，本文的差别是什么？作者有没有**明确比较**？
- 增量属于哪一类：新问题 / 新方法 / 新数据 / 新发现 / 新应用？这一类是否达到**该刊门槛**？
- 声称的「首次」是否成立？检索范围是否说明？
- 创新点是否**可证伪**？（"提高了性能"可证伪；"提供了新思路"不可证伪）
- 是否存在「方法新但问题旧」或「问题新但方法只是套用」？
- 若是组合式创新，组合是否产生 1+1>2 的效果，还是简单拼接？有无消融支持？
- 选题是否与目标期刊范围匹配？

> ⚠ **「我不认为这个方法有价值」≠「创新性不足」**。只有能指出「已有工作已做过」「增量不足以支撑该刊要求」「声称的首次不成立」时，才可写成创新性不足。个人学术偏好不得作为否定理由（见阶段五）。

#### 维度 2 · 方法严谨性

- 方法描述是否足以**复现**？关键超参、结构、数据预处理、随机种子、代码可得性是否交代？
- 假设是否**明示**？假设与研究问题是否匹配？
- 基线选择是否合理？是否遗漏公认强基线，或只用过时弱基线？
- 对比是否**公平**？（同数据、同划分、同调参预算、同评价指标、同算力）
- 消融实验是否覆盖了每一个声称的贡献模块？
- 评价指标是否与结论匹配？（类别不平衡却只报 accuracy 是典型问题）
- 是否做了统计检验？多次运行是否给均值/方差/置信区间？
- 领域特定口径：
  - **实验/实证类**：识别策略与前提检验（RCT/DiD/IV/RD 各自的成立条件）、聚类层级是否正确、控制变量是否为「坏控制」、是否做了稳健性检验 → 参考 `skills/empirical-research/econ-audit/SKILL.md` 的清单
  - **AI/算法类**：基线公平性、超参搜索预算是否对等、是否只在测试集上调参、消融是否逐模块
  - **理论类**：定理陈述完整性、证明是否跳步、假设是否过强、符号是否定义
  - **系统/工程类**：负载条件、可扩展性测试、与现有系统的对比条件是否交代
  - **综述类**：检索策略（库、关键词、时间范围）、纳入排除标准、筛选流程（是否可复现）、覆盖完整性
- 可复现性声明是否符合期刊政策？（数据/代码可得性声明缺失是政策问题，不是口味问题）

#### 维度 3 · 数据可靠性

- 数据来源、采集时间、采集方式是否交代？
- 样本量是否明确？**各阶段样本量是否一致**（入选/排除/缺失/最终分析）？有无流程图？
- 缺失值如何处理？处理方式是否可能引入偏倚（如整例删除 vs 插补）？
- 标注质量：标注者数量、一致性指标（kappa/ICC）、分歧仲裁机制？
- 数据划分是否**泄漏**？（同一受试者/同一张图/同一时间窗口/同一样本出现在训练与测试集）
- 数据是否公开可得？不可得的理由是否合理？涉及人类受试者的**伦理审查与知情同意**是否声明？
- 描述统计是否与结论方向一致？表格数字内部是否自洽（合计=分项之和、百分比基数、频数总计）？
- 异常值的处理是**事前说明**还是事后挑选？
- 单位、量纲、时间口径全文是否一致？

#### 维度 4 · 论证充分性

- 从数据到结论的每一步推理是否有据？（「相关当因果」「以偏概全」「以个体推总体」）
- 结论是否**超出数据支持范围**（overclaim）？逐条拿「主要结论」与结果章节对账。
- 是否考虑了**替代解释**？有没有排除性分析？
- 局限性与未来工作是否诚实？是否回避了最关键的威胁？
- 讨论是否只是复述结果，没有机制解释？
- 图表能否**独立读懂**？（坐标轴、单位、误差棒含义、显著性标注、样本量 n、图注完整性）
- 图表与正文是否一致？（正文说的数与表里不一致是硬伤）
- 有无**选择性报告**：只报显著结果 / 只报最好一次 / 只报有利子组 / 事后改主要终点？

#### 维度 5 · 写作规范

- 结构是否完整（IMRaD）？摘要是否含目的/方法/结果/结论且**无引用、无未定义缩写**？
- 摘要与正文结论是否一致？有无摘要夸大？
- 术语与符号是否全文一致、是否都有定义？
- 图表质量：分辨率、可读性、色盲友好、是否有重复信息、图注是否自足？
- 参考文献格式是否符合该刊要求？**正文引用与文末列表是否一一对应**（有无「幽灵引用」——列表中未被引用，或正文引了列表中不存在）？
- 篇幅是否符合该刊要求？
- 标题与关键词是否恰当、可检索（避免过于宽泛或生造词）？

> ⚠ **语言问题只能作为 Minor，除非严重影响理解**。审稿人不是语言编辑，不要用语言问题打压一篇方法扎实的稿件。同理，格式问题不构成拒稿理由。

#### 维度 6 · 文献覆盖

- 关键先行工作是否引用？（方法来源、同问题最相关工作、作者自己相关前作）
- 是否遗漏近 2–3 年的重要进展？
- 有无「只引支持自己的文献」倾向？关键反方证据是否被略过？
- 自引比例是否异常高？（合理交代前作是应该的；但关键比较缺失 + 自引密集，是问题）
- 是否存在「装饰性引用」（引了却没讨论与本文的关系）？
- 引用是否与本文声称的创新点冲突？（引了某工作，但该工作已做过本文声称的「首次」）

> ⚠ **审稿人的文献视野有限**。不确定是否遗漏时，措辞必须是「建议作者考虑是否需要引用/讨论 X 方向的工作」，
> 不能写「作者忽略了 X」。把自己的知识边界当成作者的过错，是不专业的审稿。

**输出**：六维评审记录（每维：结论 + 问题清单 + 问题定位）。

**退出条件**：六维都有结论；每个要写进意见的问题都能定位到**页/段/图/表/公式**；
不确定的事项只写「请作者澄清」，不写成断言。

### 阶段三 · 疑点筛查（与给作者的意见严格隔离）

**这是本 skill 最重要的一条流程红线：学术不端疑点只给编辑，不写进给作者的意见。**
本阶段独立进行，产出 `疑点备忘.md`，随保密意见提交编辑。

**输入**：稿件的全部图像、数据表格、文本。

#### A. 图像复用与操纵

- **Western blot**：同一条带在不同图中重复出现（泳道形状、背景噪点、边缘像素一致）；条带边缘异常锐利或背景过于干净；不同曝光条件下的「同一条带」；拼接缝（背景灰度阶跃、矩形边界）；裁剪未声明（多数期刊要求 cropped blot 须标注）；分子量 marker 被裁掉。
- **其他图像**：不同实验条件下的图高度相似；同一张图在不同图号下标注不同说明；图内 copy-move 重复区域；流式/免疫组化/显微镜图的重复视野；图片与图注描述不符。
- **可做的基础操作**（不做定性判定）：把图放大到 200–400% 逐图目视；把同一稿件内所有相似图**集中到一页并排比对**；记录可疑区域坐标与页码；检查图内是否有重复区域。
- **注意**：同一图内对照组泳道被多图共用，在部分领域是允许的，但**必须在图注中说明**。因此措辞是「请编辑部核查 / 请作者说明来源」，不是「造假」。

#### B. 数据异常

- **Benford 定律**：仅适用于**跨数量级的自然数据**（人口、财务、计数）且样本量足够（一般 n≥数百）。
  对**小样本、受约束数据（1–5 分量表、pH、百分比、率）不适用**——乱用会大面积误伤。只作为线索，不作为证据。
- **不合理的标准差**：多个组的 SD 完全相同或都是 0.1 的整数倍；SD 与均值呈固定比例（手算痕迹）；SE 与 SD 标注混用；误差棒含义未说明。
- **样本量异常**：方法说 n=30、结果表里变成 n=45；各表 n 不同且无解释；统计检验的自由度与样本量对不上。
- **统计不可能的数值**：p 值与检验统计量/t 值不匹配；相关系数与 p 不匹配；百分比合计异常；频数合计与总数不符；置信区间宽度与样本量不相容。
- **其他可疑模式**：组间基线差异过大却未做调整；效果量大到超出该领域常识（如行为学相关 r>0.9）；数值末位数字分布异常、过度集中在整数、成串重复数值（复制粘贴痕迹）；图里 5 个点而表里 n=6。

#### C. 文本重复

- 与作者自己前作的方法/引言段落高度重合（文本回收，方法学描述尤常见）；
- 与其他已发表文献的段落重合（用教师所在机构可用的查重服务复核，**本 skill 不做全网抄袭判定**）；
- 同一稿件内方法/结果段落重复；
- 翻译式重复（他人英文段落改写为中文再译回）；
- 会议论文扩展版是否已声明并做了实质扩展。

#### D. 处理流程（红线，逐条执行）

1. 疑点**一律**写入 `给编辑的保密意见.docx`（或独立 `疑点备忘.md` 随附），
   **禁止出现在给作者的意见里**——包括暗示性表述。
2. 给作者的意见中最多做到**中性、不指控**的要求：「请作者提供原始图像/原始数据以备核查」。
   不得出现「疑似造假」「图片重复」「抄袭」「拼接」等字样。
3. 措辞纪律：用「编辑部可能希望核查图 3 与图 5 的条带是否存在重复」，
   并明确写上「**本意见不代表对学术诚信的最终结论**」。定性是编辑与作者所在机构调查的职责，审稿人没有调查权。
4. 疑点严重时（如多图重复 + 数据自洽性同时异常），建议编辑**在调查完成前暂缓决定**，并建议另请图像取证专家。
5. 疑点内容**不得**在聊天群、社交媒体、学生或同事面前讨论；发现即本地隔离保管，评审结束后按要求删除。
6. 若疑点涉及审稿人自己的熟人/合作者 → 回到利益冲突条款：声明并回避，把线索交给编辑即可。

**输出**：`疑点备忘.md`（每条：位置 + 现象 + 证据强度弱/中/强 + 建议编辑部动作）。

**退出条件**：每条疑点都有具体位置；每条都标了证据强度；**逐句比对过给作者的意见，确认为零泄漏**。

### 阶段四 · 意见撰写

四块结构，**顺序与分栏必须与审稿表一致**（有模板时按模板字段组织，内容仍用这里的要求写）。

#### 1. 总体评价（Summary）——2–3 句

作用只有一个：**让编辑和作者确认你读懂了这篇稿子**。
写法：复述研究问题 + 方法 + 数据 + 主要结论 + 作者声称的贡献，不加评价词。

> 本文针对【研究问题】，采用【方法】，基于【数据】开展研究，主要结论为【结论】。
> 作者声称的贡献是【1–2 条】。该选题具有【现实意义/理论价值】，在【数据/方法/结构】方面有一定基础，
> 但在【X、Y】方面存在若干需澄清之处。

禁忌：不要用 Summary 完成判决；不要超过 4 句；不要在这里夹带讽刺或暗示。

#### 2. 主要问题（Major）——编号，每条三段式

**每条必须齐全：问题（定位 + 引用原文）→ 为什么是问题（如何影响结论可信度）→ 建议如何改进（可操作方向）。**
缺「为什么」就是宣判；缺「建议」就是不建设性。

> **M1.** 3.2 节（第 7 页）称「本文方法在全部数据集上均显著优于基线」，但表 2 中 Data-C 上本文方法 F1 为 81.3、基线为 82.0，且全文未报告多次运行的方差与显著性检验。
> *为什么是问题*：该表述与表 2 数据直接冲突，且缺少方差信息，读者无法判断其余数据集上的差异是否稳定，因此「全部数据集均显著优于」这一核心卖点目前缺乏证据支持。
> *建议*：补充每项结果的「均值 ± 标准差」与统计检验（并说明检验方法），或将该结论限定为「在 Data-A/Data-B 上优于基线」，并在结论章同步修改。

#### 3. 次要问题（Minor）——编号

格式、表述、图表细节、符号定义、文献补充、语言。**一条一件事**，不要在同一编号里塞五件事。

> **m1.** 表 1 中 "MAPE(%)" 的单位与表注重复，建议统一只保留一处。
> **m2.** 第 4 页第 2 段「显著提高」未给统计证据，建议改为「提高」或补充检验结果。
> **m3.** 第 3 页公式 (2) 中符号 α、β 首次出现处未定义，建议在正文补充说明。
> **m4.** 建议补充讨论【方向】的近年相关工作，以更完整地定位本文贡献。
> —— 注意：若不确定具体文献，**只写方向**；写具体文献必须确知存在且作者/年份/期刊准确（见红线 7）。

#### 4. 给编辑的保密意见（Confidential comments to editor）——独立文件

与给作者的意见**分开**，单独成文。内容包含：

- 你对稿件的整体判断与理由（为什么给这个结论）
- **不便写进给作者意见的保留意见**（例如：选题有价值但执行明显不足；本刊读者可能不关心这个方向）
- **学术不端疑点备忘**（阶段三产物，必须在此上报）
- 条件式判断：「若作者能补充 M1、M2 所述实验并修订 M3 的结论范围，本文可考虑在小修后接收」
- 专业外声明：「我对【X】部分不够熟悉，建议编辑部另请该领域审稿人复核」
- 与期刊适配度的判断（是否更适合改投其他类型刊物——**不点名具体期刊**，除非确有把握）

保密意见可以坦率，但仍需专业、可追溯；不做无据指控；不得贬损作者身份、单位或国籍。
若投稿系统只有一个文本框 → 在给作者的意见末尾明确标注「以下内容仅供编辑参考，请勿转达作者」，
但**优先争取分栏**，不要默认混写。

**输出**：`审稿意见.md`（作者可见部分）+ `给编辑的保密意见.md`。

**退出条件**：四块齐全；Major 每条三段式完整；每条问题都有定位；
**保密意见与作者意见之间无内容倒置**（尤其疑点）；已确认终稿结论以明确语句写出。

### 阶段五 · 分级、措辞与结论建议

#### 5.1 意见分级（借鉴 `QUALITY_GATES.md` 的三级问题模型）

| 分级 | 含义 | 对应质量门 | 处理方式 |
|---|---|---|---|
| **must-fix** | 不解决则结论不成立，或违反期刊政策（伦理声明缺失、数据可得性声明缺失、关键统计检验缺失导致主要结论无据） | `blocked` | 必须解决，否则建议拒稿或大修后重审 |
| **should-fix** | 显著削弱说服力，但结论不一定错（基线不全、消融不完整、图表不清、结论表述过强） | `needs-review` | 大修须处理 |
| **nice-to-have** | 提升质量但非必须（补充讨论、措辞优化、多引 1–2 篇、图表美化） | `advisory` | 作者可自行取舍 |

规则：

- **must-fix 一般不超过 3 条**。超过 3 条通常意味着结论不成立 —— 那就该是「拒稿」或「大修后按新稿重审」，而不是小修。
- 分级与 major/minor 不是一一对应：一个写在 Minor 里的问题（如作者承诺公开代码却没给链接）若涉及政策合规，要**升格为 must-fix**。
- 每条意见都要能回答「这是哪一级」，交付前统计一次三级条数。

#### 5.2 措辞：可接受 vs 应避免

| ❌ 应避免（对人 / 武断 / 情绪） | ✅ 可接受（对事 / 具体 / 可操作） |
|---|---|
| 作者显然没有读最近的文献 | 引言对 X 方向近年的工作覆盖较少，建议补充讨论该方向的进展 |
| 这个实验设计是错的 | 该设计未控制【变量】，因而【结论】可能受【混杂因素】影响；建议补充【对照/敏感性分析】 |
| 结果不可信 | 表 2 未报告方差与显著性检验，难以判断差异是否稳定；建议补充均值±标准差与检验结果 |
| 我不认为这个方法有意义 | 该方法与【已有工作】的核心区别尚不清晰，建议明确说明增量所在 |
| 英文太差，建议找母语者润色 | 第 3、5 页若干句子存在语法与术语一致性问题（如第 5 页第 1 段），影响理解；建议全文语言润色 |
| 作者自引太多 | 文献列表中自引占比较高，而与本工作最接近的第三方工作未做比较，建议补充 |
| 这明显是造假 | （**不给作者**）请编辑部核查图 3 与图 5 的条带是否存在重复；本意见不代表对学术诚信的最终结论 |
| 这篇文章毫无新意 | 与【已发表工作】相比，本文增量在于【X】，该增量目前不足以支撑本刊对创新性的要求 |
| 强烈建议拒稿，无需再投 | 该稿在【X】方面存在根本性问题，超出大修可解决范围，建议不予接收（附理由） |
| 你连基本概念都搞错了 | 第 2 页对【概念】的表述与通行定义不一致，建议核对并统一 |
| 我不同意这个观点 | 该论断目前尚缺证据支持 / 建议讨论替代解释的适用边界 |

**四条措辞纪律**：

1. **对事不对人**：主语是「该段 / 该表 / 该实验 / 该结论」，不是「作者」。
2. **给理由**：每个判断后面跟「因为…」或「证据是…」。
3. **给出口**：尽量给可执行的修改方向，而不是只宣判。
4. **去情绪词**：不用「明显」「显然」「居然」「可笑」「糟糕」；不做人身评价。

#### 5.3 关键区分：「我不同意」vs「论证不充分」

| | 论证不充分 | 我不同意 |
|---|---|---|
| 本质 | 论文**内部**证据链断了（缺实验、缺对照、缺统计、结论超出数据） | 审稿人的理论立场 / 方法偏好 / 学派与作者不同（贝叶斯 vs 频率派、质性 vs 量化、特定政策立场等） |
| 可否作为否定理由 | **可以**，可写成 must-fix | **不可以**。最多写成「建议作者讨论该替代路线的适用边界」，并明说这是学术观点差异而非缺陷 |
| 自检问句 | 把这条意见里的「我」换成一位持相反立场的同行，它是否仍然成立？ | 若答案是否 → 这是个人偏好，必须删掉或降级为 nice-to-have |

> 这条区分是审稿伦理的核心。审稿人有权要求证据，无权要求作者同意自己的世界观。

#### 5.4 结论判定标准

| 结论 | 判定标准（须同时满足） |
|---|---|
| **接受 Accept** | 无 must-fix；贡献达到本刊门槛；方法可复现；结论有据；仅剩 nice-to-have 级意见。现实中直接接受很罕见，若无十足把握不要给。 |
| **小修 Minor Revision** | 无 must-fix；结论与创新性成立；问题集中在表述、图表、文献补充、局部澄清；**作者无需补做新实验**即可完成修改。 |
| **大修 Major Revision** | 结论方向可能成立但目前证据不足；存在 1–3 条 must-fix（需补实验/补数据/重做部分分析/重新界定结论范围）；问题可由作者在原稿基础上解决，**不需推翻研究设计**。 |
| **拒稿 Reject** | 满足下列任一：研究设计或识别策略有根本缺陷且无法事后补救；核心结论被数据否定；创新性低于本刊门槛且非补实验可解决；严重伦理/合规问题；**疑似学术不端**（此时意见里只写「存在需编辑部核查的问题」，交由编辑决定）；与期刊范围不符。 |
| **拒稿但鼓励改投**（Reject with encouragement） | 选题有价值、问题在于执行。须明确告知：哪些问题必须解决、建议改为投向哪一类刊物。**不点名具体期刊**，除非确有把握，避免误导。 |

结论写作要求：

- **结论必须在意见末尾明确写出**，不要只列问题让编辑猜。
- 给**条件式判断**帮助决策：「若作者能补充 M1、M2 并修订 M3 的结论范围，本文可考虑在小修后接收」。
- 若审稿人自认在某维度专业不足（如统计细节、特定实验技术），必须**明说**并建议编辑部另请该领域审稿人复核 —— 硬答比说不会更伤信誉。
- 审稿结论**由审稿人本人拍板**：AI 给的是「按你列的问题，四档标准分别对应什么」，最终选择必须由人做出。

### 阶段六 · 交付与自检

**输入**：阶段一至五的全部中间产物。

**动作**：

1. 意见正文写成 Markdown 并冻结（`审稿意见.md`、`给编辑的保密意见.md`）。
2. 用 office-layer 生成 docx：

```bash
PY="skills/office-layer/.venv/bin/python"

$PY skills/office-layer/scripts/docx_kit.py md \
    --in 审稿意见.md --out 审稿意见.docx --title "审稿意见"

$PY skills/office-layer/scripts/docx_kit.py md \
    --in 给编辑的保密意见.md --out 给编辑的保密意见.docx --title "Confidential Comments to the Editor"

$PY skills/office-layer/scripts/docx_kit.py inspect --in 审稿意见.docx   # 自检
```

3. **若要在稿件上直接留批注**（很多期刊支持上传批注版；教师也常习惯先标再写），
   用 `docx_kit.py comment` 写 **Word 原生批注**（真 `comments.xml`，Word 打开即显示批注气球）：

```bash
$PY skills/office-layer/scripts/docx_kit.py comment \
    --in 稿件.docx --out 稿件_审稿批注.docx \
    --comments 批注锚点.json --author "Reviewer"
```

`批注锚点.json` 示例（**`anchor` 必须与稿件正文逐字一致，含标点**；可锚定正文段落，也可锚定表格单元格内文字）：

```json
[
  {"anchor": "本文方法在全部数据集上均显著优于基线",
   "text": "【must-fix】表2 中 Data-C 上本文方法低于基线，且未报告方差与显著性检验。建议补充均值±标准差与统计检验，或将该结论限定范围。"},
  {"anchor": "样本量为 30 名受试者",
   "text": "【should-fix】此处 n=30 与表1 的 n=45 不一致，请核对并统一。"},
  {"anchor": "本文首次将该方法应用于城市轨道交通客流预测",
   "text": "【must-fix】请补充说明文献检索范围；据我所知该方向已有相关研究，建议明确本文与既有工作的差别。"}
]
```

   - **锚点未命中会让脚本以退出码 2 结束并返回 `failed` 列表 —— 必须逐条修正锚点文本，不能忽略非零退出码。**
   - 批注里同样**不得出现学术不端定性表述**（阶段三红线适用于所有输出）。
   - **批注署名会影响匿名性**：单盲评审下批注作者栏不要写真实姓名（写 "Reviewer" 或按期刊要求）；
     双盲评审下不要产出任何含身份信息的批注文件。
   - 稿件是 PDF 时：office-layer 只处理 docx。若期刊只给 PDF 且要求回传批注版，
     先转换为 docx（用本机可用的转换工具），**转换后必须人工核对版式与文字**；
     转换有损时不要依赖锚点批注，改为在意见 docx 中按「页码 + 原文片段」定位引用。

4. 产出交付说明，写清：这是草稿；哪些判断需教师本人确认；哪些部分超出审稿人专业范围；稿件与意见须保密。
5. 提醒教师：评审结束后删除中间产物（拆解卡、提取的文本、批注中间文件）。

**退出条件**：全部文件产出且 `inspect` 通过（批注命令退出码为 0）；
意见中所有结论性判断都带人工确认位；**疑点零泄漏已逐条比对确认**。

每个交付文件末尾必须带人工确认位：

```
【待审稿人确认：最终结论建议（接受 / 小修 / 大修 / 拒稿）】
【待审稿人确认：判定为 must-fix 的条目是否恰当（当前 N 条）】
【待审稿人确认：保密意见中的疑点是否上报编辑部】
【待审稿人确认：本人是否熟悉【X】维度，是否需请编辑另请审稿人】
```

## 红线

1. **立场是中立审稿人，不替作者重写论文。** 可以指出「此处证据不足，建议补充 X」，
   **不得**代写段落、代做分析、代拟结论；意见中不出现可直接粘贴进论文的成品文字（Summary 的复述除外）。
2. **不因个人学术观点分歧而否定论文。** 必须严格区分「我不同意」与「论证不充分」（见 5.3）；
   每条意见过一遍自检问句：换成持相反立场的同行，它还成立吗？
3. **学术不端疑点单独提示编辑，绝不写入给作者的意见。** 给作者的意见中不得出现
   「疑似造假 / 图片重复 / 拼接 / 抄袭」等定性表述，连暗示都不行；只可要求提供原始图像与数据。
   审稿人没有调查权，定性是编辑与机构的职责。
4. **审稿内容与稿件本身严格保密。** 不得外传（含聊天群、社交媒体、学生、同事、家人）、
   不得用于自己的研究、不得据为己有、不得据此抢先发表、不得在评审结束前公开讨论。
   稿件只在本机处理；评审结束后删除中间产物。
5. **利益冲突必须回避并声明。** 作者是熟人、合作者、同单位同事、师生、竞争者，
   或近 3 年有合作/共同发表/共同申请项目，或存在个人恩怨 → 立即向编辑声明并退回邀请。
   事先没发现、审到一半才意识到的，也要立刻补声明，不要「审完再说」。
6. **AI 只出草稿，审稿结论必须由审稿人本人判断。** 接受/小修/大修/拒稿的选择权在人；
   产出必须留显式人工确认位，不得未经确认直接提交。
7. **不编造文献。** 「建议引用 X」必须基于教师确知存在的文献；
   不确定时只写方向（「建议补充该方向近年工作」），**绝不编造作者、年份、期刊、DOI**。
   同理，不虚构稿件的页码、图号、数据数值 —— 所有引用必须来自实际读到的稿件内容。
8. **不代替编辑部做调查结论**，只提供线索与证据强度判断。
9. **不泄露审稿人身份**（除非该刊为开放评审）：批注作者名、文件名、元数据都不得包含可识别身份的信息。
10. **不因语言或格式问题否定论文**（除非严重影响理解），这类问题一律 Minor。

## 自检清单

**流程完整性**

- [ ] intake 七项是否一次性问完；**利益冲突是否已确认并排除**
- [ ] 稿件文本提取是否有缺口，缺口是否显式标注（未靠猜测补全）
- [ ] 论文类型是否判定并写明依据（决定方法学口径）
- [ ] 拆解卡六项是否填满；声称 vs 实现是否逐条对照
- [ ] 六个维度是否都过了一遍（「无问题」的维度也有结论）
- [ ] 是否检查了「幽灵引用」（正文引用与文末列表是否一一对应）

**意见质量**

- [ ] Major 每条是否「问题 + 为什么是问题 + 建议改进」三段齐全
- [ ] 每条意见是否定位到页/段/图/表/公式
- [ ] 引用的原文片段、页码、数值是否都确实来自稿件（无一处凭印象）
- [ ] Minor 是否一条一件事，没有把五件事塞进一个编号
- [ ] 是否出现过「作者显然/明显/居然/可笑」等对人或武断措辞
- [ ] 是否把个人学术偏好当成了论文缺陷（做过「换成反方同行」自检）
- [ ] 语言与格式问题是否都被归为 Minor
- [ ] 每条意见是否已归入 must-fix / should-fix / nice-to-have，并统计了条数
- [ ] must-fix 是否不超过 3 条（超出则重新考虑是否应判拒稿或大修）
- [ ] 结论建议是否明确写出，且与 5.4 的判定标准一致
- [ ] 是否给出了条件式判断（「若补充 X 则可小修」）
- [ ] 专业范围外的部分是否显式声明并建议编辑部另请审稿人

**保密与合规（最重要的四项）**

- [ ] **保密意见是否独立成文件**，未与给作者的意见混写
- [ ] **疑点零泄漏**：逐句检查给作者的意见与批注，无「造假/重复/拼接/抄袭」字样或暗示
- [ ] 疑点每条是否都标了位置与证据强度（弱/中/强），并写明「不代表对学术诚信的最终结论」
- [ ] 是否留了人工确认位，交付说明是否写明「这是草稿，结论由您判断」
- [ ] 是否提醒教师：稿件与意见保密、评审结束后删除中间文件；批注署名未泄露身份

**产出物**

- [ ] docx 是否用 office-layer 生成，并 `inspect` 过（段落数/表格数/批注数符合预期）
- [ ] 批注命令退出码是否为 0（为 2 说明有锚点未命中，必须逐条修正）
- [ ] 交付说明是否写明何处用了默认值（无审稿表模板、无截稿时间等）

## 附录 · 常见审稿表字段 → 本 skill 结构映射

| 审稿表常见字段 | 对应本 skill |
|---|---|
| Summary / 稿件概要 | 阶段四 · 总体评价 |
| Novelty / Originality | 阶段二 · 维度 1 创新性 |
| Methodology / Technical soundness | 阶段二 · 维度 2 方法严谨性（按论文类型选口径） |
| Data / Statistics | 阶段二 · 维度 3 数据可靠性 + 阶段三 B 数据异常 |
| Validity of conclusions / Discussion | 阶段二 · 维度 4 论证充分性（结论与结果逐条对账） |
| Presentation / Clarity / Language | 阶段二 · 维度 5 写作规范（一律 Minor） |
| References / Literature | 阶段二 · 维度 6 文献覆盖 |
| Comments to the Author | 阶段四 · Major + Minor |
| Confidential Comments to the Editor | 阶段四 · 保密意见 + 阶段三 疑点备忘 |
| Recommendation | 阶段五 · 5.4 结论判定标准 |

> 审稿表缺「给编辑的保密意见」栏时，仍产出独立文件，由审稿人决定是否通过邮件发给编辑。
