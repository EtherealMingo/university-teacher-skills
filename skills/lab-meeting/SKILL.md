# 研究生组会管理

> **Goal**：把组会从「每周临时想」变成「一学期一张表 + 每人一条进度线」。
> 覆盖轮值排期、文献派工、会中追问、会后纪要、进度跟踪五件事，
> 全部落到 office-layer 出的 xlsx / docx / pptx。
> **AI 只出表、出框架、出草稿；排期公平性的最终判断、每个学生的进度评价、
> 学生汇报稿的实质内容，一律留给人。**

## 何时使用

- 「这学期组会怎么排 / 安排组会轮值 / 帮我排个轮值表」
- 「这篇文献让学生讲 / 把这篇文献派给小李 / 文献派工」
- 「会上问他们什么 / 给我几个追问的问题 / 怎么逼他们想深一点」
- 「生成组会纪要 / 整理一下今天组会 / 把三栏进度记一下」
- 「实验进度跟踪 / 谁的项目卡住了 / 这学期谁落后了」
- 「开题模拟 / 中期模拟 / 预答辩演练怎么安排」

**不适用**：本科毕业论文指导（走 `thesis-supervisor`）；课程教学设计（走 `lesson-plan`）；
单篇论文的纯分析不要 PPT（直接走 paper-to-slides / 文献精读）。

## 底座（vendor-first，禁止重写）

| 路径 | 用途 |
|---|---|
| `vendor/office-layer/` | **文件产出唯一通道**：`xlsx_kit.py`（轮值表/进度表 + 原生图表）、`docx_kit.py`（纪要 + **原生批注**）、`pptx_kit.py`（学生汇报稿骨架） |
| `vendor/paper-slides/paper-analyst/` | 文献派工后的上游分析能力。`references/output-schema.md` 分析结构；`references/presentation-schema.md` 幻灯片计划 JSON；`references/presentation-style-guide.md` 幻灯片内容压缩规则；`references/quality-checklist.md` 反幻觉（`[原文声明]`/`[模型归纳]` 标注） |
| `vendor/learning-education/thinking-toolkit/methods/01-socratic-inquiry.md` | 苏格拉底提问法 —— 组会追问问题的问法来源 |
| `vendor/awesome-benzi/references/INPUT_MODEL.md` | 问题批次（`question-batch`）机制 —— 本 skill intake 一次问完的依据 |
| `vendor/VENDOR.md` | 上游溯源与许可证合规 |

### 底座的两处必要改造（照抄会出错，务必看清）

1. **苏格拉底提问法**（`01-socratic-inquiry.md`）原设计是 **1 对 1 问诊**，
   铁律是「每次只问一个问题，等回答后再问下一个」。
   组会场景必须改造为 **批量问题清单**——导师一次拿到 5–8 个问题，现场自行取舍。
   **只借它的问法分类与「只问可能改变结论的问题」原则，不借它的逐问节奏。**
2. **paper-analyst 的 pptx 交接**（`references/pptx-handoff.md`）原设计是把幻灯片计划
   拼成自然语言 prompt 交给通用 `pptx` skill。本包按 `CONVENTIONS.md` §2
   改为 **映射到 office-layer 的 `spec.json`**（映射表见阶段三）。
   另一处偏差：该文件要求「不要传演讲者备注」，但本场景交付对象是**学生**，
   备注是给学生的讲解支架，因此 **保留备注**。

## 前置信息收集（intake，一次性问完）

按 `INPUT_MODEL.md` 的 `question-batch`，**合并成一次提问**，不要边做边问：

| # | 要问的 | 为什么必须问 |
|---|---|---|
| 1 | **课题组人数与学生名单**（姓名/年级/方向，文件或直接列） | **唯一不能默认的一项**。本 skill 绝不虚构学生姓名 |
| 2 | **组会频率与时长**（每周 / 双周；每次 1 小时还是 2 小时） | 决定槽位密度与每场汇报人数 |
| 3 | **学期周次范围**（开学第几周、共几周、首个组会日期） | 决定排期起点与终点 |
| 4 | **汇报类型**（文献汇报 / 进展汇报 / 开题 / 中期 / 预答辩，及轮换顺序） | 写进轮值表「汇报类型」列 |
| 5 | **是否有固定模板**（学院/课题组的轮值表、纪要、进度表模板） | 有则照套，无则用本 skill 通用结构 |
| 6 | **文献是否需要英文**（原文语言、是否要求英文汇报） | 决定派工单的语言要求与 PPT 用词 |

附加但强烈建议一次问掉：**节假日日期**、**导师出差/会议冲突周**、
**本学期需预答辩/开题/中期的学生名单**。

### 缺信息时的安全默认值（不停下干等）

| 缺什么 | 默认值 | 交付物标注 |
|---|---|---|
| 学生名单 | **不默认，必须索要** | 直接说明「不给名单无法排期，本工具不编造姓名」 |
| 频率 | 每周 | 「默认按每周排，如需双周请说明」 |
| 学期周次 | 18 周 | 「默认 18 周，请对照校历调整」 |
| 汇报类型 | 文献汇报 → 进展汇报 → 预答辩 轮换 | 「类型轮换为通用方案」 |
| 模板 | 本 skill 通用结构 | 「结构为通用模板，请对照贵院要求调整」 |
| 英文要求 | 按文献原文语言，汇报用中文 | 「假定中文汇报，如需英文请说明」 |

## 工作流

### 阶段一 · 一学期组会总排期（学期初做一次）

**输入**：学期周次范围、校历节假日、学校官方开题/中期/答辩时间点、各生所处阶段。

**动作**：把学期切成**三段式**，先定大事，再填轮值。

| 段落 | 典型周次 | 组会形态 | 目标 |
|---|---|---|---|
| 前段 · 打基础 | 第 1–6 周 | **文献精读**，每场 1 篇，逐段过 | 定向补方法基础，练读文献 |
| 中段 · 推进展 | 第 7–14 周 | **阶段进展汇报**，每人每 2 周一轮 | 数据、实验、写作往前推 |
| 后段 · 上考场 | 第 15–18 周 | **开题 / 中期 / 预答辩模拟** | 按正式答辩流程演练，全组当评委 |

后段必须**倒排**：以学院官方开题/中期/答辩日期为锚点往前推 2–3 周，
把模拟场次排进轮值表，不要等学生自己发现时间不够。

**输出**：`学期组会规划.md`（需要正式版再走 docx）。

**退出条件**：三段的时间边界与学院官方节点对齐，且**教师已确认**（这是排期判断，不是 AI 能定的）。

### 阶段二 · 轮值表生成与管理（每学期 / 每次调整）

**输入**：intake 的名单 + 频率 + 周次范围 + 节假日 + 导师冲突周；阶段一的三段划分。

**动作**：用 `scripts/roster_plan.py` 出 spec，再用 office-layer 落盘。

```bash
PY="vendor/office-layer/.venv/bin/python"

# 1) 学生名单写文件，一行一名（# 后为注释）
cat > 学生名单.txt <<'EOF'
张三   # 2023级 硕士
李四
王五
EOF

# 2) 生成轮值表 spec
$PY skills/lab-meeting/scripts/roster_plan.py \
    --students-file 学生名单.txt \
    --start 2025-03-03 \
    --weeks 18 \
    --frequency weekly \
    --per-meeting 1 \
    --types "文献汇报,进展汇报,预答辩" \
    --holidays 2025-04-07,2025-05-05 \
    --blocked 2025-03-31 \
    --predefense 张三,李四 \
    --out roster_spec.json

# 3) 落盘（office-layer 唯一通道）
$PY vendor/office-layer/scripts/xlsx_kit.py build --spec roster_spec.json --out 组会轮值表.xlsx
```

脚本会打印 `有效组会 / 跳过 / 汇报次数 / 点评次数 / 公平性告警`，**告警非空就必须处理**。

**轮值表列结构**（照此填，不要增删列，否则统计与筛选会错）：

| 列 | 填法 |
|---|---|
| 周次 | `第N周`，与校历一致 |
| 日期 | `YYYY-MM-DD`，表内按序列升序 |
| 汇报人 | 一名学生姓名；跳过周填 `—` |
| 汇报类型 | 文献汇报 / 进展汇报 / 开题 / 中期 / 预答辩 |
| 主题 | **生成时一律 `【待补：汇报主题】`** —— 主题由学生与导师定，AI 不编 |
| 点评人 | 另一名学生（自动避开本场汇报人，按点评次数最少轮换） |
| 备注 | 节假日/冲突标注，或临时调整说明 |

外带一张 **`公平性统计`** 工作表（姓名 / 汇报次数 / 点评次数 / 均衡检查）+ 原生柱状图。

**生成逻辑（五条，脚本已实现，可向学生解释）**：

1. **槽位铺排**：从首个组会日期起，每周 +7 天（双周 +14 天），铺满 `--weeks`。
2. **跳过保留行**：节假日与导师冲突周 **不删除行**，只标 `【节假日跳过】`/`【导师时间冲突，顺延】`
   且不排汇报人 —— 这样它仍是一张完整的学期日历，日历不会出现断层。
3. **预答辩倒排**：`--predefense` 指定的学生占据**最后 k 个槽位**，一人一场，
   保证演练落在学期末而非期中。
4. **类型轮换**：非预答辩槽位按 `--types` 循环（排除预答辩类型），避免连排同类。
5. **公平性贪心**：候选池先剔除**上一场的汇报人**（硬约束：任何人不得连续两场汇报），
   再按 `(汇报次数升序, 姓名)` 取；点评人取剩余人中点评次数最少者。
   若人数少到无法满足硬约束，脚本**打印告警并说明放宽原因**，绝静默糊过去。

**管理（学期中调整）**：
- 临时换人/调周：**直接改 xlsx**，改完回头看「公平性统计」是否还均衡。
- 结构性调整（加人、改频率、补节假日）：改参数**重新生成**，不要手工补行。
- 每周把实际日期、实际主题回填进表，学期末它自动成为一份组会档案。

**退出条件**：公平性统计无「⚠ 次数偏少」、脚本无公平性告警、抽查无连续两场同一人、教师确认。

### 阶段三 · 文献派工（导师指定文献 → 学生汇报稿骨架）

**输入**：教师指定的文献（PDF / DOI / 标题）、派给谁、汇报日期、汇报时长。

**动作**：

1. **先填派工单**（下面的四要素是重点，缺一样学生就白读）。派工单走 docx：
   ```bash
   $PY vendor/office-layer/scripts/docx_kit.py md --in 文献派工单.md --out 文献派工单.docx --title "文献派工单"
   ```
2. **走 paper-analyst 做上游分析**（`presentation` 或 `presentation_with_figures` 模式）：
   按 `references/paper-type-rubric.md` **先判论文类型再分析**（不要默认是 AI/ML 论文），
   按 `references/output-schema.md` 出结构，全程遵守 `references/quality-checklist.md`：
   每条结论标 `[原文声明]`（附位置）或 `[模型归纳]`（附推理依据），
   缺失字段标 `[未明确给出]`，**venue/DOI/年份原文没有就不许写**。
3. **出幻灯片计划**（`references/presentation-schema.md`），再映射到 office-layer 的 spec：
   ```bash
   $PY vendor/office-layer/scripts/pptx_kit.py build --spec slides.json --out 汇报稿骨架.pptx
   $PY vendor/office-layer/scripts/pptx_kit.py inspect --in 汇报稿骨架.pptx
   ```
   映射关系（替代 vendor 的自然语言 handoff）：

   | presentation-schema | office-layer spec |
   |---|---|
   | `deck_title` / `talk_style` + `audience` | `meta.title` / `meta.subtitle` |
   | `slides[].title` | `slides[].title` |
   | 幻灯片要点 | `slides[].bullets: [{text, level}]` |
   | `type: table` 的字段 | `slides[].table: {header, rows}` |
   | `figure_ref` / `figure_hint` | `slides[].image`（先用 `scripts/extract_pdf_figures.py` 导出） |
   | 讲述提示 | `slides[].notes`（**本场景保留**，给学生当讲解支架） |

   `inspect` 报出的 `overdense`（单页正文 >220 字符）**必须拆页**，这是提示不是错误。

**派工单必须给学生的信息（四要素 + 三项约束）**：

| 要素 | 写法 | 反例 |
|---|---|---|
| **为什么选这篇** | 与本组哪个课题相关、要借鉴它的哪一点（方法/实验设计/图表/写作） | 「随便找篇顶刊看看」 |
| **要重点看什么** | 指定 2–3 处：如「第 3 节的方法假设」「图 4 的消融实验设计」 | 「自己看去」 |
| **汇报时长** | 讲 X 分钟 + 提问 Y 分钟，明确页数上限 | 「讲一下」（学生必讲 40 分钟） |
| **需回答的问题** | 3–5 个，**从阶段四的五类里挑**，写清「答不上来也要说清卡在哪」 | 「有没有问题？」 |
| 语言要求 | 原文语言 / 是否要求英文汇报（对应 intake 第 6 项） | 默认中文，标注「假定中文汇报」 |
| 交付时间与格式 | 初稿发给导师的时间、终稿进组会的时间 | 「组会前给我」 |
| 图要自己重画 | 明确「图不要截图，自己用数据重画」 | — |

**输出**：`文献派工单.docx` + `汇报稿骨架.pptx`。

**退出条件**：派工单四要素齐全无空缺；pptx 已 `inspect` 且 `overdense` 已拆页；
**pptx 首页与末页均已写入「本文件为骨架，须由汇报学生自行重做主体内容」声明**；教师确认。

### 阶段四 · 组会追问问题生成（会前备，会中用）

**输入**：学生的汇报主题 / 摘要 / 上次纪要里的遗留项 / 进度表里的滞后与阻塞行。

**动作**：按五个分类各出问题，**由浅入深排序**，一场组会合计 **5–8 个，最多不超过 10 个**。

| 分类 | 训练什么 | 模板句式 |
|---|---|---|
| **① 澄清概念** | 别用大词糊过去 | 「你说的『显著提升』具体指哪个指标、提升多少？」「你用的 A 和文献里的 B 是一回事吗？」「这个术语你自己怎么定义？」 |
| **② 质疑假设** | 找出没写出来的前提 | 「这个结论依赖哪个你没说出口的前提？」「如果样本不是随机的，你的结论还成立吗？」「你默认了 X 成立，凭什么是 X？」 |
| **③ 追问证据** | 结论必须落在数据上 | 「这个说法的原始数据在哪？几个样本、几次重复？」「你做过统计检验吗，p 值多少？」「对照组是怎么设的？」 |
| **④ 检验边界** | 知道方法什么时候会崩 | 「换一个数据集/换一批参数，这套方法还成立吗？」「在什么条件下你的方法会失效？」「最坏情况下会怎样？」 |
| **⑤ 探寻替代解释** | 防止过早收敛到自己的解释 | 「除了你的解释，还有哪些可能？」「你怎么排除是数据泄漏而不是模型变强？」「如果是别人的审稿人，会从哪攻击这个结论？」 |

**硬规则**：
- 不出「是不是」「对不对」「有没有做」这类**封闭式提问** —— 学生一个「是」就把天聊死了。
- 每个问题后面标一句**想训练什么**，方便导师现场取舍。
- 优先从**上次遗留没闭环**和**进度表里标了滞后/阻塞**的地方生成问题，效果最好。
- **判断题不在自动生成范围**：「这工作够不够毕业」「要不要换题」「是否通过预答辩」属教师判断，
  一律留 `【待教师确认：___】`，AI 不出结论。

**输出**：`组会追问清单.md`（需要可再走 docx）。

**退出条件**：五类至少各 1 问（缺的类目说明为什么不适用，不得静默省略）、无封闭式提问、教师已圈选保留项。

### 阶段五 · 组会纪要（会后 24 小时内）

**输入**：会上记录 / 录音转写 / 教师口述、上一版纪要与进度表。

**动作**：按固定栏目成稿，**核心是三栏进度跟踪**。

**纪要栏目（照此结构，可另存为模板复用）**：

```markdown
# 组会纪要 · 第 N 周（YYYY-MM-DD）

## 一、会议信息
时间 / 地点 / 主持人 / 记录人 / 应到 X 人、实到 Y 人 / 缺席及原因 / 本次组会时长

## 二、汇报摘要
### 汇报人：__（汇报类型：__）
- 核心内容 3–5 条（只记事实，不写评价）
- 展示的关键数据/图表（注明编号）

## 三、三栏进度跟踪   ← 本纪要的核心
| 学生 | 上次遗留 | 本次进展 | 下次计划 |
|---|---|---|---|

## 四、讨论与追问
| 提问 | 学生回答要点 | 是否答清 |
|---|---|---|

## 五、导师意见
【待教师确认：本次组会总体意见】
【待教师确认：对 __ 同学的具体要求】

## 六、待办事项
| # | 事项 | 责任人 | 截止日期 | 验收方式 |
|---|---|---|---|---|

## 七、下次组会
时间 / 汇报人 / 汇报类型 / 文献与派工对象
```

**三栏进度跟踪怎么用（最关键的一条纪律）**：

- **上次遗留**：必须**逐条**出现在本次纪要里，每条标注去向 ——
  `已完成` / `未完成（原因）` / `已取消（原因）`。
  **遗留项凭空消失是组会纪要最常见的失效方式**，一旦允许消失，学生就知道拖着就行。
  写法示例：`上次要求补的对比实验 → 未完成（服务器排队 2 周）→ 顺延，导师协调算力`。
- **本次进展**：只写事实与数据（跑了什么、得了什么结果、卡在哪），
  **不写「表现不错」「态度积极」** —— 那是评价，属教师意见栏。
- **下次计划**：必须有**可验收的产出**（一份图表 / 一版初稿 / 一组数据），
  不写「继续推进」这种无法验收的话；同时明确它将在**哪一周组会**上验收。

**输出**：`组会纪要_YYYYMMDD.docx`。

```bash
$PY vendor/office-layer/scripts/docx_kit.py md --in 组会纪要.md --out 组会纪要_20250303.docx --title "组会纪要 · 第1周"
$PY vendor/office-layer/scripts/docx_kit.py inspect --in 组会纪要_20250303.docx
```

需要单独给学生留批注时，走 office-layer 的**原生批注**（学生看得见的批注气球）：

```bash
cat > 批注.json <<'EOF'
[{"anchor": "未完成（服务器排队 2 周）",
  "text": "顺延可以，但下周组会必须给出第一组对比结果。"}]
EOF
$PY vendor/office-layer/scripts/docx_kit.py comment \
    --in 组会纪要_20250303.docx --out 组会纪要_20250303_批注.docx \
    --comments 批注.json --author "指导教师"
```

> `anchor` 必须与正文**逐字一致（含标点）**，否则进入 `failed` 且进程以退出码 2 结束。**不要忽略这个非零退出码。**

**退出条件**：三栏无空缺；每条遗留项都有去向；待办事项每行都有责任人与截止日期；
导师意见栏为 `【待教师确认：…】` 而非 AI 拟好的评价；docx 已 `inspect`。

### 阶段六 · 实验进度跟踪表（每次组会后滚动更新）

**输入**：阶段五的三栏数据 + 教师/学生对状态的判断。

**动作**：

```bash
PY="vendor/office-layer/.venv/bin/python"

# 1) 出进度表（spec 里「状态」列的值必须是四个口径词之一）
$PY vendor/office-layer/scripts/xlsx_kit.py build --spec 进度spec.json --out 实验进度跟踪表.xlsx

# 2) 上状态色标（office-layer 的 build 不支持逐格填充，故用本 skill 的薄后处理，仍走 office-layer 的 venv）
$PY skills/lab-meeting/scripts/status_colorize.py \
    --in 实验进度跟踪表.xlsx --sheet 进度跟踪 --status-col 4
```

**列结构**：

| 列 | 填法 |
|---|---|
| 姓名 | 学生的本人姓名 |
| 课题 | 学生的学位论文/项目题目 |
| 阶段目标 | 本阶段**可验收**的产出（「完成 3 组对比实验」），不写「推进研究」 |
| 状态 | **只能是：正常 / 滞后 / 阻塞 / 未开始 / 已完成**（口径词，脚本靠它上色） |
| 卡点 | 具体障碍：外部条件（数据/设备/合作方）还是本人方法瓶颈 |
| 下一步 | 谁、做什么、到什么时候 |
| 预计完成 | `YYYY-MM-DD`；空白 = 未排期，红色提示 |

**状态色标口径（全组统一，不许各自解释）** —— 脚本同时写一张 `色标说明` 图例页：

| 状态 | 色 | 含义 | 导师动作 |
|---|---|---|---|
| 🟢 正常 / 已完成 | 绿底 `C6EFCE` | 按计划推进 | 常规过会 |
| 🟡 滞后 | 黄底 `FFEB9C` | 落后于阶段目标 | 会上要学生给出追赶时间点 |
| 🔴 阻塞 | 红底 `FFC7CE` | 卡在外部条件或方法瓶颈 | 导师介入，明确破局责任人 |
| ⚪ 未开始 | 灰底 `F2F2F2` | 尚未启动该阶段 | 确认启动条件是否具备 |

**怎么用它一眼看出谁需要关注**：
1. 打开表只看**颜色分布**：红黄合计即 `<需关注>` 数，脚本会在返回 JSON 里直接给出。
2. **看颜色变化**：上周绿、本周黄 → 这是会上最该问的一句「这两周发生了什么」。
   （所以务必**保留上周版本**，只改状态列，不要整表覆盖。）
3. **连续两次黄** → 触发一对一谈话提示（连续滞后多半不是能力问题，是任务分解或选题问题）。
4. **红项必须有导师动作**：红色单元格对应的「下一步」里若没有导师角色，说明这不是阻塞，是没人管。
5. 「预计完成」为空的行单独筛一遍 —— 没排期就没有进度可言。

**输出**：`实验进度跟踪表.xlsx`（含 `进度跟踪` + `色标说明` 两页）。

**退出条件**：每生每行状态明确且用口径词；所有红色行都有导师动作；
色标已落盘（抽查单元格填充色）；教师确认状态判断。

## 红线

1. **不虚构学生姓名与进度**。名单必须由教师提供（没给就停下索要，不给默认值）；
   进度事实必须来自教师记录、学生汇报或会议转写。
   缺的一切写 `【待补：具体说明】`，**绝不按「一个研二学生通常的进度」编造**。
   这在本包是后果最重的一条 —— 编造的进度一旦进了考核或答辩材料，是真实伤害。
2. **进度评价属判断性内容，一律留人工确认位**。
   「是否滞后」「是否算阻塞」「能否按期毕业」「要不要换题」「预答辩是否通过」
   全部写 `【待教师确认：___】`。AI 负责把事实摆整齐、把颜色标出来，
   **不负责替教师下判断**；色标只是提示位，不是结论。
3. **学生汇报稿的主体必须由学生自己完成**。
   派工产出的 pptx 是**骨架与参照**，不是学生的作业。
   必须在 pptx **首页和末页**、以及交付说明里写明「本文件为骨架，须由汇报学生自行重做主体内容」，
   并明确要求学生**自己重画图表**（不截图）、**自己组织论证链**。
   导师可给结构与提问，不能给学生的汇报内容 —— 这是训练，不是代做。
4. **文献不虚构**。派工的文献只能是教师实际指定的那篇；
   分析中作者、单位、年份、期刊、DOI 原文没有就标 `[未明确给出]`，
   绝不为了「看起来完整」补一个像样的期刊名。
5. **敏感数据本地处理**。学生姓名、学号、成绩、录音转写不出本机；
   spec/json/txt 中间文件含姓名，任务结束提醒删除；交付说明写明含个人信息。
6. **不覆盖教师提供的原始材料**。轮值表/进度表按新文件名另存，不要原地改教师的历史版本。
7. **不生成 Markdown 当交付物**（`CONVENTIONS.md` §2）。
   `.md` 只是中间稿，交付一律走 office-layer 出 docx/xlsx/pptx。
