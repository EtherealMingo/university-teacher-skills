# 质量门与错误规则

## 目录

- 问题模型

## 问题模型

`QG-ISSUE-001` 每个问题记录规则 ID、级别、栏目、块或路径、消息和建议动作。

`QG-ISSUE-002` 级别为 `blocked`、`needs-review` 或 `advisory`。

`QG-ISSUE-003` 存在 `blocked` 时不得进入下一状态。

## 内容门

`QG-CONTENT-001` 按语法、栏目、标题、十模块、事实、证据、对应关系、字数、语言、提示污染、项目专属规则顺序执行。

`QG-CONTENT-002` 缺失必需栏目、末级标题无正文、复杂栏目无论证单元或正文为空时阻断。

`QG-CONTENT-003` 事实冲突、计划伪装为结果、未知个人事实未占位时阻断。

`QG-CONTENT-004` 正文引用文献、数据、政策或他人观点但未使用 `[n]` 标识，或引用标识无对应已核实证据卡、主张超出来源范围时阻断。

`QG-CONTENT-005` 目标、方法、证据、验证和成果存在断点时阻断。

`QG-CONTENT-006` 检查段落碎片、重复、术语漂移、口语、空泛判断和机械连接；字数按正文“字数”（每个汉字 1 字、连续西文/数字串 1 字）统计。

`QG-CONTENT-007` 提示词原句、任务管理语言和聊天机器人残留时阻断。

## 字数与引用门

`QG-LENGTH-001` 限字检查以正文“字数”为准，不使用原始字符数：每个汉字计 1 字，连续西文单词或数字串计 1 字，标点、空白不计。

`QG-LENGTH-002` 实际字数低于规定字数，或超过规定字数的 110%，均为 `blocked`；达到规定字数且不超过 110% 才可通过。

`QG-CITE-001` 正文出现“已有研究表明、文献显示、数据显示、政策规定、调查发现”等引用性表述时，同段必须出现 `[n]` 数字引用标识，否则阻断。

`QG-CITE-002` `[n]` 标识必须能在证据卡中查到，证据卡 `verified=true` 且具有可定位来源；证据卡标记为已使用但正文未出现对应 `[n]` 时阻断。

## 推理合同门

`QG-REASON-001` `reasoning-plan.v1` 的栏目 ID 唯一、依赖存在且无环；中心命题必须有证据或显式未知项。

`QG-REASON-002` 高风险主张必须被独立核验覆盖；每栏问题不超过 3 个，全文不超过 20 个。

`QG-REASON-003` 定向修订次数不得超过一次；满足无阻断、无新增证据或质量不再改善任一条件时必须早停。

`QG-REASON-004` 推理台账不得包含自由形式内部思维链，只允许结构化计划、证据、核验结果、决策和状态。

## 预算与恢复门

`QG-BUDGET-001` 新外部操作开始前必须检查剩余机械预算；预算不足返回 `E_TIMEOUT`，不得启动后端。

`QG-BUDGET-002` `backend_attempts` 记录后端、文件、开始/结束时间、结果、耗时、剩余预算和熔断原因。

`QG-BUDGET-003` 超时、取消、构建失败、渲染失败和续跑失败不得修改原材料、留下用户目录半成品或遗留受控进程。

`QG-BUDGET-004` `recovery_checkpoints` 的成功项必须由文件哈希和产物哈希验证后才可复用。

## Prompt 十模块门

`QG-MODULE-001` 全文任务要求 M1–M10 全部 `complete`；单节任务要求目标模块及适用的 M8–M10。

`QG-MODULE-002` 每个完成模块必须记录输入修订、目标栏目、诊断和完成修订。

`QG-MODULE-003` M1 检查问题链、文献综合和双重价值。

`QG-MODULE-004` M2 检查任务关系、重点难点和可验证目标。

`QG-MODULE-005` M3 检查方法名实一致、操作、整合、技术路线和可行性。

`QG-MODULE-006` M4 检查缺口对应、不可替代性和夸大表达。

`QG-MODULE-007` M5 检查任务成果对应、可检验性、体量和使用路径。

`QG-MODULE-008` M6 检查成果关联、团队分工和资源来源。

`QG-MODULE-009` M7 检查四要素、信息密度、关键词和字数。

`QG-MODULE-010` M8 检查全文闭环、承诺交付和跨栏目一致性。

`QG-MODULE-011` M9 检查自然语言问题和实际修改日志。

`QG-MODULE-012` M10 检查六维证据化评分、严重度和修订路线。

## 一致性门

`QG-PARITY-001` 输入为冻结稿和暂存 DOCX，输出 `parity-report.v1`。

`QG-PARITY-002` 任一未允许差异阻断并删除暂存 DOCX。

## 结构门

`QG-STRUCT-001` 检查 DOCX ZIP、关系、页面尺寸和边距。

`QG-STRUCT-002` 检查允许样式、普通加粗标题、表格拓扑/列宽/合并、图片关系和占位样式。

`QG-STRUCT-003` 检查连续空段、孤立标题、Markdown 标记、边框、底纹和 Office 标题样式。

## 渲染门

`QG-RENDER-001` 每次使用独立 LibreOffice profile 把 DOCX 转 PDF，再转逐页 PNG。

`QG-RENDER-002` 机械检查页数大于零、文件非空、图片可读和尺寸合理。

`QG-RENDER-003` Agent 在 100% 缩放检查全部页面。

`QG-RENDER-004` 复核裁切、重叠、缺字、字体替换、破表、空白页和页眉页脚漂移。

`QG-RENDER-005` `render-review.v1` 必须匹配会话、冻结稿哈希、暂存 DOCX
哈希、总页数和全部页码；续跑还要重算模板、冻结稿、渲染报告及每张页面图哈希。

`QG-RENDER-006` 渲染器缺失不阻断交付：跳过机械渲染与视觉复核，交付结果记录 `render_gate=skipped` 与警告；只有显式调用渲染且渲染器缺失时才返回 `E_RENDERER_UNAVAILABLE`。

`render-review.v1.checks` 必须逐项记录
`cropping`、`overlap`、`missing_glyphs`、`font_substitution`、
`broken_tables`、`blank_pages`、`header_footer_drift`，全部取值为
`passed`；任何真实问题同时写入 `issues`，不得用缺省字段表示“已检查”。

## 风格门

`QG-STYLE-001` 内容门执行 `style-gate.v1`，检查 AI 套话、聊天残留、口水话、机械转承、句长节奏、严肃性和参考文案重合。

`QG-STYLE-002` 风格门只对新增正文生效；模板固定文字、官方说明和短字段不参与段落密度统计。

`QG-STYLE-003` 参考文案只用于生成 `style-profile.v1`；参考文案原文不得写入草稿、台账或交付目录。

## 错误与退出码

`QG-ERROR-001` 路径、限制、格式、抽取、模板、正文、冻结、构建、对齐、结构、渲染和交付使用稳定错误码。

`QG-ERROR-002` 错误包含阶段、路径/字段、恢复级别、是否需用户动作和建议。

`QG-ERROR-003` 退出码 0 表示成功或 Agent 可继续内部动作；2 表示输入/内容/质量阻断；3 表示环境不可用；4 表示内部不变量失败。

## 包结构门

`QG-PACKAGE-001` 五个参考文件和五个项目工作流存在且能从 `SKILL.md` 一层发现。

`QG-PACKAGE-002` 规则 ID 唯一，无孤立、深层或循环引用。

`QG-PACKAGE-003` 运行时包不包含原 Prompt 角色壳、复制说明、来源仓库、模型推荐、版本许可叙述、测试、PRD 或开发报告。

`QG-PACKAGE-004` `SKILL.md` 正文不超过 150 行，frontmatter 只有 `name` 和 `description`。

`QG-PACKAGE-005` 公共 CLI 不包含业务算法，只负责参数、兼容转换、核心调用和序列化。
