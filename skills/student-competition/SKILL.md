# 学生竞赛与双创项目指导（导师侧）

> **Goal**：教师带学生做大创/挑战杯/创青春/中国国际大学生创新大赛时，本技能负责**导师侧**的全链路：
> 引导学生自己想出选题 → 组队分工 → 交申报书正文给 `grant-proposal` → 过程督导 → 中期检查 →
> 结题 → 答辩演练。**AI 出的是导师工作用的草稿、模板、清单与演练预案，不替学生干活、不代写申报书。**

## 与 grant-proposal 的分工边界（先读这一节）

`grant-proposal` 也提到大创、挑战杯，但它走的是 awesome-benzi 的**申报书撰写**通道；
本技能走的是**导师带队**通道。两者不是替代关系，是交接关系。

| 场景 | 走哪个技能 | 理由 |
|---|---|---|
| 申报书正文从零到初稿、论证活页、选题查重、模拟评审 | `grant-proposal` | 它掌握 awesome-benzi 七阶段 + 十模块 + 质量门 |
| 学生想不出题目，怎么引导他自己收敛 | **本技能** | 这是教学行为，不是写作行为 |
| 谁当负责人、怎么防止搭便车 | **本技能** | 团队治理问题 |
| 申报书里「导师支持」怎么写、导师该补哪些内容 | **本技能**出清单 → `grant-proposal` 落笔 | 边界在此切开 |
| 中期报告怎么写、进度落后怎么答 | **本技能** | 过程管理 |
| 结题报告结构、成果认定、经费决算、票据 | **本技能** | 结题管理 |
| 路演 PPT 结构、评委追问演练 | **本技能** | 答辩训练 |
| 结题材料要成一份装订稿、要按模板排版 | 本技能出内容 → `vendor/office-layer/` 出文件 | 文件产出唯一通道 |

### 交接协议（双向，必须显式执行）

**本技能 → `grant-proposal`（申报书正文撰写）**

交接时**一次性递全**下面五项，缺项要在交接单里标 `【待补：…】`，不要口头带过：

1. **赛道与模板**：赛事名称 + 赛道（大创创新训练 / 创业训练 / 创业实践；挑战杯：自然科学类学术论文 / 哲学社会科学类社会调查报告 / 科技发明制作 / 创业计划；创青春分支；中国国际大学生创新大赛：高教主赛道 / 「青年红色筑梦之旅」赛道 / 产业命题赛道）+ 学校通知文件 + 申报书模板。
2. **选题定稿**：来自本技能阶段一的《选题评估表》，含选定题目、一句话问题陈述、五维评分。
3. **事实台账**：每名学生的**真实**已有基础（会什么、做过什么、手上有什么数据/原型/调研）。
4. **团队与分工**：来自阶段二的《分工责任矩阵》。
5. **导师支持边界**：实验室能提供什么设备/数据/场地、导师本人承诺投入什么、**明确不做什么**（这一条评委很爱追问）。

**`grant-proposal` → 本技能（回传）**

回传申报书初稿 + 质量门结果 + 它的模拟评审追问清单。本技能用这份追问清单**反向生成过程指导清单**
（哪几条追问意味着学生哪个环节基础不牢，就要在阶段四重点盯）。

**什么时候不该交接**：学生只想聊天、还没定赛道、还没有任何真实基础。此时先在阶段一把选题和事实台账做实，
交过去也只会被质量门的「事实不足」拦住。

## 何时使用

- 「我带了个学生团队做大创，从哪开始」「这几个孩子想不出题目，我怎么引导」
- 「挑战杯怎么带」「创青春 / 互联网+ 怎么报名、怎么准备」
- 「帮我看看学生的申报书」（→ 本技能先做导师侧体检，正文修订转 `grant-proposal`）
- 「学生中期检查进度落后了，怎么答」「结题报告怎么写」「结题经费决算怎么弄」
- 「帮我搭个路演 PPT 的架子」「评委一般会问什么」「模拟提问一下我这个学生」
- 「怎么分工才不出现搭便车的」

**不适用**：数学建模、电子设计、ACM、结构设计等**学科竞赛**（本技能不做）；教师本人的科研/教改项目申报（→ `grant-proposal`）；
毕业论文指导（→ `thesis-supervisor`）。

## 前置信息收集（intake，一次性问完）

按 `INPUT_MODEL.md` 的 `question-batch` 机制，把下面 8 条**合并成一次提问**，不要边做边问：

1. **竞赛类型与赛道**：大创（创新训练 / 创业训练 / 创业实践）、挑战杯（论文类 / 调查类 / 发明制作 / 创业计划）、创青春、中国国际大学生创新大赛（哪个赛道）。
2. **学生年级与专业**：年级决定可用时间（大二最充裕、大三要考研/实习、大四基本做不动）；专业决定技术可行性。
3. **团队规模与已有成员**：几人、是否已组好、是否跨专业。
4. **时间节点**：申报截止、立项公布、中期检查、结题验收、答辩——把这四个日期要到。
5. **学校要求**：学校通知文件、申报书模板、中期报告模板、结题材料清单、经费额度与报销规定（**必须要原件或学生手上的截图**）。
6. **已有基础**：学生会不会相关技术、有没有数据/原型/调研/合作单位、导师实验室能给什么。
7. **导师自身约束**：能投入多少时间、每周能见几次、能否提供经费/设备/数据。
8. **产出物格式**：要 Word 还是 PDF、要不要按学校模板套版、答辩 PPT 页数限制与时长限制。

**缺什么也不能缺赛道和学校模板**——这两样没有就先按通用结构做，并在每份产出物抬头标注
「结构为通用模板，请对照贵校通知调整」。其余缺项用安全默认值继续（默认团队 4 人、默认 3–5 人为一组、默认每周一次例会），
并在交付说明里逐条列出「本次用了哪些默认值」。

## 工作流

七个阶段。每阶段写明 **输入 → 动作 → 输出 → 退出条件**。**退出条件不满足就停在原地**，
不要带着没做完的事进入下一阶段（这是这类项目最常见的事故来源）。

---

### 阶段一 · 选题引导（学生自己找题，导师不给题）

**输入**：intake 全部信息 + 学生各自填的一份「经历与痛点清单」（见下）。

**动作**

1. **先让学生各写三句话**（不写这三句不谈选题）：
   - 我遇到过的一件让我觉得「这事不合理」的具体事（越具体越好，带时间场景）；
   - 我专业里老师反复讲、但现实里大家还在凑合用的做法；
   - 我在实习/兼职/志愿服务/家里见到的、有人真的为此花钱或花时间的麻烦。

2. **用苏格拉底提问把三句话收敛成问题**（`thinking-toolkit/methods/01-socratic-inquiry.md`）。
   导师只提问、不给答案，用下面这条提问链，**每轮只推进一步**：

   | 轮次 | 导师可以问的问题 | 目的 |
   |---|---|---|
   | 澄清 | 「你说的『不方便』具体指哪一步？谁在什么时候做这一步？」 | 把形容词换成动作 |
   | 证据 | 「这件事你怎么知道是普遍的？你问过几个人？」 | 逼出调研，而不是想象 |
   | 边界 | 「谁最痛？谁其实不在乎？」 | 收敛受益人群 |
   | 因果 | 「如果这一步去掉，会坏在哪？」 | 找到真实机制 |
   | 反例 | 「有没有人已经解决了？为什么没推广？」 | 提前撞上「别人做过」 |
   | 可行性 | 「用你现在的技能，两周内能做出什么最小的东西？」 | 落到学生能力边界 |
   | 归属 | 「这个题你为什么非做不可？」 | 找承诺度，也是答辩必问题 |

3. **填《选题评估表》**（xlsx，五维各 1–5 分，权重可调）：

   | 维度 | 判定问题 | 3 分以下的典型信号 |
   |---|---|---|
   | 可行性 | 学生现有技能 + 一学期 + 现有设备，做得完吗 | 需要导师实验室之外的重资产、需要审批资质 |
   | 创新性 | 与已有做法比，差异点能不能一句话说清 | 差异点只能说「效果更好」而说不出机制 |
   | 工作量 | 够撑起一个周期吗（太少不够结题，太多做不完） | 两周能干完，或换三个人也做不完 |
   | 团队匹配度 | 这个题需要的能力，队里现在有人会吗 | 关键技能全要现学，且无人带 |
   | 资源可得性 | 数据/场地/被试/合作单位/经费，现在拿到了吗 | 依赖「到时候应该能拿到」 |

   得分 ≥18 且无单项 ≤2 → 进入阶段二；否则**回上一轮继续提问**，不要靠导师硬压一个题下去。

```bash
PY="vendor/office-layer/.venv/bin/python"
$PY vendor/office-layer/scripts/xlsx_kit.py build \
    --spec 选题评估表.spec.json --out 选题评估表_初稿.xlsx
$PY vendor/office-layer/scripts/xlsx_kit.py inspect --in 选题评估表_初稿.xlsx
```

4. **写「为什么不能直接给题目」的说明**给学生看（导师口径统一，避免学生以为导师偷懒）：
   - **答辩时讲不出细节**。评委最擅长问「这个想法最初是谁提的、为什么这么定」，导师给的题学生答不上追问。
   - **承诺度不够**。学生自己收敛出来的题，遇到卡点会自己找路；导师给的题，卡住就等导师。
   - **选题能力本身就是培养目标**。大创叫「训练计划」，不是「代做计划」。
   - **归属风险**。导师给的题往往是导师课题的延伸，容易被看出「是老师的项目让学生署名」。
   - **结题时说不清贡献**。`student-innovation/WORKFLOW.md` 要求事实台账记录每名学生的真实贡献，无贡献可记就是事故。

**输出**：`选题候选清单.md`（每人至少 2 个候选 + 提问记录）、`选题评估表_初稿.xlsx`、
`选题定稿说明.md`（选定题目、一句话问题陈述、待验证项、**由学生自己写的**选择理由）。

**退出条件**：题目由学生提出并被学生自己论证过；评估表总分 ≥18；学生能不看稿回答「这个题你为什么非做不可」。
导师此处留位：`【待教师确认：是否同意以此题立项申报】`

### 阶段二 · 组队与分工

**输入**：选题定稿 + 学生名单（年级、专业、技能、每周可投入时间）。

**动作**

1. **定规模**：大创 3–5 人（创新训练 3–5，创业训练/创业实践可到 5–6）；挑战杯、创青春、中国国际大学生创新大赛 5–8 人且**建议跨专业**（技术 + 经管 + 设计/传媒）。少于 3 人扛不住工作量，多于 8 人一定有人浮着。

2. **配角色**（每人**必须**有一个可署名、可核查的交付物）：

   | 角色 | 职责 | 可核查交付物 |
   |---|---|---|
   | 项目负责人 | 统筹进度、对外联络、答辩主讲 | 进度表 + 答辩主稿 |
   | 技术/实现 | 原型、代码、实验、样品 | 可运行原型 + 测试记录 |
   | 数据/调研 | 问卷、访谈、抽样、数据分析 | 原始问卷/访谈记录 + 分析脚本 |
   | 文案/材料 | 申报书、中期/结题报告、图表 | 各阶段报告底稿 |
   | 财务/后勤 | 预算、发票、报销、物资 | 票据台账 + 决算表 |
   | 展示/答辩辅助 | 路演 PPT、演示视频、海报 | PPT 源文件 + 演示脚本 |

   一人可兼两角（小团队），但**技术**与**文案**不要都压在一个人身上。

3. **设计反搭便车机制**（三件事同时做，缺一必有人浮）：
   - **交付物实名制**：每项交付物写进矩阵，署名到人；
   - **里程碑到人**：每个里程碑下拆到人的任务，逾期自动进入例会第一项议题；
   - **贡献台账**：从第一天起记录「谁在哪天做了什么、产出在哪」，这是结题和答辩的唯一凭据（`student-innovation/WORKFLOW.md` 第 6 节明确要求）。
   - 补充：**轮值主持例会**（每人轮流当一次会议主持并写纪要），浮着的人当两次主持就藏不住了。

```bash
$PY vendor/office-layer/scripts/xlsx_kit.py build \
    --spec 分工责任矩阵.spec.json --out 分工责任矩阵.xlsx
```

规格片段（`build` 用，`header` + `rows` 两级即可）：

```json
{"sheets": [{"name": "分工责任矩阵",
  "header": ["任务/交付物", "负责人", "协作者", "截止", "验收标准", "证据形式"],
  "rows": [["需求调研问卷（≥120份有效）", "【待补：姓名】", "【待补：姓名】", "【待补：日期】", "有效回收率≥80%", "原始问卷文件"],
           ["原型 v1 可演示", "【待补：姓名】", "【待补：姓名】", "【待补：日期】", "现场演示无卡死", "录屏+代码仓库"]]}]}
```

4. **划清指导教师与团队的责任边界**（写成一页《导师支持边界说明》，交接给 `grant-proposal` 时会用到）：

   | 导师做 | 导师不做 |
   |---|---|
   | 提问、给方向、指出证据不足 | 替学生定题目、写正文 |
   | 提供实验室设备/数据/场地等**真实可核**的资源 | 承诺拿不到的资源 |
   | 定期检查、批注学生材料 | 替学生改写成稿 |
   | 联系合作单位、开介绍信 | 代办学生该跑的流程 |
   | 经费合规把关、提醒留票据 | 违规变通报销 |

**输出**：`分工责任矩阵.xlsx`、`导师支持边界说明.md`、`贡献台账模板.xlsx`、`里程碑计划.md`。

**退出条件**：每个人至少一项交付物；负责人已明确且本人同意；反搭便车三机制落地；
边界说明经学生确认（留 `【待教师确认：边界是否需调整】`）。

### 阶段三 · 申报书撰写（**本阶段只交接，不代写**）

**输入**：阶段一、二的产出 + 学校申报书模板 + 赛事通知。

**动作**

1. **先做导师侧体检**（本技能做，不写正文）：
   - 选题与赛道是否匹配（创业计划塞进创新训练是常见错配）；
   - 学生基础是否真实、可核查（有没有把导师实验室的工作写成学生完成）；
   - 工作量与周期是否相称（`student-innovation` M2/M8 检查项）；
   - 预算与任务是否逐项对应（每一笔钱要有对应任务）；
   - 是否出现 `EVIDENCE_MODEL.md` 禁止的写法（把「计划做」写成「已完成」）。
2. **出《申报书交接单》**，把「本技能 → `grant-proposal`」的五项材料一次递全。
3. **把正文撰写交给 `grant-proposal`**，并明确告诉它：这是**学生项目**，
   正文里的事实主体是学生，所有学生事实必须来自事实台账。
4. **导师需补的部分单列一页**（这是本技能唯一直接产出到申报书里的内容）：
   - 导师/团队已有的前期基础署名与归属（不得混淆师生贡献）；
   - 导师承诺提供的支持（设备、数据、场地、经费配套）——**只写能兑现的**；
   - 指导教师意见栏（措辞由导师定，AI 只出草稿，留 `【待教师确认：指导教师意见】`）。
5. 拿到 `grant-proposal` 回传的初稿后，**本技能反向用它的模拟评审追问清单生成阶段四的盯防清单**。

**输出**：`申报书交接单.md`、`导师补充内容清单.md`、`申报书导师意见_草稿.docx`、`申报前置体检报告.md`。

**退出条件**：五项材料齐全（缺项已标 `【待补：…】`）；正文撰写已正式交接给 `grant-proposal`；
学生已知晓「正文由自己写、AI 与导师只做批注和提问」。

### 阶段四 · 过程指导

**输入**：里程碑计划 + 贡献台账 + 分工责任矩阵。

**动作**

1. **定期检查机制（三档，按周期选或叠加）**：

   | 机制 | 频率 | 形式 | 硬要求 |
   |---|---|---|---|
   | 例会 | 每 1–2 周 | 30–45 分钟，学生轮值主持 | 每人事前提交一页进展，会上只谈卡点与决策 |
   | 书面周报 | 每周 | 一页，负责人汇总 | 数据/证据必须附文件路径，不接受「进展顺利」 |
   | 月度评审 | 每月 | 导师 + 学生，对照里程碑 | 逾期项进入下月第一议题，连续两月逾期触发团队调整 |

2. **阶段里程碑设计（以 12 个月大创周期为例，按实际周期等比缩放）**：

   | 里程碑 | 时点 | 可核查交付物 | 退出条件 |
   |---|---|---|---|
   | M1 选题定稿 | 第 1 月 | 选题评估表 + 定稿说明 | 五维 ≥18，无人为导师代定 |
   | M2 前期调研/预实验完成 | 第 3 月 | 原始调研记录或实验记录 | 有原始文件，能追溯到人 |
   | M3 原型/方案 v1 | 第 5 月 | 可演示原型或完整方案 | 能现场演示或逐条讲清 |
   | M4 中期材料 | 第 6 月 | 中期报告 + 答辩稿 | 见阶段五 |
   | M5 验证与迭代 | 第 9 月 | 测试/调研分析报告 | 指标与对照对象明确 |
   | M6 成果固化 | 第 11 月 | 论文/专利/软著/实物 + 结题报告 | 见阶段六 |
   | M7 结题验收 | 第 12 月 | 结题全套材料 | 全部质量门通过 |

3. **周报 / 月报模板**（用 office-layer 出成 Word，学生直接填）：

```bash
$PY vendor/office-layer/scripts/docx_kit.py md \
    --in 周报模板.md --out 团队周报模板.docx --title "团队周报"
```

周报固定六栏：`本周完成（附文件路径）` / `未完成项及原因` / `下周计划（到人）` /
`卡点与需要导师/学校支持的事` / `证据清单` / `本周工时与参与人`。
月报在周报基础上加：`里程碑对照（完成/逾期/取消）`、`预算使用情况`、`下月决策事项`。

4. **常见停滞原因与干预**（导师最需要的其实这张表）：

   | 停滞类型 | 表面说法 | 真实原因多半是 | 干预动作 |
   |---|---|---|---|
   | 技术卡壳 | 「这个做不出来」 | 目标定太大 / 没人会 / 环境搭不起来 | 要求拆成两周内可达的最小步骤；导师只给方向与资源，不代做；必要时换技术路线并写明理由 |
   | 团队矛盾 | 「他最近很忙」 | 贡献不均、署名争议、负责人不敢催 | 摊开贡献台账逐条对；重分交付物；署名规则提前书面确定 |
   | 经费问题 | 「钱不够/报不了」 | 预算与任务错配、票据不合规 | 对照预算表逐项核；票据不合规的**不接受变通**，走学校正规流程；缺口写进中期调整说明 |
   | 学生懈怠 | 「课太多」 | 项目与个人目标（考研/实习/就业）脱钩 | 把项目产出与他的个人目标挂钩（作品集、毕业论文选题、竞赛加分）；仍无意愿则调整分工或退出，别拖到结题 |
   | 调研做不动 | 「没人愿意填」 | 抽样与渠道没设计 | 要求先做 10 份预调研并复盘渠道，再铺开；导师可帮联系单位但不代发代填 |
   | 导师自己也忘了 | 例会中断两周 | 无固定节奏 | 例会固定到日历，学生轮值主持，导师缺席也要开 |

**输出**：`团队周报模板.docx`、`月报模板.docx`、`里程碑计划.md`、`贡献台账.xlsx`、
`阶段检查纪要.md`（每次例会一页）。

**退出条件**：连续两个周期（两周）例会未中断；贡献台账每人均有记录；
无「逾期超过一个里程碑且未上报」的事项。

### 阶段五 · 中期检查

**输入**：中期报告模板（学校要求）+ 里程碑进度 + 已有证据。

**动作**

1. **搭中期报告结构**（学校有模板就用学校模板，此为通用结构）：

   | 章节 | 写什么 | 不许写什么 |
   |---|---|---|
   | 一、项目概况 | 题目、赛道、团队、周期、指导教师 | 拔高的宏大叙事 |
   | 二、任务书对照 | 原计划任务逐条 ↔ 当前完成情况 | 含糊的「基本完成」 |
   | 三、已完成工作与证据 | 每项工作配原始证据（数据文件、调研记录、原型截图、测试记录） | 无证据的成果表述 |
   | 四、阶段性成果 | 论文/专利/软著/实物/调研报告的**当前真实状态** | 把「投稿中」写成「已发表」 |
   | 五、进度偏差分析 | 偏差多少、原因是什么、谁的责任（对事不对人） | 甩锅、模糊归因 |
   | 六、调整方案 | 调整后的任务、时间表、分工、预算 | 无条件承诺原计划全做完 |
   | 七、经费使用情况 | 已支出、待支出、票据情况 | 笼统的「使用正常」 |
   | 八、下一步计划 | 到人的时间表 | 空话 |

2. **答辩准备**（中期答辩照阶段七的流程走一遍，PPT 压到 8–10 页）。
3. **重点练「进度落后」的质询应答**——这是中期答辩最高频、最容易翻车的追问。教学生用**四段式**，不许撒谎、不许打太极：

   > ① 如实说当前真实进度（给出数字：原计划 N 项，完成 M 项）
   > ② 说清原因，且**原因要可核**（不是「课程太忙」，而是「问卷渠道只覆盖了本院，跨院渠道 5 月才打通」）
   > ③ 给出调整后的**新时间表**（具体到周、到人）
   > ④ 说明调整后仍能保证的**必保成果**与**可以让步的成果**（分清底线与可选项）

   导师演练时扮演三种评委：**追问细节型**（「你说渠道打通了，谁签的字」）、
   **质疑能力型**（「你们还会不会做」）、**给台阶型**（「要不要缩小范围」）。
   第三种最容易让学生松口把所有成果都砍掉——要教学生回答「范围可以缩，但 X 这个核心验证不缩」。

**输出**：`中期报告_初稿.docx`（含 `【待补：…】` 占位）、`中期答辩PPT.pptx`、`进度落后应答卡.md`。

**退出条件**：任务书逐条有对照；每条成果都有证据或明确标为「未完成」；
进度偏差已量化并给出调整方案；学生能不看稿完成四段式应答。

```bash
$PY vendor/office-layer/scripts/docx_kit.py md \
    --in 中期报告_初稿.md --out 中期报告_初稿.docx --title "中期检查报告"
# 导师在初稿上写原生批注后回给学生
$PY vendor/office-layer/scripts/docx_kit.py comment \
    --in 中期报告_初稿.docx --out 中期报告_导师批注.docx \
    --comments 中期批注.json --author "指导教师"
$PY vendor/office-layer/scripts/docx_kit.py inspect --in 中期报告_导师批注.docx
```

批注 JSON（`anchor` 必须与正文逐字一致，含标点，否则退出码 2）：

```json
[{"anchor": "完成情况基本符合预期",
  "text": "「基本符合」请改成具体数字：原计划 4 项，完成几项？未完成的是哪项、卡在哪一步？"},
 {"anchor": "下一步将加快推进",
  "text": "「加快推进」不可核查。请写到周、到人：谁在几月几日前交出什么？"}]
```

### 阶段六 · 结题

**输入**：结题通知与材料清单（学校原件）+ 全部过程材料 + 成果实物/凭证。

**动作**

1. **搭结题报告结构**：

   一、项目基本信息（题目、编号 `【待补：项目编号】`、赛道、团队、周期、指导教师）
   二、任务书完成情况对照表（原定任务 ↔ 完成情况 ↔ 证据 ↔ 偏差说明）
   三、研究工作与技术路线（实际走的路线，包括走过的弯路——写弯路不丢分，显得真实）
   四、核心成果与创新点（**一条成果一条证据**）
   五、成果应用与育人成效（学生获得了什么能力、有几个人因此改变了去向，能举实例就举）
   六、经费决算（见第 3 点）
   七、存在的问题与未完成事项（如实写）
   八、下一步计划

2. **成果认定表**（每种成果的认定口径不同，别混着写）：

   | 成果类型 | 需要留存的证据 | 结题时常见坑 |
   |---|---|---|
   | 论文 | 录用/发表页、DOI 或期刊页、**项目资助标注页** | 未标注基金项目编号 → 不能算本项目成果 |
   | 专利 | 受理通知书或授权证书、申请号 | 把「准备申请」写成「已申请」 |
   | 软著 | 登记证书、登记号 | 申请人排序与实际贡献不符 |
   | 实物/原型 | 实物照片、演示视频、测试记录、代码仓库 | 只有 PPT 截图，无测试记录 |
   | 调研报告 | 原始问卷、访谈录音/记录、抽样说明 | 只给分析后结论，原始材料缺失 |
   | 获奖 | 获奖证书、赛事名称与级别 | **未获奖就写未获奖，绝不虚构** |

```bash
$PY vendor/office-layer/scripts/xlsx_kit.py build \
    --spec 成果认定清单.spec.json --out 成果认定清单.xlsx
```

3. **经费决算与票据**（导师必须把住这一关）：
   - 逐笔列：日期、事由、金额、对应任务、票据编号、报销状态；
   - **每一笔支出必须对应立项书里的一条任务**，对不上就单独说明；
   - 票据要求：正规发票/收据、抬头与项目一致、无涂改；**打车票、餐费、无明细的「办公用品」通常不能报**；
   - 结余资金按学校规定处理，不得自行挪作他用；
   - 提醒学生：**从第一笔支出起就建票据台账、当月清**，绝不允许「先垫着、年底补票」。

```bash
$PY vendor/office-layer/scripts/xlsx_kit.py build \
    --spec 经费决算表.spec.json --out 经费决算表.xlsx
```

4. **结题答辩**：照阶段七流程，PPT 压到 10–12 页，重点练「未达标怎么答」。
5. **未达标时的如实说明（标准口径，教学生背下来）**：

   > 「原定 A、B、C 三项任务，A 和 B 完成，C 未完成。原因是 ___（可核事实）。我们已把 C 做到 ___ 程度，
   > 现有材料是 ___。这是我们的判断失误：立项时低估了 ___。本次真正扎实的收获是 ___，
   > 后续计划是 ___（或在毕业论文/下一届团队中继续）。」

   **红线**：不许用「基本完成」「拟于近期完成」模糊过去，不许拿无关成果顶替，
   不许临时补做假数据。未达标如实说明只影响评优，**造假影响的是学生的学术诚信记录**。

**输出**：`结题报告_初稿.docx`、`成果认定清单.xlsx`、`经费决算表.xlsx`、`结题答辩PPT.pptx`、`未达标说明口径.md`。

**退出条件**：任务书逐条有对照（含未完成项）；每项成果有证据且口径正确；
经费逐笔可核、票据合规、无变通操作；结题答辩演练过至少一遍。

### 阶段七 · 答辩指导（路演 / 中期 / 结题通用）

**输入**：赛道规则（页数上限、时长）+ 项目材料 + 证据文件。

**动作**

1. **路演 PPT 结构**（大创结题 10–12 页；挑战杯/中国国际大学生创新大赛路演 12–15 页，按规则裁剪）：

   | 页 | 内容 | 硬要求 |
   |---|---|---|
   | 1 | 封面：项目名、赛道、团队、指导教师、日期 | 项目名不要玄学，要看得懂 |
   | 2 | 问题：谁在什么时候遇到什么麻烦 | 一页一个具体场景，不要行业大背景 |
   | 3 | 需求证据：调研/访谈数据 | **必须标样本量与时间**，无证据就写待验证 |
   | 4 | 现有做法为什么不灵 | 至少一个真实对比对象 |
   | 5 | 我们的方案（一张原理图/流程图） | 图要能自解释，不要满屏字 |
   | 6 | 原型 / 实物 / 演示 | 实拍图或录屏截帧，不用网图 |
   | 7 | 验证结果：指标 + 对照 | 指标给条件（在什么条件下测的） |
   | 8 | 创新点（2–3 条，每条一句） | 每条能指向第 7 页的某个数据 |
   | 9 | 应用/落地路径与边界 | 说清做不到什么，反而加分 |
   | 10 | 团队与分工 | 对应《分工责任矩阵》 |
   | 11 | 进度与下一步 | 时间表到月 |
   | 12 | 经费与致谢 | 决算口径与结题报告一致 |

$PY vendor/office-layer/scripts/pptx_kit.py build \

$PY vendor/office-layer/scripts/pptx_kit.py notes \

{"meta": {"title": "【待补：项目名称】", "subtitle": "中国国际大学生创新大赛·高教主赛道", "presenter": "【待补：负责人】"},

   {"title": "问题：谁在什么时候遇到什么麻烦",

   {"title": "验证结果",
    "table": {"header": ["指标", "我们的方案", "对照方案", "测试条件"],
              "rows": [["【待补】", "【待补】", "【待补】", "【待补：样本量/环境/时间】"]]},

`inspect` 会把单页正文 >220 字符的页面报进 `overdense` —— 这是提示拆页，路演页尤其要拆。

2. **评委常见提问与应答要点**：

   | 高频问题 | 应答要点 | 千万不要 |
   |---|---|---|
   | 这个想法最初是谁提的？ | 直说是谁、在哪次讨论提出的，附当时记录 | 含糊说「团队共同」 |
   | 和已有的 X 比，差在哪？ | 给一个真实对比对象 + 一个可测差异 | 说「我们效果更好」却说不出测法 |
   | 数据怎么来的？样本多少？ | 说清抽样方式、样本量、时间、渠道 | 临时报一个数 |
   | 你们几个人分别做了什么？ | 逐人对应交付物与证据 | 说「大家一起做的」 |
   | 指导老师在其中起了什么作用？ | 说清导师提供的真实资源与指导方式 | 把导师工作说成学生做的，或反过来 |
   | 这件事商业上怎么持续？ | 说清成本结构与收入来源，或直说是公益/研究性质 | 编用户量、订单、收入 |
   | 下一步怎么办？ | 给到月的时间表 | 「继续完善」 |
   | 这个项目最大的困难是什么？ | 讲一个真实困难 + 怎么解决的 | 说「没有困难」 |
   | 如果给你一年时间你会改什么？ | 说一个具体的设计改动 | 泛泛说「做得更完善」 |
   | 你们这个能推广到别的地方吗？ | 说清前提条件与边界 | 拍胸脯说「全国都能用」 |

3. **答辩礼仪与时间控制**：
   - 主讲人固定一人，其他人负责被点名追问（分工写在 PPT 讲稿备注里）；
   - 提前实测：**按 1.2 倍语速排练**，把超时页删掉，而不是临场加速；
   - 每页停留时间写进讲稿备注，卡点页（问题页、验证页）留最多时间；
   - 着装整洁、站立位置不挡屏幕、翻页器提前试、演示留离线录屏兜底（现场网络不可靠）；
   - 回答追问时先复述问题再作答，避免答偏；
   - 不会的问题直接说「这一点我们还没验证，是下一步要做的」——**这比编答案安全得多**。

4. **常见失分点清单**（答辩前逐条自查）：

   - [ ] 满页文字、字号小于 18pt、评委看不清
   - [ ] 数据无来源、无样本量、无时间
   - [ ] 把计划说成已完成（`EVIDENCE_MODEL.md` 明令禁止）
   - [ ] 创新点说不清与现有方案的差异
   - [ ] 团队分工答不出、有人明显没参与
   - [ ] 超时被打断（最常见，也最冤）
   - [ ] 用网图/无授权素材，被问版权
   - [ ] 导师越位主讲（学生项目应由学生主讲）
   - [ ] 未来时态与完成时态混用
   - [ ] 未准备任何失败/困难类问题的答案

**输出**：`路演PPT.pptx`（+ 含备注版）、`逐页讲稿.md`、`评委提问应答卡.md`、`超时风险检查表.md`。

**退出条件**：页数与时长达标（实测排练过一遍）；每页有讲稿备注；
十类高频问题学生都能不看稿回答；演示有离线兜底；失分点清单逐项过完。

## 红线

1. **不虚构学生成果、获奖、数据、调研结果、订单、收入、专利状态、合作单位。**
   这是学生的学术诚信问题，后果由学生承担且不可逆。所有未知一律 `【待补：…】` 占位，
   宁可交一份带占位的草稿，也不交一份漂亮的假材料。
2. **导师不得代做。** 本技能帮导师**指导**学生：出模板、出清单、出提问、出演练预案、写批注。
   **不替学生写申报书正文、中期报告正文、结题报告正文，不做项目本身**（不代写代码、不代跑数据、
   不代做调研、不代做 PPT 内容）。学生自己写得糙但真实，胜过导师润色得漂亮却讲不出。
3. **不得鼓励学生为获奖而编造数据或抄袭。** 不美化未完成项、不用无关成果顶替、
   不用「基本完成」掩盖未达标、不代学生应付中期/结题质询。
4. **学生个人信息（姓名、学号、联系方式、成绩）本地处理**：只在本机使用，不上传、不外发；
   交付物里如需出现姓名，用「负责人 / 成员 A」或学生本人同意的署名方式；
   中间文件任务结束后提醒教师删除；交付说明写明「本文件含学生个人信息，请注意保管」。
5. **经费使用需合规。** 提示学生**从第一笔支出起留存票据**、当月清、每笔对应立项任务；
   票据不合规时走学校正规流程，**不做任何变通**，不提供规避报销规定的写法。
6. **不引具体政策条款号**，只写「按学校/学院相关规定」，并提示教师核对当年通知与模板。
7. **评价性内容留人工确认位**：是否立项、是否通过中期、是否同意结题、评优推荐、
   导师意见措辞，一律留 `【待教师确认：…】`。AI 与学生都不给终稿判断。
