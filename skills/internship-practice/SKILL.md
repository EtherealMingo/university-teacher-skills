# 实习实训与实践教学

> **Goal**：把「联系基地 → 签协议 → 排学生 → 跑现场 → 写记录 → 评成绩 → 归档」这条三方长链路，
> 拆成可逐步交付的材料与清单。AI 出草稿、出表格、出检查清单；
> **安全责任、协议责任、评价结论一律由教师与院系确认，AI 不给终稿。**

## 何时使用

- 「帮我联系实习基地」「给这家企业写个洽谈邮件」
- 「这个单位能不能接收学生，要查什么」
- 「校企合作协议怎么写 / 协议要包含哪些内容」
- 「实习方案 / 实习大纲 / 实习指导书怎么做」
- 「排实习安排表，学生分到各单位的表」
- 「实习前安全教育讲什么」「安全承诺书模板」「应急预案怎么写」
- 「今天去企业看了学生，指导记录怎么写」
- 「实习周报怎么批」「学生不适应企业怎么办」
- 「实习成绩怎么算」「鉴定表怎么填、怎么盖章」
- 「实习总结报告怎么写」「实习材料要归档哪些」

**不适用**：课程内实验/实训的教案设计（走 `lesson-plan`）、毕业设计论文指导（走 `thesis-supervisor`）、
企业横向项目合作洽谈（不在本技能范围）。

> 本技能覆盖**认识实习 / 生产实习（含顶岗） / 毕业实习**三种类型，差异见阶段三的对照表。

## 前置信息收集（intake，一次性问完）

按 `vendor/awesome-benzi/references/INPUT_MODEL.md` 的 `question-batch` 机制，
**把下面 7 项合并成一次提问，不要边做边问**：

1. **专业与年级**：专业名称、学生年级、层次（本科/专科/研究生）
2. **实习类型与周数**：认识实习 / 生产实习 / 毕业实习；总周数、起止时间、是否集中安排
3. **学生人数**：总人数、是否有特殊学生（身体条件、涉外、需要就近安排等），**只问人数与约束，不要学生名单细节**
4. **已有基地情况**：现有合作单位名单、往年合作记录、今年需不需要新开发基地、单位接收上限
5. **学校规定与模板**：本校实习管理规定文件名、协议书模板、鉴定表模板、成绩单格式（**有就给，没有就按通用结构并标注**）
6. **时间节点**：动员会日期、进企业日期、中期检查日期、报告提交截止、成绩录入截止、归档截止
7. **安全特殊要求**：是否涉及高危岗位（电气、机械、化工、高空、野外、医疗、涉密），
   是否已有统一购买的实习责任保险，本校应急报告流程与联系人

**信息不全时不停下干等**，按下列安全默认值继续，并在每份产出物顶部标注用了默认值：

| 缺失项 | 安全默认值 |
|---|---|
| 学校模板 | 用本技能通用结构，交付物注明「结构为通用模板，请对照本校规定调整」 |
| 安全特殊要求 | **一律按「有高危因素」处理**：加安全培训签到、加应急演练、加保险核对清单 |
| 评价权重 | 用 40/30/30 默认权重，并在成绩表上留 `【待教师确认：各项权重】` |
| 时间节点 | 按常见学期节奏给草案，所有日期写成 `【待补：日期】` |

### 阶段一 · 实习基地联系与资质核查

**输入**：专业名称、岗位方向、单位接收上限、往年合作名单
**动作**：

1. **基地资质核查清单**（AI 出清单，**核查动作由教师/院系完成**）：

| 核查项 | 要拿到的东西 | 判断要点 | 状态 |
|---|---|---|---|
| 合法经营 | 营业执照（经营范围页） | 在有效期内；经营范围覆盖拟实习岗位 | 【待教师确认：已核验】 |
| 专业匹配 | 单位主营说明、岗位说明书 | 岗位内容能对应培养方案的能力指标，不是纯体力或纯打杂 | 【待教师确认：匹配度】 |
| 安全生产条件 | 安全管理制度、近三年事故情况、现场安全防护 | 高危岗位须有资质与培训记录；不确定的一律降级处理 | 【待教师确认：结论】 |
| 接收能力 | 可提供岗位数、可容纳学生数、住宿与通勤条件 | 换算成**明确的接收上限数字**给安排表用 | 【待补：上限人数】 |
| 指导力量 | 拟任企业导师的人选与岗位 | 一名企业导师带几名学生要有上限，不搞「一个师傅带二十个」 | 【待补：师徒比】 |
| 权责场所 | 是否有固定办公/操作场地、能否签收材料与盖章 | 涉及盖章的鉴定表必须确认由谁签、盖什么章 | 【待补】 |

> 涉及资质核验、消防与安全生产的最终判断，**以本校实习管理规定和当地主管部门要求为准**。
> AI 不引具体法规条款号，也不替院系下「这家单位合格」的结论。

2. **联系函 / 洽谈邮件**（用 `docx_kit.py md` 出正式函，邮件正文走同一份草稿的简版）：

结构固定为五段：① 自我介绍与来意（学校、学院、专业、年级）；② 合作意向与拟安排岗位、
人数、时段；③ 我方承担的责任（指导教师、安全教育、保险、纪律管理）；④ 需贵方确认的事项
（接收上限、企业导师人选、能否签署协议与盖章）；⑤ 联系方式与回复时限。

**必须留白的地方**：单位全称、联系人姓名职务、电话、地址一律 `【待补：…】`，**不得由 AI 编造**。

```bash
$PY vendor/office-layer/scripts/docx_kit.py md --in 基地联系函.md --out 基地联系函.docx --title "实习基地联系函"
$PY vendor/office-layer/scripts/docx_kit.py inspect --in 基地联系函.docx
```

**输出**：`基地资质核查清单.md`、`基地联系函.docx`、`基地候选单位清单.xlsx`
**退出条件**：每个候选单位都有明确的「已核验 / 待核验 / 不推荐」状态，且接收上限是具体数字

### 阶段二 · 校企合作协议要素核对（法务前置）

**输入**：学校协议书模板（若无则用通用要素表）、阶段一的单位信息
**动作**：出一份**协议要素核对表**，逐条对照学校模板查缺，而不是自己造一份协议文本。

| 要素 | 具体要写清什么 | 常见缺口 |
|---|---|---|
| 合作内容 | 实习类型、岗位方向、人数、起止时间 | 只写「合作育人」，无具体岗位与人数 |
| 双方权责 | 学校负责教育管理与指导教师；单位负责岗位、场地、企业导师与劳动保护 | 权责不对等，单位义务写得含糊 |
| 学生管理 | 考勤、请假、作息、纪律、宿舍与通勤责任方 | 谁管考勤、谁管请假没写 |
| **安全责任** | 上岗前安全培训、劳动保护用品、高危岗位限制、事故报告与处置分工 | 最常见缺口：只写「注意安全」 |
| 保险 | 由谁投保、险种、保额、覆盖时段 | 保额与时段空白 |
| 保密条款 | 商业秘密、涉密岗位的学生保密义务与期限 | 涉密岗位没有单独条款 |
| 知识产权 | 实习期间产生的成果归属 | 完全没写 |
| 指导教师安排 | 双方指导教师数量、职责、联系与到位频次 | 无企业导师指定机制 |
| 期限与续签 | 协议有效期、终止条件、续签方式 | 无期限，长期挂空 |
| 争议解决 | 争议处理方式与管辖 | 空白 |

**铁律**：协议涉及法律责任，**必须经学校法务 / 教务或主管部门审核，不得直接使用本技能生成的文本签署**。
本技能的产出是「要素核对表 + 缺口清单」，不是可签文本。

**输出**：`校企合作协议要素核对表.xlsx`（要素 × 校模板 × 缺口 × 建议动作）
**退出条件**：缺口清单每一条都写明了「需向单位还是向本校哪个部门确认」

### 阶段三 · 实习方案与实习大纲设计

**输入**：培养方案（能力指标部分）、实习类型与周数、单位岗位信息、阶段一二结论
**动作**：

1. **实习目标对回培养方案**——每个目标必须挂到一个具体能力指标，指标编号无依据就留占位：

| 实习目标 | 对应培养方案能力指标 | 可观测的达成证据 |
|---|---|---|
| 能独立完成【待补：岗位典型任务】 | 【待补：指标编号与原文】 | 岗位任务记录、企业导师确认 |
| 能读懂并遵守企业工艺/作业规程 | 【待补：指标编号与原文】 | 安全培训记录、周报记录 |
| 能对岗位问题做初步分析并提出改进建议 | 【待补：指标编号与原文】 | 实习报告中的问题分析章节 |

2. **三种实习类型的差异**（照此定内容与时间分配，不混用）：

| 维度 | 认识实习 | 生产实习（含顶岗） | 毕业实习 |
|---|---|---|---|
| 主要目的 | 建立专业感性认识、了解行业与岗位 | 在真实岗位承担具体任务、形成职业能力 | 综合运用专业知识解决实际问题，衔接毕业设计/就业 |
| 典型时长 | 1–2 周（集中） | 4–12 周（集中或分段） | 8–16 周（多在最后一学年） |
| 岗位轮换 | 以参观、讲座、跟岗观察为主，可多岗走看 | **应有轮换或递进**：由辅助岗到独立岗 | 以固定岗位深入为主，可结合选题 |
| 学生独立操作 | 一般不独立操作 | 在师傅指导下逐步独立 | 独立承担任务并交付成果 |
| 考核重心 | 认识报告、参观记录 | 岗位任务完成度、职业素养、企业评价 | 综合报告、问题解决能力、企业评价 |
| 安全等级 | 以现场安全告知为主 | 需完整安全教育 + 岗位安全培训 | 同生产实习，另加毕业设计相关安全 |

3. **校企双导师分工表**：

| 环节 | 校内导师职责 | 企业导师职责 |
|---|---|---|
| 实习前 | 动员、安全教育、协议与保险核对、岗位匹配 | 岗位与人选确认、安全培训计划、上岗条件说明 |
| 实习中 | 现场巡视、周报批阅、思想与心理疏导、考勤监督 | 日常任务派工、操作指导、考勤与表现记录 |
| 实习后 | 报告评阅、成绩汇总、鉴定表审核、归档 | 填写企业评价、鉴定表签署与盖章 |

4. **实习大纲结构**（固定 8 节，缺一节即为不完整）：
① 实习性质与在培养方案中的位置；② 实习目标（对应能力指标）；③ 实习内容与岗位要求；
④ 时间安排与周次分配；⑤ 实习方式与地点；⑥ 考核方式与成绩构成；⑦ 纪律与安全要求；
⑧ 参考资料与附录模板。**实习指导书**在大纲基础上加：每日/每周任务清单、记录表模板、
报告撰写要求与格式、常见问题问答。

**输出**：`实习方案.docx`、`实习大纲.docx`、`实习指导书.docx`、`校企双导师分工表.xlsx`
**退出条件**：每个实习目标都有对应能力指标与可观测证据；时间分配总和等于实际实习周数

### 阶段四 · 实习安排表

**输入**：学生名单（本地文件）、单位接收上限、学生意愿、地域、安全约束
**动作**：

1. **分配原则**（按优先级，冲突时按此顺序裁定）：

| 优先级 | 原则 | 落地做法 |
|---|---|---|
| 1 | **安全与合规** | 高危岗位人数不得超上限；身体条件受限学生不得安排到不适岗位；涉密岗位需单位书面同意 |
| 2 | 专业匹配 | 岗位内容对应培养方案指标；匹配度低的单位降为备选 |
| 3 | 单位接收上限 | 严格不超上限，超限即换单位，不搞「先塞进去再说」 |
| 4 | 学生意愿 | 在满足前三条的前提下，按志愿顺序满足 |
| 5 | 地域与通勤 | 就近优先，减少长途与夜间通勤 |
| 6 | 均衡 | 各单位学生水平、男女比例适度均衡，便于管理 |

2. **生成安排表**（走 `xlsx_kit.py build`）：

```bash
$PY vendor/office-layer/scripts/xlsx_kit.py build --spec 安排表规格.json --out 实习安排表.xlsx
$PY vendor/office-layer/scripts/xlsx_kit.py inspect --in 实习安排表.xlsx
```

`安排表规格.json` 规格片段：

```json
{"sheets": [
  {"name": "实习安排表",
   "header": ["序号","学号","姓名","专业","实习单位","岗位","起止时间","校内导师","企业导师","单位联系人及电话","住宿安排","已签承诺书","保险费凭证号","备注"],
   "rows": [[1,"【待补：学号】","【待补：姓名】","【待补：专业】","【待补：单位全称】","【待补：岗位】","【待补：起止时间】","【待补：校内导师】","【待补：企业导师】","【待补：联系人及电话】","【待补】","是/否","【待补】",""]],
   "widths": [6,14,10,16,26,16,24,12,12,22,16,12,16,20]},
  {"name": "单位汇总",
   "header": ["实习单位","接收上限","已分配人数","剩余名额","企业导师人数","师徒比","状态"],
   "rows": [["【待补：单位全称】","【待补：上限】","【待补：人数】","【待补】","【待补】","【待补】","【待确认】"]]}
]}
```

`单位汇总` 表用来当场验算「已分配 ≤ 接收上限」，**这是排表最容易翻车的地方**。

3. **一表三用**：同一份安排表另存为「学生版」（无学号、无身份证、只留导师联系方式）
和「院系报备版」（含全部字段），用 sheet 或另存区分，避免把含个人信息的表直接群发。

**输出**：`实习安排表.xlsx`（含单位汇总与校验列）、`实习安排表_学生版.xlsx`
**退出条件**：`已分配人数 ≤ 接收上限` 全部成立；每名学生都有校内导师与企业导师；无空岗空人

### 阶段五 · 安全管理（最高优先级）

> **本节所有内容都是「AI 出清单与草稿、教师与院系做确认」**。
> 安全相关事项**必须人工确认**，AI **不得**输出「已确保安全」之类的结论性表述。

**输入**：实习类型、岗位风险、学校安全规定、保险方案、应急流程
**动作**：

不得擅自离岗、不得失联）；③ 岗位安全操作规程与劳动保护用品；④ 交通与住宿安全；
⑤ 请假与报告流程；⑥ 应急报告流程与电话；⑦ 学生权利义务与申诉渠道；⑧ 保密与职业操守。

3. **保险购买核对**（AI 只出核对清单，投保动作由学校办理）：
被保险人为**每名学生本人**、覆盖**全部实习时段（含往返途中）**、险种与保额符合本校规定、
保单号与凭证已归档、**已建立「学生 → 保单号」的对照关系**、中途新增/变更学生的补保流程已明确。

### 阶段六 · 实习指导记录

**输入**：现场走访事实（教师口述或笔记）、学生周报、线上沟通记录
**动作**：

1. **现场指导记录**（一份一次，走 `docx_kit.py md`）：

```bash
$PY vendor/office-layer/scripts/docx_kit.py md --in 指导记录.md --out 实习指导记录.docx --title "实习指导记录"
$PY vendor/office-layer/scripts/docx_kit.py inspect --in 实习指导记录.docx
```

结构固定七要素：**时间 / 地点 / 参与学生 / 指导内容 / 发现问题 / 处理结果 / 后续跟进**。
模板要点：

| 字段 | 填写要求 |
|---|---|
| 时间 | 具体到上午/下午与起止时刻 |
| 地点 | 单位全称 + 具体车间/部门/办公地点 |
| 参与学生 | 姓名（脱敏版可写学号后四位）+ 实到/应到人数 |
| 指导内容 | 看了什么岗位、查了什么记录、与学生和师傅谈了什么 |
| 发现问题 | **只写观察到的事实**，不写推断；如「3 名学生未佩戴防护手套」 |
| 处理结果 | 当场如何处置、谁配合处置、是否已整改 |
| 后续跟进 | 何时复查、复查什么、责任人 |

> 记录里**不得**出现「一切正常」「学生表现良好」这类无事实支撑的结论；
> 有问题就写问题，没问题也要写清依据（查了哪几项、问了几个人）。

2. **线上指导与周报批阅**：用 `docx_kit.py comment` 写 Word 原生批注，
学生打开就是批注气泡，可读可回：

```bash
$PY vendor/office-layer/scripts/docx_kit.py comment \
    --in 学生周报.docx --out 学生周报_批注.docx \
    --comments 批注.json --author "校内指导教师"
$PY vendor/office-layer/scripts/docx_kit.py inspect --in 学生周报_批注.docx
```

`批注.json`（`anchor` 必须是原文逐字片段，含标点；锚点未命中会进 `failed` 且退出码为 2，
**必须逐条修正锚点，不要忽略非零退出码**）：

```json
[{"anchor": "本周主要在车间熟悉设备",
  "text": "请补充具体设备名称、本周累计操作的次数，以及师傅带你完成了哪一项独立任务。"},
 {"anchor": "感觉自己还有很多不足",
  "text": "请把「不足」写成可核查的一条：是操作规程不熟、还是某个工具不会用？写清后我下周现场时针对性看。"}]
```

周报批阅的固定四问：① 本周具体做了什么（可核查的任务与工作量）；② 遇到什么问题、怎么解决的；
③ 安全与纪律是否合规；④ 下周计划是否对应实习大纲要求。

3. **常见问题处置**（先保安全、再保合规、再谈教学效果；**一律留痕**）：

| 问题 | 处置要点 | 必须留的记录 |
|---|---|---|
| 学生不适应（岗位枯燥、想换岗） | 先听诉求、查岗位是否偏离大纲；能在单位内部调岗的优先内部调，不在未获批准前擅自换单位 | 谈话记录、调岗申请与审批单、更新后的安排表 |
| 企业临时变卦（撤销岗位/减产/换人） | 立即暂停上岗并集中安置，评估同单位转岗或启用备选单位；同步核对保险与安全材料 | 单位书面通知或沟通记录、安置方案、学生知情同意记录 |
| 学生擅自离岗 / 失联 | **立即联系本人与家长、报告院系**，必要时报警；不得替学生隐瞒，不得事后补记考勤 | 联系时间线、报告记录、考勤原始记录、处理意见 |
| 三方矛盾（学生对单位、单位对学生、家长介入） | 分别听取三方陈述、以协议与校规为依据界定责任、做成书面结论；超出权限的上交院系 | 三方陈述、协调纪要、结论与签字 |
| 岗位内容与约定不符（打杂、加班超时） | 现场核实、以协议与大纲为依据向单位提出整改；不整改的启动转岗或转移单位 | 现场核查记录、整改函、单位回复 |
| 学生提出提前结束实习 | 核清原因、评估是否影响毕业要求、按校规走审批；不得口头同意 | 申请单、审批意见、后续补实习方案 |

**输出**：`实习指导记录.docx`（每次一份）、`学生周报_批注.docx`、`问题处置记录.docx`
**退出条件**：每次现场指导都有记录且七要素齐全；每个问题都有对应的处理结果与跟进人

### 阶段七 · 考核与鉴定

**输入**：企业评价（单位填写或盖章）、学生实习报告、校内导师评价、考勤与周报记录
**动作**：

1. **成绩构成**（默认权重，**须经教师与院系确认后方可执行**）：

| 评价来源 | 默认权重 | 主要内容 | 依据材料 |
|---|---|---|---|
| 企业评价 | 40% | 岗位任务完成度、职业素养、纪律与安全、协作能力 | 企业评价表、考勤记录 |
| 实习报告 | 30% | 内容真实性、专业深度、问题分析、规范性 | 学生实习报告 |
| 校内导师评价 | 30% | 周报质量、现场表现、纪律、实习目标达成度 | 周报批注、指导记录 |

> 权重以本校实习管理规定为准。上表仅为默认值，成绩表首行必须写
> `【待教师确认：各项权重 ____ / ____ / ____】`。

2. **实习报告评分标准**（五维，按 `competency-based-assessment.md` 的四等第做法给档次）：

| 维度 | 权重 | 优 | 良 | 合格 | 不合格 |
|---|---|---|---|---|---|
| 内容真实性 | 25% | 任务、数据、时间地点具体可核查 | 大体具体，个别表述笼统 | 有明显笼统段落，但无编造迹象 | 存在抄袭、编造或与考勤记录矛盾 |
| 专业深度 | 25% | 能解释岗位背后的专业原理，术语准确 | 原理基本讲清 | 停留在操作描述 | 只有流水账，无专业内容 |
| 问题分析 | 20% | 提出问题并给出可验证的改进建议 | 能提出问题，建议较笼统 | 只描述问题，无分析 | 无问题意识 |
| 规范性 | 15% | 结构完整、图表规范、引用可查 | 结构完整，格式小瑕疵 | 结构缺项 | 结构严重残缺 |
| 反思与改进 | 15% | 反思具体、与个人能力短板对应 | 反思较具体 | 反思空泛 | 无反思 |

> **及格线下判断与最终分数一律留人工确认位**：`【待教师确认：报告得分 ____】`。

3. **实习鉴定表的填写与盖章**（AI 只出填写说明与字段清单，**不代拟评语内容**）：

| 栏目 | 谁来填 | 注意 |
|---|---|---|
| 学生基本信息 | 学生本人 | 与学籍信息一致 |
| 实习单位、岗位、起止时间 | 学生填 + 校内导师核对 | 必须与安排表、协议一致 |
| 实习内容简述 | 学生本人 | 具体，不写「若干」 |
| 企业评语与成绩 | **企业导师/单位填写** | **不得由 AI 或教师代拟代签** |
| 单位盖章 | 实习单位 | 必须是单位公章或人事部门章，部门内部章按校规确认 |
| 校内导师评语 | 校内导师 | 依据指导记录与企业评价写，留 `【待教师确认：评语】` |
| 院系意见与盖章 | 院系 | 按本校流程 |
| 成绩等级 | 按本校规定折算 | 折算规则以本校文件为准 |

4. **成绩汇总**（走 `xlsx_kit.py build`）：一张表含「学号/姓名/单位/企业评价得分/报告得分/校内导师得分/加权总分/等级/异常标记」，
异常标记用来看「三项分差过大」「得分明显偏离考勤记录」这类需要复核的行。
若实习成绩本身由多道分项考核构成，可另用 `analyze` 做分项统计：

```bash
$PY vendor/office-layer/scripts/xlsx_kit.py analyze --in 分项评分表.xlsx \
    --out 实习分项分析.xlsx --first-q-col 3 --full-marks '[30,30,40]'
```

**输出**：`实习成绩汇总表.xlsx`、`实习报告评分表.xlsx`、`鉴定表填写说明.docx`、`鉴定表核对清单.xlsx`
**退出条件**：每名学生的三项分数都有原始依据；无「无依据的分数」；企业评语与盖章状态逐条核对完毕

### 阶段八 · 材料归档与总结报告

**输入**：阶段一至七的全部产出物
**动作**：

1. **归档清单**（按教学档案要求逐项核对，缺项标 `【缺失：…】`）：

2. **实习工作总结报告**（七节结构）：① 基本情况（专业、人数、单位数、时段）；

## 红线

1. **学生安全第一位**。安全相关事项（安全教育内容、承诺书条款、应急预案、高危岗位安排）
   **必须人工确认**，AI 只帮准备材料与检查清单，**不得输出「已确保安全」之类的结论**，
   也不得替院系判断某个单位「安全合格」。
2. **不虚构**。企业名称、协议条款、学生考勤、企业评价、实习成绩**一律依据真实材料**；
   无数据留 `【待补：…】`。**实习鉴定造假是学术不端**——AI 绝不代企业写评语、代签、代盖章。
3. **不代写学生实习报告**。本技能帮教师做**指导与评价**（出评分量规、出批注、出评分表），
   **不替学生完成作业**。学生报告只有学生本人能写。
4. **学生个人信息（身份证号、联系方式、家庭住址、健康信息）本地处理、不外传**，
   只在本机 office-layer 流程内流转；中间文件任务结束后提醒教师删除；
   群发版本必须用脱敏学生版。
5. **协议涉及法律责任，必须经学校法务 / 教务或主管部门审核**，
   **不得直接使用本技能生成的文本签署**。本技能只出要素核对表与缺口清单。
6. **评价与结论不给终稿**。成绩、等级、评语、是否通过、是否同意变更单位或岗位，
   一律留 `【待教师确认：…】`，由教师签字负责。
7. **各校实习管理规定不同，一律以本校文件为准**。AI 不引具体法规条款号，
   只写「按学校/学院相关规定」并提示教师核对。
8. **问题处置不得隐瞒**。学生擅自离岗、失联、事故苗头等，必须立即上报，
   不得替学生遮掩，不得事后补记考勤。
